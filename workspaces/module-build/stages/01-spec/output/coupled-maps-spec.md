# Spec: coupled-maps

Library layer: Systems. Milestone M5 (`_config/build-order.md`, row "M5 P3"). Status: approved at the stage 01 checkpoint, 2026-11-05 (D103), with open points P1 to P12 settled as proposed. No Julia type, function or file names appear outside the Compute and Oracle sections (Pattern 10). Every statement marked "derived" was derived while drafting; "drafting check" marks a throwaway numerical check run in the session scratchpad (not a source, not citable, to be reproduced at stage 02 and 04).

## Scope

- Catalog rows (`_config/catalogs/systems.md`, section A): Y3 (coupled standard maps, Froeschle 4D map, dimension 4) and Y4 (N coupled standard maps, chain, dimension 2N). Row L7c (`_config/catalogs/lyapunov.md`, banded QR) is a research line: this spec only records the bandwidth of the tangent map (Equations item 9) and designs nothing.
- Prerequisite: standard-map, verified (Y1, Y5; `standard-map-spec.md`). Layering: Systems imports nothing from Foundation (`_config/architecture.md`, "Layering"; decision D23).
- The module supplies, per system: one forward step, one analytic tangent step, one inverse step, one inverse tangent step, the invariant residuals of the Invariants section, the wrapped system with integer counts (same policy as standard-map Amendment D28), and the known answers of this spec. It does no health checking and no renormalization (tangent-core and Diagnostics own those).
- Dimension: Y3 is 4. Y4 is 2N with 2 <= N <= 100, so 4 to 200 (architecture, "Phase-space dimension: 2 to 200"; research line R3 names N = 2..100). N = 1 is Y1.
- Domain: any finite real state and parameters. Non-finite input gives non-finite output, not an error (as Y1).
- This module is the 4D (and 2N-dimensional) system that GALI_k with k > 2 needs (gali-spec, open point P8: "a k > 2 stream oracle needs a 4D map in Systems"). What it supplies for that purpose is listed in Equations item 10 and Oracle O8.
- Out of scope: indicators, estimators, the banded QR design (L7c), element-type policy (precision spec), the Henon map (Y2).

## Equations

Notation. eps_T as in standard-map (binary64 2^-52, double-double nominal 2^-104). Omega_2N = [[0, I], [-I, 0]] in the ordering (q_1..q_N, p_1..p_N), the block form of Skokos2010 J_2N p.7 and the condition M^T Omega M = Omega, Skokos2010 Eq. (5) p.8. Both systems use this ordering: the first N components are positions, the last N are momenta. Y1 is the case N = 1 of the ordering (state (x, p)).

**Item 1. Source form of Y3 (Froeschle variant).** Skokos2010 Eq. (16) p.9 (ordering x1, x2 = positions, x3, x4 = momenta), parameters nu, kappa, mu, all variables mod 2 pi:

- x1' = x1 + x3
- x2' = x2 + x4
- x3' = x3 - nu sin(x1') - mu [1 - cos(x1' + x2')]
- x4' = x4 - kappa sin(x2') - mu [1 - cos(x1' + x2')]

Here x1', x2' are the new positions (Skokos2010 writes them as x_{1,n+1}, x_{2,n+1}). The paper calls this "a variant of Froeschle's 4d symplectic map" and cites Froeschle1972 as the origin; Froeschle1972 itself was not read (bibliography: verified via secondary sources only) and no equation here is taken from it.

**Item 2. Same variant, other labelling.** Skokos2003a Eq. (9) p.3 (ordering x1, x2 = position and momentum of map 1, x3, x4 of map 2):

- x1 = x1 + x2, x2 = x2 - nu sin(x1 + x2) - mu [1 - cos(x1 + x2 + x3 + x4)]
- x3 = x3 + x4, x4 = x4 - kappa sin(x3 + x4) - mu [1 - cos(x1 + x2 + x3 + x4)]  (mod 2 pi)

The same form is printed in Maffione2011a Sect. 2 p.3 to 4 (called vFSM there) and in SandorMaffione2016 Eq. (3), with the same default parameters. Reading (derived): the right-hand sides use the values before the step, so x1 + x2 is the new position of map 1 and x1 + x2 + x3 + x4 is the sum of the two new positions. With the relabelling (x1, x2, x3, x4) of item 2 -> (x1, x3, x2, x4) of item 1 the two systems are identical. Skokos2003a Eq. (8) p.3 is the uncoupled 2D map x1' = x1 + x2, x2' = x2 - nu sin(x1 + x2) (same reading), which is the part of the 4D map with mu = 0.

**Item 3. Parameters and published orbits.** nu = 0.5, kappa = 0.1, mu = 10^-3 (Skokos2003a p.4 and Fig. 2 caption p.5; Maffione2011a Sect. 2 p.4). Orbits in the labelling of item 2, deviation vectors (1,1,1,1) and (1,0,0,0): ordered orbit C (x1, x2, x3, x4) = (0.5, 0, 0.5, 0); chaotic orbit D = (3, 0, 0.5, 0) (Skokos2003a p.4). In the labelling of item 1 these are C = (0.5, 0.5, 0, 0) and D = (3, 0.5, 0, 0) (positions first). Reported behaviour (Skokos2003a p.4 and Fig. 2 p.5): SALI of C fluctuates around 0.28; SALI of D reaches 10^-16 after about 4.7 x 10^3 iterations; the finite-time exponent L_N of C decays by a power law to 1.6 x 10^-6 at 10^7 iterations; L_N of D "seems to stabilize near" 5 x 10^-2 at 10^7 iterations (text; Fig. 2b shows about 10^-2, see Findings). Skokos2010 Fig. 7 p.37 (left panel, orbits of the map of item 1; parameters of the figure not printed there) reports regular orbits with X_1(t) ~ t^-1 and chaotic orbits with the maximal exponent about 8 x 10^-3.

**Item 4. Tangent map of Y3 (source).** Skokos2010 Eq. (21) p.11 in the ordering of item 1:
w1' = w1 + w3, w2' = w2 + w4, w3' = a w1 + b w2 + (1 + a) w3 + b w4, w4' = b w1 + c w2 + b w3 + (1 + c) w4, with a = -nu cos(x1') - mu sin(x1' + x2'), b = -mu sin(x1' + x2'), c = -kappa cos(x2') - mu sin(x1' + x2'), all evaluated at the new positions x1', x2' (derived check: these are the derivatives of the third and fourth lines of item 1 after substituting dx1' = dx1 + dx3, dx2' = dx2 + dx4). In block form, with A = [[a, b], [b, c]] (symmetric):

M = [[I, I], [A, I + A]] = [[I, 0], [A, I]] . [[I, I], [0, I]] (kick after drift).

Determinant (derived): both factors are block triangular with identity diagonal blocks, so det M = 1. Symplecticity (derived): the drift factor [[I, I], [0, I]] satisfies the condition for any I; the kick factor [[I, 0], [A, I]] satisfies it exactly when A = A^T, which holds because the off-diagonal entries of A are both b. This is also what makes item 1 symplectic: the force on x3 and x4 is the gradient of a function of (x1', x2') (derived: dF3/dx2' = dF4/dx1' = -mu sin(x1' + x2')). The torus: the force is 2 pi periodic in x1', x2' (periodic coefficients, no linear term), so the map commutes with the shifts (x_j -> x_j + 2 pi a_j) as in standard-map item 2 (derived), and a lifted orbit wrapped is the torus orbit. Wrapped and lifted tangents coincide (only sin and cos of positions enter).

**Item 5. Inverse of Y3 (derived).** From item 1, at the image point (x1', x2', x3', x4'): x3 = x3' + nu sin(x1') + mu [1 - cos(x1' + x2')], x4 = x4' + kappa sin(x2') + mu [1 - cos(x1' + x2')], x1 = x1' - x3, x2 = x2' - x4. Inverse tangent: M^-1 = [[I + A, -I], [-A, I]] with A built from the image positions (derived: inverse of the product in item 4 is [[I, -I], [0, I]] . [[I, 0], [-A, I]]).

**Item 6. Relation of Y3 with mu = 0 to Y1 (derived).** For mu = 0 the two pairs (x1, x3) and (x2, x4) are independent copies of x' = x + p, p' = p - nu sin(x'). Let C(x, p) = (x + p, p). Then C maps this pair map to the standard map of Y1 with K = -nu: with (X, P) = C(x1, x3), P' = P + K sin X = x3 - nu sin(x1') = x3' and X' = X + P' = x1' + x3' = the first component of C(x1', x3'). So Y3 at mu = 0 is Y1 with K = -nu (and K = -kappa for the second pair), conjugated by the exactly symplectic shear C. The sign of K is immaterial for the dynamics by standard-map item 5 (x -> x + pi). In floating point the check is exact (Oracle O1c): the operations of one Y3 pair step at mu = 0 and of one Y1 step on C(x1, x3) are the same additions and the same sine, negation being exact.

**Item 7. Fixed point of Y3 (derived).** The origin is a fixed point for all parameters (all forces vanish). There b = 0, a = -nu, c = -kappa, so M is two uncoupled Y1 blocks [[1, 1], [-nu, 1 - nu]] and [[1, 1], [-kappa, 1 - kappa]], trace 2 - nu and 2 - kappa, determinant 1. Elliptic for 0 < nu < 4 with rotation angle phi = arccos(1 - nu / 2) (nu = 0.5: 0.7227; kappa = 0.1: 0.3176, drafting check), hyperbolic for nu < 0 or nu > 4, exponent ln |lambda_+| with lambda_+ = (|tr| + sqrt(tr^2 - 4)) / 2. This is why orbit C (near the origin, small amplitude) is ordered.

**Item 8. Y4: chain of N coupled standard maps.** Source (the only printed instance is N = 2): Maffione2011a Sect. 6 p.19 to 20, "two coupled standard mappings" in unit-torus coordinates:
x1' = x1 + x2, x2' = x2 + (K / 2 pi) sin(2 pi x1) - (beta / pi) sin[2 pi (x3 - x1)], x3' = x3 + x4, x4' = x4 + (K / 2 pi) sin(2 pi x3) - (beta / pi) sin[2 pi (x1 - x3)], with K = 3 and beta = 0.1 or 0.3051 (orbits A2 regular and A3 weakly chaotic of Voglis et al. 1999 and Skokos2001, both not read; their initial conditions are not printed in Maffione2011a). No equation number is printed in Maffione2011a for this map. Skokos2010 Fig. 7 p.37 (right panel) shows "a 4d map composed of two coupled 2d standard maps" with maximal exponent about 1.6 x 10^-7 for chaotic orbits (parameters not printed there, "see [122]" = Skokos2001, not read).

Neither Skokos2004 nor Skokos2007 prints a 4D map or a chain (Findings (a)). No source read prints a chain with N > 2, a boundary condition, or Y4 spectra. The general-N chain below is therefore a derived generalization of the N = 2 map, and the owner decides it (P4, P5).

Canonical form in the library coordinates (radians, positions q_j, momenta p_j, j = 1..N; this is the Y1 form, kick then drift):

- p_j' = p_j + F_j(q),  q_j' = q_j + p_j'
- F_j(q) = K sin q_j + eps sum over neighbours k of j of sin(q_j - q_k)

with nearest-neighbour bonds. Conversion of the printed form (derived): q = 2 pi x_u, p = 2 pi y_u multiplies both printed equations by 2 pi, giving K sin q and 2 beta sin; so eps = 2 beta, K unchanged. For N = 2: F_1 = K sin q_1 + eps sin(q_1 - q_2), F_2 = K sin q_2 + eps sin(q_2 - q_1), equal to the printed map when the force is taken at the pre-step positions and the position update uses the new momentum. Reading note (derived, Findings (c)): taken literally, the printed lines use the old momentum in the position update and the old positions in the force, which has determinant 1 - dF/dq, not 1; the canonical form above is the symplectic reading and the only one that keeps Y1 as its decoupled limit.

Boundaries (open point P4): open chain (free ends, bonds (j, j+1) for j = 1..N-1) is the proposed default, because N = 2 in the source is one bond. The ring (bond (N, 1) added) is defined for N >= 3 only; for N = 2 a ring would double the bond.

**Item 9. Y4 tangent, inverse, invariants (derived).** G(q) = dF/dq is symmetric: G_jj = K cos q_j + eps sum over neighbours k of cos(q_j - q_k); G_jk = -eps cos(q_j - q_k) for a bond (j, k), else 0. Tridiagonal for the open chain; tridiagonal plus the two corner entries (1, N), (N, 1) for the ring. The drafting check confirms G is the derivative of F by central differences (max error 3 x 10^-10 at step 10^-6, N = 5).

M = [[I + G, I], [G, I]] = [[I, I], [0, I]] . [[I, 0], [G, I]] (drift after kick), with G at the pre-step positions. det M = 1 and M^T Omega M = Omega because G = G^T (same argument as item 4). For N = 1, M = [[1 + c, 1], [c, 1]] with c = K cos q, which is Y1 (standard-map item 3). Inverse: q_j = q_j' - p_j', p_j = p_j' - F_j(q) with q the preimage; inverse tangent M^-1 = [[I, -I], [-G, I + G]] with G at the preimage positions (derived; N = 1 gives standard-map item 4).

Bandwidth (note for L7c, not a design): in the ordering (q, p), M consists of four N x N blocks, each at most tridiagonal (ring: cyclic tridiagonal). In the interleaved ordering (q_1, p_1, q_2, p_2, ...) the nonzero entries lie within distance 3 of the diagonal (ring: cyclic). So the action of M on k vectors needs a number of operations linear in N, not quadratic. Y3 has dimension 4 and no banded structure to use.

Torus (derived): F_j is 2 pi periodic in every q_k and depends on the q's through sines of them and of differences, so the map commutes with the shifts q_j -> q_j + 2 pi a_j, p_j -> p_j + 2 pi b_j (a_j, b_j integers) exactly as standard-map item 2, and the lifted tangent equals the wrapped one.

Symmetries (derived): (i) K -> -K with every q_j -> q_j + pi and eps unchanged (differences are unchanged; the on-site sines flip). (ii) For Y3: (nu, kappa) -> (-nu, -kappa) with x1, x2 -> x1 + pi, x2 + pi and mu unchanged (the shift of the sum x1' + x2' is 2 pi). (iii) Translation: for K = 0 the force sums to zero, so the total momentum sum_j p_j is conserved in exact arithmetic (open chain and ring).

Fixed point of Y4 (derived): q = 0, p = 0 for any K, eps. G(0) = K I + eps L, with L the graph Laplacian of the chain (L_jj = number of neighbours, L_jk = -1 for a bond). Eigenvalues of L: 2 - 2 cos(k pi / N), k = 0..N-1 (open chain); 2 - 2 cos(2 pi k / N), k = 0..N-1 (ring). So G(0) has the eigenvalues g_k = K + eps l_k with l_k from L. Orthogonal U with U^T L U diagonal turns M(0) into N decoupled 2 x 2 blocks [[1 + g_k, 1], [g_k, 1]], trace 2 + g_k, determinant 1. Mode k is elliptic for -4 < g_k < 0 (rotation angle arccos(1 + g_k / 2)), hyperbolic for g_k > 0 or g_k < -4 (exponent ln |lambda_+|, lambda_+ + 1 / lambda_+ = |2 + g_k|, |lambda_+| > 1). Exact spectrum of the origin (largest to smallest): +ln |lambda_+(g_k)| and -ln |lambda_+(g_k)| for hyperbolic modes, zero twice for elliptic modes. This is the exact answer available at any N up to 100.

**Item 10. What gali with k > 2 needs from this module (derived from Skokos2007).** Skokos2007 Sec. 6 p.37 states that Eqs. (43) and (80) hold for 2N-dimensional symplectic maps. For Y3 (N = 2) with the pairing lambda_3 = -lambda_2, lambda_4 = -lambda_1 the chaotic law Eq. (43) becomes: GALI_2 ~ exp(-(lambda_1 - lambda_2) n), GALI_3 ~ exp(-2 lambda_1 n), GALI_4 ~ exp(-4 lambda_1 n) (derived: (k-1) lambda_1 minus the sum of lambda_2..lambda_k, with the pairs cancelling). For regular orbits on a 2-torus, GALI_2 is constant and GALI_3, GALI_4 decay by power laws given by Eq. (80) (benchmarks row "GALI_k, regular orbit on N-dim torus"; the exponents are not restated here). The module therefore supplies: a 4D system with an analytic tangent, a fixed ordered orbit (C), a fixed chaotic orbit (D), the exact tangent products for k = d = 4, and for a frame of k = 4 vectors the identity that the volume equals the absolute determinant of the unit frame (gali-spec B5).

## Algorithm

1. Y3 forward step: item 1, in lifted variables. Compute x1' = x1 + x3 and x2' = x2 + x4 first, then s = x1' + x2' and the two forces, then x3', x4'. Tangent step: item 4 at x1', x2', which are formed from the pre-step state (the tangent of the step at z uses the intermediate positions x1 + x3, x2 + x4). Inverse and inverse tangent: item 5.
2. Y4 forward step: item 8 in lifted variables: all p_j' from the pre-step positions, then all q_j' from the new momenta. Tangent: item 9 at the pre-step positions. Inverse and inverse tangent: item 9.
3. Wrapped system with counts: the state is each coordinate reduced to [0, 2 pi) plus one integer count per coordinate (policy D28, `_config/numerics-policy.md`). Each substep of the lifted step is followed by the exact reduction of standard-map item W-E1 (two guards, counts updated by the floor), applied per component: for Y4 the momentum reductions come before the position updates, as W-E2; for Y3 the new positions are reduced, then the new momenta. The forces see the reduced positions (periodic, so the same value up to one rounding). Counts propagate: q count m_j' = m_j + n_j' + b_j, p count n_j' = n_j + a_j (Y4, as W-E2); for Y3, with the momentum updated after the position, m_j' = m_j + n_j + b_j and n_j' = n_j + a_j (derived by the check of W-E2: X' = X + P, P' = P - f(X'), written with counts). Wrapped tangent equals the lifted one. Inverse: the mirror of the above (derived, W-E4). Overflow of a count gives NaN in all components (W-I5 of standard-map).
4. Parameters (nu, kappa, mu; K, eps; N and the boundary) are inputs stored in the element type of the state; constants not exactly representable are built in that type (precision spec, Algorithm item 2).
5. No coefficient tables. No numerics-defaults key is needed; no value is proposed here.

## Invariants

Residuals exposed for any state (floating-point values in the element type T). d = 2N is the dimension, a_max the bound below.
- I1: det residual |det M - 1|, evaluated in 256-bit arithmetic from the rounded matrix.
- I2: symplectic residual, max entry of |M^T Omega M - Omega|.
- I3: lifted vs wrapped orbits agree on the torus.
- I4: round trip, inverse(forward(z)) = z and forward(inverse(z)) = z; for the wrapped system the counts too.
- I5: the symmetries of items 6 and 9 (K -> -K with a shift by pi, and the Y3 version).
- I6: decoupled limit: Y3 with mu = 0 is Y1 conjugated by C (item 6), bitwise; Y4 with eps = 0 is N independent copies of Y1, bitwise; and in the decoupled limit the orbit of one pair or site does not depend on the other states (bitwise).
- I7: exact spectra: K = 0 shear (criteria 7 and 8), the origin spectra of items 7 and 9, and the finite-time pairing: a product Y_n of symplectic matrices is symplectic, so its singular values come in pairs sigma_i sigma_{2N+1-i} = 1 exactly (derived from Skokos2010 Eq. (5)); the log-singular-value exponents pair as lambda_i(n) = -lambda_{2N+1-i}(n), and sum_i lambda_i(n) = 0, at every finite n.
- I8: total momentum for K = 0 (item 9 (iii)).

Error budget used by every orbit comparison (derived, first order, the standard-map budget extended). Let a_max = max(|nu|, |kappa|) + 2 |mu| for Y3 (Gershgorin on A: |a| <= |nu| + |mu|, |b| <= |mu|, |c| <= |kappa| + |mu|) and a_max = |K| + 4 |eps| for Y4 (Gershgorin on G: diagonal at most |K| + 2 |eps|, off-diagonals at most |eps| twice per row). Then ||A||_2 <= a_max, ||G||_2 <= a_max. The kick factor has largest singular value s(a) = (a + sqrt(a^2 + 4)) / 2 (each eigen-direction of the symmetric block gives a 2 x 2 shear [[1, 0], [alpha, 1]]), the drift factor has the golden ratio phi = (1 + sqrt 5) / 2, so ||M||_2 <= phi s(a_max) =: sigma. The bound does not depend on N. Gamma_n = sigma^n bounds the growth of any perturbation over n steps (the inverse has the same bound). tau(n) = 32 eps_T M_n n Gamma_n, M_n = max(1, parameter scale, max over the orbit and all components of |x_j|, |p_j|) on the lifted orbit; the constant 32 is 16 of standard-map doubled for the larger number of operations per component (open point P9). n_H is the largest n <= 20 with Gamma_n <= 10^6. For the published Y3 parameters sigma = 2.07 and n_H = 19 (drafting check). The torus distance d is the maximum over components of the absolute difference reduced to (-pi, pi]. A bound on one-step tangent entries: |entries| <= 1 + a_max.

## Compute

Policy: `_config/architecture.md`, "Compute" (decision D17). Machine: GTX 1050 3 GB, compute capability 6.1, weak binary64 throughput (risk K15); CI has no GPU.
- Data parallel, GPU candidates: ensembles of independent orbits (grids of initial conditions, parameter sweeps, indicator maps) of Y3 and of Y4 at small N. Orbits share no data; steps within an orbit are sequential. One kernel serves CPU and GPU. A Y3 step is light (3 sines and 2 cosines, about 20 additions and multiplications); no GPU speedup is assumed. The 04-verify report measures binary64 CPU threads vs GPU and the module ships GPU as default only if the cross-backend test passes (D25).
- Y4 at large N: within one orbit, the force and the update are data parallel over sites, but one orbit of dimension up to 200 is a small amount of work per step and the step chain stays sequential, so one orbit is a CPU-thread case; ensembles of orbits stay the GPU candidate. Full Lyapunov spectra (k = 2N frames) need a QR per step (LAPACK-heavy, a CPU case by policy); the module only has to supply the tangent action on a frame in a number of operations linear in N (criterion 17).
- CPU only: BigFloat (not isbits; GPU request falls back with the recorded reason "kernel does not compile for the element type"), single long orbits. Double64 is attempted on the GPU and falls back with the same reason.
- Memory per orbit (structure-of-arrays), numbers per orbit: state 2N; plus the tangent: 4 N^2 for a full matrix, or 2N k for a frame of k deviation vectors. Y3: 4 + 16 = 20 numbers (160 bytes binary64, 320 bytes double-double) with a full matrix; 4 + 4k with k vectors. Y4 at N = 100 (d = 200): full matrix 40 200 numbers = 322 KB binary64, k = 10 vectors 2200 numbers = 17.6 KB. The wrapped system adds 2N integer counts. For orientation only; chunk sizes derive from free memory at run time (policy).
- Reproducibility: initial conditions of orbit j come from a random stream keyed by j, never by thread or device; the CPU result for orbit j is bitwise identical with 1 and with N threads.
- CPU-vs-GPU agreement: not bitwise; the bound is tau(n) for n <= n_H, max over the ensemble. Longer runs are compared at the estimator tolerances owned by the Lyapunov and Indicators specs.

## Acceptance criteria

Seeded data: x_j, p_j uniform in [-4 pi, 4 pi]; 1000 points per check unless stated. Y3 parameter sets (nu, kappa, mu): (0.5, 0.1, 10^-3) published; (0, 0, 0); (1, 1, 0); (2, 0.5, 0.1); (-1.5, 3, 0.5); and uniform draws in [-5, 5]^3. ## Findings for the owner

(a) Source gap. Skokos2004 and Skokos2007, the keys the catalog gives for Y3 and Y4, do not contain a 4D map or a chain. The Y3 equations are in Skokos2010 Eq. (16) and Skokos2003a Eq. (9) (also Maffione2011a, SandorMaffione2016). The only printed chain is N = 2 (Maffione2011a Sect. 6, no equation number). The catalog sources column needs correction at stage 05.
(b) Two labellings of the same Y3 map: Skokos2010 Eq. (16) lists positions first, Skokos2003a Eq. (9) lists (position, momentum) pairs. Equivalent under the relabelling of item 2.
(c) The printed coupled-standard-map lines of Maffione2011a, read literally with pre-step values, give determinant 1 - dF/dq, not 1 (not area preserving). The authors surely meant the symplectic form; the spec adopts it (item 8).
(d) Orbit D: Skokos2003a text prints L_N of D near 5 x 10^-2 at 10^7 iterations, Fig. 2b on p.5 shows about 10^-2, Skokos2010 Fig. 7 p.37 gives about 8 x 10^-3. A drafting check in the session scratchpad (Python, QR spectrum, binary64, item 1 form, orbit D) gave lambda_1 = 0.0150 at n = 10^3, 0.0090 at 5 x 10^3, 0.0085 at 10^4, 0.0083 at 2 x 10^4 and 0.0093 at 10^5; so the 8 x 10^-3 value is consistent and the 5 x 10^-2 in the text looks like a misprint. The same check gave SALI of C in 0.14 to 0.39 (reported 0.28) and lambda_{1..4} of D at 10^5 equal to (0.0093, 0.0002, -0.0003, -0.0093), pairing to 3 x 10^-5. A chain check (N = 2, K = 3, eps = 0.2, one random orbit, 2 x 10^5 steps) gave lambda = (0.749, 0.461, -0.461, -0.749), sum 1 x 10^-16, pairing to 1.3 x 10^-5; and central differences of the N = 5 chain confirmed the tangent of item 9 (3 x 10^-10) and symplecticity to 1 x 10^-16 (drafting checks, not sources).
(e) Sign and ordering of Y3 against Y1: Y3 applies the force at the new position and with a negative sign, Y1 at the old position with a positive sign. They are conjugate by the shear C and K -> -nu (item 6), not equal; the decoupled-limit test therefore goes through C and is still bitwise.
(f) Coordinate convention: the papers take all variables mod 2 pi in [-pi, pi); the library works in lifted coordinates and wraps to [0, 2 pi) for output (standard-map item 2, D28). Torus comparisons reduce to (-pi, pi]. No numerical change.
(g) Docs against code: `_config/architecture.md` "Module map" says Systems uses StaticArrays for dimension <= 8 and names the operations `step`, `tangent`, `invariants`; the existing Systems code (`src/Systems/`) uses forward, inverse, tangent, inverse_tangent, dimension and residual functions, and its state is a small fixed-size vector, which does not fit Y4 with N > 4. Following the code, the spec names the operations by what they do; the large-state representation is a stage 03 question (P8). The architecture's N bound (dimension 200) and research line R3 (N = 2..100) agree once dimension = 2N is read.
