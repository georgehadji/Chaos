# Spec: experiments

Library layer: Experiments (`_config/architecture.md`, "Module map" row Experiments and "Layering": above Tangent, Lyapunov and Diagnostics, which it may import; nothing below it may import it). Created by decision D49 (`_config/decision-log.md`). Draft for the 01-spec checkpoint, branch module/experiments. No Julia type, function or file names appear outside the Compute and Oracle sections (Pattern 10). Choices made here, not given by a source, are marked "(proposed)" with a one-line rationale; open points for the owner are listed in Scope.

Notation. T is the lifted standard map and DT its analytic tangent (`standard-map-spec.md`, Equations items 1 to 3). eps_BF is the spacing at 1 of the extended type at `bigfloat_bits` (`_config/numerics-defaults.toml`). A "panel cell" is a pair (K, design class); a "grid cell" is one cell of the screening grid. Design classes: T (KAM torus), R (resonant), C (chaotic sea), S (sticky), X (near separatrix or hyperbolic fixed point), as in the preregistration, section "Panel". "The preregistration" is the frozen study file `workspaces/study/stages/01-design/output/p1-le-benchmark-preregistration.md` for the first study; the module takes the path of any study's preregistration as input. Exponents are per map step, natural log (`lyap-benettin-spec.md`, S1).

## Scope

- Catalog rows: none (the module is not a catalog method or system). Its scope is fixed by decision D49 and by the preregistration, section "Panel" ("Selection rule", "Subsets", "Eligible sets"). Prerequisites, all `verified`: Y1 standard map lifted and wrapped (`standard-map-spec.md`), Y5 linear symplectic maps (same spec, Equations item 10), tangent-core (stream, seeded per-orbit rule), precision (Float64 and BigFloat element types), L5 Householder (`lyap-householder-qr-spec.md`, used for screening), L1 Benettin (`lyap-benettin-spec.md`, used for a cross-check), diagnostics.
- First scope (this spec): the study panel builder used by study stage 02. From the preregistration it produces (a) the screening of a uniform grid per K, (b) the set of periodic orbits of period up to the preregistered bound with their stability, (c) the panel: initial conditions per panel cell drawn by the preregistered rule, the controls, the nested subsets S_D and S_L, (d) the panel file with its manifest, (e) the content of the phase portraits.
- Out of scope, stated so that nothing is built early: the runner (chunked, resumable sweeps over the panel), the run store (HDF5 layout of `schema/run-store.md`), caching by content hash, analysis, the measured labels of D36 and D37, and the command-line entry point (D16, D49). They follow in a later amendment of this slug, before study/03 (D49). Rendering of portraits belongs to the Figures layer; this spec only fixes what is drawn (Algorithm item 12).
- Generic by construction: K values, grid size, N_scr, every predicate threshold, window length, stuck length, n_c, subset sizes and caps, period bound, displacement, residual tolerance, the log10 r range, the control cap and the Y5 eigenvalue are inputs. The module holds no study value. The preregistration is the single home of every threshold, value and count; this spec refers to them as "the preregistration's value" and lists in Equations E0 where each input lives, without copying a number.
- numerics-defaults.toml: this spec first needs no new key. It reads `seed`, `bigfloat_bits`, `renorm_interval_tau` and `precision` as the preregistration's Methods do ("used unchanged"). Proposed values: none.

### Owner decisions at the checkpoint (2026-10-17)

- P2 Values not stated at freeze are now in the block: Newton cap, delta_dup, screening direction alpha, window w and the stuck-stretch definition (Amendment A1, items 3 to 5). Parabolic tolerance equals rho (E4). Plotted iterates per orbit: 2000, presentation only, held by the portrait script.

- P4 and P5 Caps: raised so that full population is not cut (Amendment A1, item 6). The cap rule of E17 stays as the deterministic fallback; the control order of E19 fills the two remaining control slots.
- P6 Class assignment stays on the CPU (Compute).
- P7 Plotting: a script in `verify/` (its own environment with CairoMakie, D27) reads the portrait content the module returns (Algorithm item 12) and writes the portraits file.
- P8 Prescribed screening direction: stage 02 checks that tangent-core accepts a prescribed initial direction; if not, adding it is part of this build, not the seeded fallback, because the direction changes which grid cells qualify.

E1 Map and tangent. p' = p + K sin x, x' = x + p'; DT = [[1 + K cos x, 1], [K cos x, 1]], det DT = 1. Source: `_config/research-question.md`, "Ground truth for variational methods"; `standard-map-spec.md` Equations items 1 and 3. Wrapped coordinates: item 2 of the same spec and Amendment D28.

E2 Shift rule (derived from `standard-map-spec.md` item 2): T maps (x + 2 pi a, p + 2 pi b) to (x' + 2 pi (a + b), p' + 2 pi b). After q steps the lifted displacement of the start changes by 2 pi (a + q b) in x and 2 pi b in p. Consequence: the winding pair (m, j) of a periodic point depends on the lifted representative (m changes by q b under a shift of p by 2 pi b; j does not), so windings are always those of the stored representative (E3).

E3 Periodic point with winding (derived from the map definition; analytic). A point z = (x, p) of primitive period q on the torus satisfies, for integers m, j,

    F(z) = T^q(z) - (x + 2 pi m, p + 2 pi j) = 0.

Residual of z: ||F(z)||_inf. With J_q = DT(z_{q-1}) ... DT(z_0), z_t = T^t(z), the Newton step is Delta = -(J_q - I)^{-1} F, and since det J_q = 1 (E1, product of determinant-one matrices),

    det(J_q - I) = 2 - tr J_q,   (J_q - I)^{-1} = (1 / (2 - tr J_q)) [[d - 1, -b], [-c, a - 1]],  J_q = [[a, b], [c, d]].

The step exists iff tr J_q != 2. For the stored (wrapped) representative the winding is (m, j) = (round((x_q - x) / 2 pi), round((p_q - p) / 2 pi)) of the lifted iterate.

E4 Stability from the trace (analytic, from det = 1). Let t = tr J_q. The eigenvalues of J_q are mu_pm = (t +- sqrt(t^2 - 4)) / 2 with mu_+ mu_- = 1 (det = 1). The trace is the same at every point of the orbit (tr(AB) = tr(BA), cyclic). Class: elliptic if |t| < 2 (mu on the unit circle), hyperbolic if |t| > 2 (real mu, |mu_+| > 1), parabolic if ||t| - 2| <= rho (proposed: a point accepted at residual rho cannot resolve the trace more finely than rho, so the same input is the parabolic band). Exponent per map step of a generic tangent vector along the orbit: hyperbolic, ln |mu_+| / q with |mu_+| = (|t| + sqrt(t^2 - 4)) / 2; elliptic and parabolic, 0 (the finite-time value decays like ln n / n or is exactly 0: `standard-map-spec.md` item 9).

E5 Fixed points (`standard-map-spec.md` Equations item 7, derived there; traces checked against daSilvaMancheinBeims2018 p.2 and ContopoulosHarsoula2008 p.3). (0, 0) and (pi, 0) for every K, traces 2 + K and 2 - K. For K > 0: (0, 0) hyperbolic; (pi, 0) elliptic for 0 < K < 4, parabolic at K = 4, hyperbolic for K > 4. Accelerator-mode fixed points (m != 0, needs K > 2 pi |m|) are found by the period-1 Newton search.

E6 Period-2 orbits in closed form (derived; analytic; used as oracle). Put z_0 = (x_0, p_0), z_1 = T z_0, windings (m, j). From E3 with q = 2: x_2 - x_0 = p_1 + p_2 = 2 p_0 + K sin x_0 + 2 pi j = 2 pi m and p_2 - p_0 = K (sin x_0 + sin x_1) = 2 pi j, so with c = m - j:

    p_0 = pi c - (K / 2) sin x_0,   x_1 = x_0 + pi c + (K / 2) sin x_0,   K (sin x_0 + sin x_1) = 2 pi j.

For j = 0 the last condition is sin x_1 = -sin x_0, i.e. x_1 = -x_0 or x_1 = x_0 + pi (mod 2 pi). Three families:
- (A) c odd, x_1 = x_0 + pi, sin x_0 = 0: the orbit {(0, pi), (pi, pi)} for every K > 0 (check: (0, pi) -> p' = pi, x' = pi; (pi, pi) -> p' = pi, x' = 2 pi = 0). Trace of J_2: with c_1 = K cos 0 = K and c_2 = K cos pi = -K, the product [[1 - c, 1], [-c, 1]] [[1 + c, 1], [c, 1]] = [[1 - c^2 + c, 2 - c], [-c^2, 1 - c]] has trace 2 - c^2, so tr = 2 - K^2: elliptic for 0 < K < 2, parabolic at K = 2, hyperbolic for K > 2.
- (B) c even (c = 0 for the representative p_0 = pi mod 2 pi), x_1 = x_0 + pi, K > 2 pi: sin x_0 = 2 pi / K gives the two orbits {(x_a, pi), (x_a + pi, pi)} and {(pi - x_a, pi), (2 pi - x_a, pi)}, x_a = arcsin(2 pi / K). The same product with c = K cos x_a gives tr = 2 - c^2 = 2 + 4 pi^2 - K^2 (since K^2 cos^2 x_a = K^2 - 4 pi^2): elliptic for 2 pi < K < sqrt(4 pi^2 + 4), parabolic at both ends, hyperbolic above. At K = 10 tr = 2 + 4 pi^2 - 100 = -58.52 (rounded), |mu_+| = 58.50, exponent ln|mu_+| / 2 = 2.03 (rounded).
- (C) x_1 = -x_0 (mod 2 pi): x_0 is a root of g(x) = 2 x + pi c + (K / 2) sin x - 2 pi k, k integer, c in {0, 1}; the points are (x_0, p_0) and (-x_0, -p_0) (mod 2 pi). With cos x_1 = cos x_0 the product J(c_0)^2, c_0 = K cos x_0, has tr = c_0^2 + 4 c_0 + 2. The scalar equation is solved by bracketing, independent of the two-dimensional search. For c = 0 the roots other than x_0 = 0, pi appear at K = 4 (g'(pi) = 2 - K / 2): the period-2 family bifurcating from (pi, 0) that ContopoulosHarsoula2008 Sec. 2 p.4 and `standard-map-spec.md` AC13 call O1 and O1'. For c = 1 roots exist for every K > 0 (g(0) < 0 < g(pi / 2) at small K: the Poincare-Birkhoff partner of family A).

E7 K = 0 (derived; `standard-map-spec.md` item 9): T(x, p) = (x + p, p). Every point with p = 2 pi a / b, gcd(a, b) = 1, has primitive period b (x_n = x_0 + n p, which is congruent to x_0 mod 2 pi iff b divides n). All such points are parabolic (DT = [[1, 1], [0, 1]], tr = 2) with exponent 0. The periodic set at K = 0 is the union of the lines p = 2 pi a / b, 1 <= b <= q_max, 0 <= a < b.

E8 Torus distance (definition). delta(s) = |s - 2 pi round(s / 2 pi)| in [0, pi]; d(u, v) = sqrt(delta(u_x - v_x)^2 + delta(u_p - v_p)^2) (Euclidean in the minimum image; proposed: rotation-symmetric, so "at least 0.3 from" is a disc). Distance to a line p = c0 (K = 0) is delta(p - c0). Distance to a set is the minimum over its members. For a periodic orbit "its points" means all q points.

E9 Duplicate rule (proposed, derived structure). Two accepted solutions are the same orbit iff they have the same primitive period q' and some iterate T^t(z'), 0 <= t < q', of one lies within torus distance delta_dup of the other. The solution is first reduced to its primitive period: the smallest divisor q' of the searched period q whose residual F with its own windings is <= rho (a periodic point of primitive period q' passes the test for q = q' k). Among duplicates the one from the smallest grid cell id wins (E10), and exact fixed points win over any Newton solution. The input delta_dup must lie below the smallest separation between distinct accepted orbit points; the manifest records that separation and the build refuses when it is below 10 delta_dup (proposed: ambiguous identity otherwise).

E10 Screening grid (definition). Grid cell (i, j), i, j in {0, ..., N_g - 1}, has id g = j N_g + i and centre z_g = (2 pi (2 i + 1) / (2 N_g), 2 pi (2 j + 1) / (2 N_g)), each coordinate the binary64 nearest to the real number (a single correct rounding from an evaluation at 256 bits or more). The screening point of a grid cell is its centre.

E11 Screening quantities and predicates. Each centre is run for N_scr steps with L5 at Float64, k = 1, first deviation vector (cos alpha, sin alpha), handoff interval tau, lifted coordinates. S(n) is the compensated cumulative sum of ln R_11 (`lyap-householder-qr-spec.md` E2; Skokos2010 Eq. (82), p.47). Then lambda_scr = S(N_scr) / N_scr, and the block exponents e_i = (S((i + 1) w) - S(i w)) / w, i = 0, ..., N_scr / w - 1 (proposed definition of the preregistration's "windowed estimate": exponent of a disjoint block; it needs w a multiple of tau and N_scr a multiple of w). Let e_med be the median of the e_i (mean of the two middle values when their count is even; proposed). A stuck stretch is a maximal run of consecutive blocks with e_i < f_S e_med; its length is the number of blocks times w. Predicates for a grid cell with periodic set P_K (E3 and E7) and elliptic subset P_K^ell (parabolic points count as elliptic here, proposed: a parabolic point is an island boundary, so the larger exclusion is the safe one):
- T: lambda_scr <= theta_T, S(N_scr / 10) > 0, g = S(N_scr) / S(N_scr / 10) < g_T, and d(z_g, P_K) >= r_T (preregistration Amendment A1, item 2).
- C: lambda_scr >= theta_C and d(z_g, P_K^ell) >= r_C.
- S: lambda_scr >= theta_S and e_med > 0 and some stuck stretch has length >= L_S. (The guard e_med > 0 is proposed: for e_med <= 0 the comparison with a fraction of e_med is meaningless.)
- X: not from screening (E12).
Preregistration order of comparisons: "<=" for T, ">=" for C and S and the distances, strict "<" for the block test. Inputs must satisfy theta_T < theta_S and theta_T < theta_C, so T is disjoint from S and C. S and C can overlap; a grid cell drawn for S is removed from the candidate list of C (E14).

E12 X placement (preregistration, item 2). z = (r cos phi, r sin phi) added to the hyperbolic fixed point (0, 0), r = 10^l, l = l_lo + (l_hi - l_lo) u_1, phi = 2 pi u_2, u_1, u_2 uniform on [0, 1) from the cell stream (E15). Defined for K > 0. For r below pi the torus distance from (0, 0) equals r.

E13 R placement. K > 0: choose a point uniformly among the points of all elliptic orbits of period <= q_max (index 1 + floor(u_1 L), L their count), add delta_R (cos phi, sin phi), phi = 2 pi u_2 (the preregistration: "displaced by [delta_R] uniform in angle"). The sum is formed in 256-bit arithmetic and rounded once to binary64 (proposed, avoids double rounding). K = 0: choose a reduced fraction a/b among those with 1 <= b <= q_max uniformly (index 1 + floor(u_1 F), F their count), p_0 = 2 pi a / b (nearest binary64 to the real number), x_0 = 2 pi u_2. No displacement at K = 0 (the preregistration: "exact rational").

E14 Draw (preregistration item 4, executed as a partial Fisher-Yates). For T, S, C the candidate list is the qualifying grid cell ids in ascending order, c_1..c_M (for C without the ids drawn for S). With u_t uniform on [0, 1) from the cell stream, for t = 1, ..., min(n_c, M): j = t + floor(u_t (M - t + 1)); swap c_t and c_j; the t-th draw is c_t. Draws are without replacement (proposed: a grid cell is one start, so repeats would duplicate an orbit). The start is the screening point itself (the preregistration does not specify a within-cell jitter, so none is applied). If M < n_c the cell is short: M orbits, the shortfall recorded. If M = 0 the cell is empty and recorded as empty with its reason; it is never filled from another class. Draw order of classes: S before C (E11), then T, R, X; the stream of each panel cell is independent of the others, so this order matters only for the S-to-C exclusion.

E15 Streams. The stream of panel cell (K index i, class k) has the 64-bit seed formed by the first 8 bytes, big-endian, of SHA-256 over the UTF-8 text "chaoslab-panel-1|<seed>|<i>|<k>" (proposed: platform independent, exactly specifiable, injective on the pairs in use, no dependence on thread or device). K index i counts from 1 in the input order. Uniform numbers are the project's stable seeded generator's uniform binary64 on [0, 1), consumed in the order stated in E12 to E14. The rule is recorded in the manifest. Screening and Newton use no random numbers.

E16 Per-orbit seed. For panel orbit id j and run seed s, the orbit's seed is tangent-core's rule (`tangent-core-spec.md`, "Initial deviation vectors": the rule mapping (s, j) to the per-orbit seed), with the panel orbit id as j (proposed: a study run that uses the panel id reproduces the same deviation vectors).

E17 Subsets (preregistration, "Subsets (nested)"). Order the orbits of each populated panel cell by draw index (rank 1, 2, ...). S_D contains the rank 1..s_D members of every populated cell plus all controls. S_L contains the rank 1..s_L members of every populated cell (all from S_D; no controls). Cap (proposed, deterministic): while the subset exceeds its cap, remove the member with the largest rank, ties broken by the last panel cell in canonical order (E20); controls are never removed. S_L is formed from S_D after its cap. Consequence: nesting S_L within S_D within P holds by construction, ranks 1 .. s_L are never removed by the S_D cap, and the removed ids are listed in the manifest.

E18 Preregistration hash. H(f) = SHA-256 of the bytes of f after replacing CRLF by LF (proposed: git on Windows may convert line endings) and after replacing the text of the value cell of the header row "SHA-256 of this file at freeze" (everything between that cell's delimiters, trimmed: the 64-digit value and its parenthetical) by the four letters SELF. The module compares H with the 64 hexadecimal digits at the start of that cell and refuses on mismatch. Checked while drafting against the committed frozen file: this reading gives the header value; replacing only the 64 digits does not.

E19 Controls. (a) Exact periodic points: the fixed points (0, 0) and (pi, 0) for each K > 0 (E5), then the Newton orbits, one point per orbit (its canonical representative, E20). Ordering: fixed points by K index then (0, 0) before (pi, 0); then Newton orbits by (period, K index, representative); the first n_ctrl_max are controls (proposed ordering, P5). Each carries its analytic exponent from E4 evaluated in 256-bit arithmetic: 0 for elliptic and parabolic, ln |mu_+| / q for hyperbolic. (b) One Y5 hyperbolic linear map of dimension 2 with eigenvalues mu and 1/mu: the block H(ln mu) of `standard-map-spec.md` Equations item 10 (cosh, sinh form, eigenvalues e^(+-ln mu)), exponent ln mu, start at the fixed point (0, 0) (proposed: a generic start overflows binary64 after about 710 / ln mu steps, as `lyap-householder-qr-spec.md` AC5 notes; the tangent map is the constant matrix for every state, so the start does not change the exponent).

E20 Canonical order and ids. Orbits are numbered 1, 2, ... in this order: panel cells by K index, then class order T, R, C, S, X, inside a cell by draw index; then the controls of E19(a) in their order; then the Y5 control. The canonical representative of a periodic orbit is its point with the lexicographically smallest wrapped (x, p) after rounding to binary64.

## Algorithm

0. Validate every input before any computation (E0 and the checks of acceptance criterion 1). A bad input is an error naming the key and the rule; nothing is written.
1. Read the preregistration, compute H (E18), refuse on mismatch. Read the inputs. Record the header's value and the computed one.
2. For each K_i: define the classes (all five for K > 0; T and R for K = 0).
3. Periodic orbits. K > 0: (a) the exact fixed points (E5), classified by E4 with the trace computed at 256 bits. (b) For each period q = 1, ..., q_max, from every grid centre as seed (all N_g^2 centres in ascending id; deterministic by construction, so no stream is needed; proposed over a random subset because it needs no count the preregistration lacks): form the 256-bit lifted iterate, take the winding (m, j) from its rounding (E3), and iterate the Newton step of E3 at 256 bits up to newton_max steps. Abandon the seed if tr J_q - 2 is zero within 256-bit rounding, if a value is not finite, or at the cap. Accept at the first iterate with ||F||_inf <= rho. Then polish: continue until ||F||_inf <= rho^2 or the cap (proposed: quadratic convergence makes this one or two steps; acceptance stays at rho as preregistered, the recorded residual is the final one). (c) Reduce to the primitive period, wrap to [0, 2 pi) with exact reduction, recompute the winding of the stored representative (E2), classify (E4), deduplicate (E9) in ascending (q, grid cell id) order after all seeds finish. K = 0: the lines of E7, recorded as parabolic, no search. The result is the periodic set P_K, the elliptic subset, and a table of orbits (period, windings, points at 256 bits, trace, class, residual).
4. Screening. For each K_i (also K = 0, which T needs): the N_g^2 centres of E10, run as E11, one grid cell per work item. Per grid cell keep lambda_scr and the block exponents until class assignment, then drop them.
5. Qualifying lists (E11) for T, C, S per K > 0 and T at K = 0; the R and X classes do not use screening.
6. Draws (E14 with E15) for each panel cell in the order S, C, T, R, X, placements by E12 and E13. Record per cell: qualifying count M, drawn count, status (populated, short, empty, undefined at this K) and a reason code for empty and short (no qualifying grid cell; no elliptic periodic point; class undefined at K = 0).
7. Controls (E19). Periodic points and the Y5 control. Controls are not drawn, so they have no cell and no draw index.
8. Subsets (E17), ids (E20), per-orbit seeds (E16).
9. Initial conditions. Every orbit's canonical start is the binary64 pair of lifted coordinates (x_0, p_0); every precision of a study widens it exactly (`lyap-benettin-spec.md` S2; precision spec, Algorithm 2). For each coordinate a decimal text with 1 + ceil(bigfloat_bits log10 2) significant digits (79 for 256 bits) is also written: for a start that was formed in binary64 (grid centres) it is the exact value of the binary64 and rebuilds the same 256-bit number; for a start formed at 256 bits (periodic points, displaced R starts, Newton controls) it is the 256-bit value before the single rounding to binary64, so a study may start a 256-bit run from the true periodic point. The binary64 pair is canonical; the decimal text is informational and exact enough to rebuild a 256-bit start (proposed: one rule for all runs and the identical-orbit protocol, and the exactness that the periodic-orbit controls need).
10. Write the panel file (Algorithm item 11), then discard the screening data.
11. Panel file content (the format of stage 02 is TOML; layout details are the build's, the content is fixed here). Every orbit: id; K index and K as written and as binary64; system (standard map or linear Y5); design class (T, R, C, S, X, or control); control flag and kind; start (x_0, p_0) as binary64 and as decimal text; for K = 0 R starts the integers (a, b); for R starts at K > 0 the id of the periodic orbit and point used and the angle phi; for X starts r and phi; run seed, per-orbit seed, cell stream seed and draw index; membership in S_D and S_L; for controls the period, the windings, the stability class and the analytic exponent (binary64 shortest decimal that round-trips, from the 256-bit value). Manifest block: format version; package version; git SHA and a dirty flag; the preregistration path, its header SHA-256 and the computed one, the number of amendment entries; every input value used (E0), with its source (preregistration or default); the K values as binary64; the stream rule and the generator's identity and version; per panel cell the qualifying count, drawn count, status and reason; the draw order; the table of periodic orbits; counts per K, per period and per class; Newton statistics (seeds tried, accepted, abandoned by reason); the smallest separation between distinct orbit points; the control list; the subsets' sizes, whether a cap was applied and the removed ids; totals. The file holds no wall-clock time, host name, thread count, backend or device (those go to a provenance sidecar), and no screening exponent or block exponent (Invariants I4).
12. Portrait content, one per K, handed to the Figures layer as data; rendering is not specified here. In wrapped coordinates [0, 2 pi) x [0, 2 pi): (a) the first n_plot iterates of every panel orbit at that K (binary64, lifted orbit wrapped), small markers coloured by design class; (b) the start of every orbit as a larger marker of its class; (c) every periodic orbit point of period <= q_max, hyperbolic as a cross, elliptic as an open circle, parabolic as a diamond; (d) the controls marked; (e) a note per K listing empty and short cells with their reason. No screening data is drawn. The stage 02 checkpoint looks at these.

## Invariants

- I1 Coordinates: the wrapped form of every start lies in [0, 2 pi) in both coordinates (the wrap of `standard-map-spec.md` item 2 and Amendment D28); lifted starts are finite.
- I2 Membership: every non-control orbit belongs to exactly one panel cell (K index, class), and its class is the class of the cell it was drawn for. Orbit ids are unique and run 1..N without gaps in the order of E20.
- I3 Controls are disjoint from drawn orbits: no drawn start equals (after wrapping) the start of a control, and a control appears once.
- I4 No screening value enters the panel file or any metric: lambda_scr, block exponents and window statistics exist only between steps 4 and 10, and the panel file holds counts of qualifying cells but no screening value.
- I5 No cell is filled from another class: an empty cell has zero orbits; a short cell has fewer than n_c orbits of its own class.
- I6 Nesting: S_L is contained in S_D, which is contained in P; sizes do not exceed the caps; controls are never removed by a cap.
- I7 Every accepted periodic orbit: all q points satisfy ||F||_inf <= rho when recomputed in 256-bit arithmetic (tested independently, acceptance criterion 8); |det J_q - 1| <= 16 q eps_BF max(1, ||J_q||_F^2); its primitive period is its stored period; class and exponent are properties of the orbit (E4).
- I8 Determinism: the panel file is a function of (preregistration bytes, defaults, package source) only. It does not depend on thread count, chunk size, backend, device, wall time or host.
- I9 Draw independence: the numbers consumed by one panel cell's stream do not depend on any other cell's stream; screening and Newton consume none.
- I10 At K = 0 only T and R cells exist; C, S and X cells are recorded as undefined at this K, not as empty.

## Compute

Policy: `_config/architecture.md`, "Compute" (decisions D17, D25, D29); random streams are keyed by cell and orbit id, never by thread or device.

- Data parallel: screening (grid cells are independent; no cross-cell reduction) and the Newton search (seeds are independent). The draw, the subsets, the controls and the file are sequential and cheap.
- Screening on CPU threads, class assignment CPU only (chosen; proposed, P6). Architecture marks Float64 grid ensembles as GPU candidates, but the discrete outputs (which grid cells qualify, hence the panel) must be bit-identical across devices, and the CPU-GPU agreement of an exponent is statistical (tangent-core AC12(c) allows 6 sigma per orbit; risk K16), so a GPU value within that band of a threshold could flip a class and no tolerance can promise identity. Detecting near-threshold cells and recomputing them on the CPU would still rest on a statistical, not a guaranteed, bound. The cost does not need the GPU: about 6 x N_g^2 x N_scr = 3.9e10 orbit-steps for the preregistered inputs, about 0.4 thread-hours at the 33.09 ns per orbit-step of the preregistration's Budget table (derived), about a minute on 23 threads. The module therefore runs screening on the CPU backend whatever `backend` says; the provenance sidecar records backend cpu with an empty reason (a requirement, not one of the nine fallback reasons of architecture "Compute", so no new reason is added). The CPU-GPU agreement tolerance is therefore not needed for this module's outputs; for any other use the single home is tangent-core AC12.
- Newton in 256-bit arithmetic on CPU threads, dynamic scheduling over (K, q, grid cell id); BigFloat is not a device type (architecture "Compute"). Estimated work for the preregistered inputs: 5 K x 65536 seeds x 6 periods x (about 30 iterations x about 3.5 steps) at about 18 microseconds per 256-bit step (the preregistration's Budget table, order of magnitude) is about one thread-hour (derived; P9). Results are collected, sorted by (K index, q, grid cell id) and deduplicated sequentially, so the thread count cannot change the outcome.
- Memory per grid cell during screening (structure of arrays): 2 state and 4 tangent numbers (48 bytes, `standard-map-spec.md` Compute), a compensated accumulator (16 bytes), and N_scr / w block exponents (8 bytes each): 800 bytes for the preregistered values, 864 bytes in all, 57 MB for N_g = 256. Per Newton task: a few tens of 256-bit values (below 4 KB per thread). The hot loop of screening allocates nothing after warm-up (`_config/coding-conventions.md`, Code). Chunking of the grid is by free memory at run start, never a fixed number, and does not change results.
- Reproducibility: no stream is used by screening or Newton; draws come from per-cell streams (E15) on one thread after both finish. The panel file is byte-identical with 1 and N threads (acceptance criterion 19).

## Amendment D51 (2026-10-17)

Supersedes Amendment D50 (its merge rule, its input sn_trace and criteria D50a to D50c are withdrawn). E3 acceptance gains a conditioning test. A Newton solution z with residual ||F(z)||_inf <= rho is accepted only if its position error bound

    e(z) = ||F(z)||_2 / sigma_min(J_q - I) <= delta_dup / 10,

with J_q evaluated at z. For the 2D map det(J_q - I) = 2 - t (det J_q = 1, E3), so sigma_min(J_q - I) = |2 - t| / ||J_q - I||_2 (derived; analytic). If |2 - t| is zero in the working precision, e(z) is infinite. Reason: near a tangent bifurcation (t -> 2) the residual no longer bounds the distance to a true periodic point (linearization of F at z), so a binary64 parameter next to the bifurcation value, such as K = 2pi, yields a cloud of residual-accepted ghost points. A solution that passes the residual test but fails the bound is rejected as ill-conditioned; the manifest counts these per K index and period, with the smallest |2 - t| among them. They never enter the periodic set, R placement, the C exclusion or the controls. The E9 refusal (smallest separation below 10 delta_dup) is unchanged. The exact fixed points are exempt only where their trace is analytically away from 2 (E5); at K values where an exact fixed point is parabolic it is kept as parabolic with its analytic class.

### Acceptance criteria (amendment)

- D51a A synthetic solution with residual <= rho and |2 - t| such that e > delta_dup / 10 is rejected and counted as ill-conditioned; the same residual with |2 - t| of order 1 is accepted.
- D51b The bound equals ||F||_2 ||J_q - I||_2 / |2 - t| within 1e-12 relative on random 2x2 matrices of determinant 1 (seeded).
- D51c At K = 2pi in binary64 with the study inputs the build completes, no accepted periodic point lies within 1e-5 of (pi/2, 0) (torus distance, period 1) unless its error bound passes, and the ill-conditioned count at K = 2pi is positive. The single homes stay where they are: thresholds, horizons, subsets, sweeps and caps in the preregistration; health multipliers in `_config/numerics-defaults.toml`; the layout in `schema/run-store.md`; the backend rules in `_config/architecture.md`, "Compute".

### What changes

1. Scope. The module gains (a) a run plan built from the preregistration, the panel file and the block, (b) a chunked, resumable executor with health checks, one rerun of a failed chunk and campaign stop rules, (c) the run store, one HDF5 file per chunk, (d) the study manifest, (e) a pilot mode. The command-line entry point (D16, D49) gains the commands run and pilot; it only parses arguments and calls the module. Still out of scope: analysis, labels (D36, D37), figures, N-body adapters.
2. Generic by construction. Every study value (methods, subsets, horizons, sweeps, tau, perturbation sizes, directions, precisions, recording grid, health tolerances, fractions, caps, wall cap, backend requests, budget lines) is read from the preregistration. The module holds no study value; tests use fixture blocks and are run with at least two different ones (D53r).
3. Preregistration amendment A4 (proposed, to be written by study/01 under its Amendment rule before any data exists; the preregistration is not edited here). It adds a `[run]` block next to the panel block and nothing else; no frozen threshold changes. Keys, without values:
   - `[run.primary]`: tau, eps (L2 perturbation size), direction (angle, closed-form string as in the panel block), coordinate_mode.
   - `[[run.arm]]` (repeated, order is the arm order): name, orbits (P, S_D, S_L or h4), methods (ids), precisions (labels), horizons, and the sweep keys tau, eps, direction, coordinate_mode, each optional (absent means the primary value), h1_check (bool: the arm whose items decide the exact-exponent control rule).
   - `[run.grid]`: points_per_decade, first_steps, extra_fractions.
   - `[run.backend]`: one backend request per precision label.
   - `[run.health]`: fail_fraction, control_bound, control_methods, setup_check_steps, setup_check_tol, drift_bound, rerun_attempts, stop_failed_fraction, first_chunk_cost_factor, wall_cap_hours.
   - `[run.budget]`: per precision label ns_cpu_thread, ns_gpu, safety.
   - `[run.k19]`: threads (the thread count at which the device record must have been taken).
   - `[run.verify]`: backend_agreement (the tolerance for GPU against CPU values of lambda_1(n) at grid points, form of `tangent-core-spec.md` AC12(c)), rerun_sample (items per arm).
   - `[run.pilot]`: orbits_per_k, horizon, seed_label.
   - `[[run.h4]]` (repeated): K, x0, p0, label (decimal texts; starts that are not panel orbits).
   - `panel_prereg_sha256_accepted`: the preregistration hashes under which the panel file was built and stays valid (the panel records the hash of the preregistration at its build, which A4 changes; E18 rule).
   - A4 also states (proposed) that a pilot run using no panel orbit and writing outside the study store is not data in the sense of the Amendment rule.

### R1 Run plan

1. Inputs: the preregistration (hash by E18, which must equal its header value), the panel file (plain SHA-256 of its bytes recorded), the block, `_config/numerics-defaults.toml` (seed, bigfloat_bits, renorm_interval_tau, precision, backend, the three health multipliers), the code version (item 3 below). Any missing or unknown key, an unknown id, a horizon that is not a multiple of tau, or a panel hash outside the accepted list is an error naming the key; nothing is computed or written.
2. Work items. For each arm, the Cartesian product of the orbits of its subset (membership flags and design class from the panel file), its methods, precisions, horizons and its sweep values. Subsets: P is every panel orbit, S_D and S_L the panel's membership flags (controls included as the panel flags them), h4 the block's extra starts, which take ids after the last panel id in listed order (proposed: the per-orbit seed rule of E16 then applies unchanged). The tau and eps sweeps and the direction list apply only to methods for which they exist (eps to L2 only). Parameters that do not apply to a method are absent from its item, not defaulted, so that they cannot split one computation into two items.
3. Content hash of an item (SHA-256, UTF-8, LF): canonical text of orbit id, system, K text, start decimal texts, run seed, per-orbit seed, method id, precision label with bits, horizon, tau, eps (L2 only), direction text, coordinate mode, the vector count, the resolved recording grid (its hash), a hash version tag, and the code version. Excluded: backend, device, thread count, launch capacity, arm names, times. Code version (proposed): the identifier of the committed content of the library source and the dependency lock together, so a commit that changes neither (a documentation commit) does not invalidate stored chunks; the manifest records the full commit SHA of every session. Identical items of different arms are one item; the item lists its arms. The plan reports the step count with and without this merge.
4. Deterministic order and ids. Items are numbered 1, 2, ... in the order: precision (order of the block's request table: Float64 first), arm order of the block, run type in block order, then orbit order of E20 (panel orbits, then extra starts). A merged item takes the position of its first arm. Float64 therefore precedes Double64 and BigFloat, which the setup check of R5 needs. The plan is a function of (preregistration bytes, panel bytes, block, code version) only (I11).
5. Plan output: item and chunk counts, planned orbit-steps per arm and per precision (before and after the merge), the chunk table, and a plan hash. A plan holding zero items is an error.

### R2 Recording grid and recorded series

1. Grid (the preregistration, Metrics, "Recorded n"). For horizon N, the set of target steps is: every step 1 to first_steps; round(10^(j / points_per_decade)) for every integer j >= 0 with the value <= N (256-bit evaluation, half up; proposed: one rule, platform independent); round(f N) for each f in extra_fractions; and N. Each target n maps to the handoff step tau ceil(n / tau) (proposed: the estimators are defined at handoffs, tau-matched sweeps then record at the first handoff not before the target); the list is sorted, duplicates removed. extra_fractions must include the fractions needed by the label rules (N / 10 for the growth ratio r(N), N / 2 for the rotation numbers; proposed, stated for A4). Orientation (derived, not a criterion): with 20 points per decade, 100 first steps, fractions 1/10 and 1/2 and tau = 1, N = 1e7 gives 201 steps and N = 1e8 gives 221.
2. Per work item, at every grid step n:
   - the finite-time exponents of the method: L1 and L2 one value (lambda_1(n), natural log per map step, Euclidean 2-norm on the lifted tangent vector as the preregistration's Metrics); the QR family and L9 both exponents (lambda_1(n), lambda_2(n); for L9 the singular-value exponents of `lyap-svd-stabilized-spec.md`);
   - the orbit point at n (lifted coordinates; in wrapped mode the wrapped coordinates and the integer winding counts, D28 and D31), which serves the drift rule, the rotation numbers and the setup check;
   - for each diagnostic defined for the method (`diagnostics-spec.md`, Scope: det and symplecticity for L1, L3 to L6, L9; orthogonality for the QR family; sum and pairing for the full-spectrum methods; none for L2): the running maximum of the residual up to n, and once per item the threshold in force and the step of the first exceedance if any;
   - once per item: steps, vector count, wall seconds (the item's share of its launch group, proportional to its steps), thread seconds, resident bytes.
3. Precision of storage (proposed): every floating value is stored as binary64, rounded once from the element type; the precision label is recorded. Resolves the dataset-dtype question left open by `precision-spec.md`. The values the preregistration compares (differences down to 1e-8) lose nothing.
4. Cost of storage (derived): about 16 kB per item at 201 grid steps (at most 10 values of 8 bytes per step), below 0.5 GB for the about 20 000 items of the preregistration's arms.
5. Diagnostics must hand the runner each orbit's running maxima, thresholds and first-exceedance record without raising; the host-side raise of `diagnostics-spec.md` ("Health error") is for callers that want an abort. If only the raising form exists, adding the per-orbit report is part of this build, as P8 was for the prescribed direction.
6. Deviation vectors. The first deviation vector of every work item is the item's direction; for k = 2 the second is its counterclockwise quarter turn (proposed: orthonormal, deterministic, no random numbers, so the L5 and L9 results of the panel's screening convention are reproduced; the preregistration says only that the Q-method frame is rotated to the direction). L2 places its shadow orbit along the same direction. The per-orbit seed is still recorded. If tangent-core cannot take a prescribed first vector, adding that is part of this build (as P8).

### R3 Chunks and memory

1. Study chunk (the preregistration, Stopping rules: "one (cell, method or run type, precision, backend) block of orbits at one horizon"): the work items of one run type whose orbits belong to one panel cell, or all controls, or all h4 starts. The chunk is the unit of health checks, failure, rerun, file and resume. A chunk has a stable id: its canonical text key (arm-independent: run type and cell) and its ordinal in the plan order; ids do not depend on free memory, threads, backend or the order in which chunks were run.
2. Chunk hash (SHA-256): the chunk key, the sorted item hashes, and the values that decide its status (the health multipliers of `_config/numerics-defaults.toml`, fail_fraction, the bounds of the block).
3. Launch group. Free memory read at run start sets a capacity in orbits: floor(f x free_bytes / (M + reducer bytes + series bytes)), f as in tangent-core, Compute (recorded); M and the reducer bytes as there, series bytes = 8 x (columns per grid step) x (grid steps) per orbit. Consecutive chunks of one run type and one resolved backend are grouped into launches up to that capacity, a chunk larger than the capacity is run in several launches (orbit independence, I5 of tangent-core). Grouping exists for GPU occupancy (the device record separates the one-wave rate from the ensemble rate, `_config/environment.md`, Local GPU), and changes no result (I12). Device and host memory are read separately; the host capacity bounds the series buffers kept until the files are written.
4. A fault in one chunk never invalidates another chunk of the same launch: results of orbits not named by the fault are those of a run without it (orbit independence). The numerical health error of the stream names an orbit id; the chunk owning that id fails (R5).

### R4 Backend

1. Request per precision from the block (proposed from the preregistration, Methods: auto for Float64; cpu for Double64 and BigFloat). Resolution per (precision, method) pair at run start by the rules of `_config/architecture.md`, "Compute" and `tangent-core-spec.md`; the result and its reason (one of the nine strings, or empty) are recorded in the manifest and per chunk. The table can be mixed: a method whose reducer chain is CPU-only (`lyap-householder-qr-spec.md`, Compute) runs on CPU while the others may run on the device; the preregistration's GPU estimate applies only to the methods that resolve to GPU.
2. Float64 on the device only if the record in `data/gpu-benchmark.toml` for the device and element type has `threads` equal to the thread count of the run and `gpu_faster` true (K19, D29). An absent entry, a record taken at another thread count, or `gpu_faster` false resolves to CPU with the existing reason "GPU not faster for the element type"; no tenth reason is added (proposed); the manifest notes a thread-count mismatch. The run's thread count defaults to the maximum core count of `_config/environment.md`, is recorded, and is compared with `[run.k19].threads`: a difference is a refusal unless an explicit recorded override is given.
3. Thread independence. On the CPU backend the stored values of every work item are bit-identical at any thread count (I12). Across backends only the tolerance backend_agreement holds and only on lambda_1(n) at grid steps (K16); a chunk records the backend that produced it. A resumed run whose resolved table differs from the manifest's is refused unless an explicit recorded override is given (proposed), so that a campaign is not silently mixed.
4. Rerun after failure is on CPU with the same inputs (the preregistration, Stopping rules).

### R5 Health checks, failure and stop rules

All thresholds come from the block and `_config/numerics-defaults.toml`. Checks run when a chunk's launches are done, before its file is written.

1. A chunk fails if any of:
   - (a) a non-finite value in any recorded series, or a numerical health error from the stream (including orthonormalisation breakdown);
   - (b) the diagnostics running maximum exceeds the threshold in force for the orbit-method pair in strictly more than fail_fraction of the chunk's orbits (strict, so a count equal to the fraction passes); the exceeding orbits are flagged "diagnostics exceeded" in any case, also in a passing chunk, so that the analysis labels them unresolved;
   - (c) an exact-exponent control, in an item of an arm marked h1_check and a method of control_methods, has |lambda_1(n) - exact| above control_bound at the item's horizon (its last grid step): this is a code defect, the campaign stops at once with status "stopped: control bound" and the item is reported (the control's exact exponent comes from the panel file); controls with exponent zero are not checked;
   - (d) the setup check: for an item at an extended precision, the orbit coordinates at the first setup_check_steps grid steps differ from the Float64 item of the same orbit, method, tau, direction and coordinate mode (lowest plan position, whose grid contains those steps) by more than setup_check_tol; with no such reference item the check is recorded "no reference" and does not fail;
   - (e) the chunk's cost cap of item 5.
2. Drift (the preregistration, Eligible sets): an orbit whose recorded lifted |p| exceeds drift_bound at any grid step is flagged "drift" (a flag, not a failure; evaluated from the recorded orbit point; wrapped mode uses the winding counts).
3. Rerun. A failed chunk is run once more on CPU with the same inputs (rerun_attempts). If the second attempt passes, the file records attempt 2 and the first attempt's reasons. If it fails, the file is written with status failed, the reasons and the orbit ids, those orbits count as "excluded, failed twice" for the analysis, and the failure is final: a resume does not retry it unless explicitly asked. A deterministic failure on CPU repeats; the rerun serves device and transient faults (stated, not hidden).
4. Campaign stop. The campaign stops, with the status recorded in the manifest and a resumable store, when: (a) the control rule of 1(c) fires; (b) the number of chunks failed twice exceeds stop_failed_fraction of all chunks of the plan (strictly more; the denominator is the plan, not the chunks run so far; proposed); (c) the campaign wall time, summed over sessions from the manifest, reaches wall_cap_hours: checked before each launch group, so a group in flight finishes (proposed: no half-written results); (d) the preregistration hash or the panel hash differs from the start value (R7); (e) a refusal at start. No stop depends on a scientific result: nothing here reads a hypothesis quantity.
5. First-chunk cost cap. For the first completed launch group of each arm, the measured cost per orbit-step (CPU: wall seconds x workers engaged / orbit-steps; device: wall seconds / orbit-steps) is compared with the arm's budget line per orbit-step for the resolved backend: ns from `[run.budget]` x safety (proposed basis: the line as the preregistration's CPU-hour arithmetic gives it, with its safety factor). If it exceeds first_chunk_cost_factor times the line, the arm is paused (status "paused: cost cap"), its remaining chunks are not run, other arms continue, and the audit "complete" fails until the arm is resumed by an explicit recorded cap override (proposed; the Amendment rule bars amendments once data exist, see P14).
6. Campaign status values: complete, complete with failed chunks, stopped (with reason), paused arms.

### R6 Run store

1. Under the data root of `_config/environment.md`: `[study]/` holds one file per chunk named by the chunk ordinal (`schema/run-store.md`, Files), plus the chunk key in the file. One file per chunk, not one per study (proposed): it follows the schema, a crash can damage at most the file being written, HDF5 has no safe concurrent writer, files are independent for resume and for a later job-array run (`_config/architecture.md`, Scalability), and about 1800 chunks (derived: 28 cell groups times the run types of the arms, before the merge) is a small number of files. A single file would turn the last chunk of a campaign of hours into a corruption risk for all of it.
2. Layout: `schema/run-store.md` with the version 2 changes of R10. One orbit group per orbit; series datasets named by the schema (`lyap/<method>`, `diagnostics/<name>`, `cost/<method>`, `t`), plus the recorded point and winding counts.
3. Atomic write. A file is written under a temporary name in the same directory with `complete` false, closed, read back (series checksum equal to the buffers), then set complete and renamed to its final name. No file with a final name is ever incomplete (I13). Temporary files left by a killed run are listed in the manifest at the next start and removed (they hold no accepted data).
4. A chunk file is never modified after the rename; a rerun writes a new file under the same name by the same procedure (the replaced file is moved aside, never deleted).

### R7 Manifest

JSON, written atomically after every chunk and at every session end, at the study stage's output path (`workspaces/study/stages/03-run/CONTEXT.md`, Outputs). It holds:
- study slug, schema version, plan hash, plan counts, campaign status and reasons;
- git: commit SHA of every session and a clean-tree flag; the run refuses to start on a tree with any tracked change or any untracked file that is not ignored, unless an explicit override is given, which is recorded with the list of differing paths and a hash of the difference (proposed: allowed for pilot and tests, and a study run with an override fails the stage audit);
- versions: language, packages (hash of the lock), HDF5 library, the module version; the host (cpu, cores), the thread count used and available;
- backend table of R4 (request, resolved, reason) per (precision, method), the device name, the device record in force with both K19 values (the record's threads, cpu and gpu ns per orbit-step, gpu_faster, date) and the prior record supplied by the run option (the 4-thread record copied before the rerun, preregistration Budget, K19), or "absent";
- preregistration SHA-256 (E18 rule) at start and at end of every session and its header value; the run refuses to start if it differs from the header, and stops if it changes between checks (checked at start, before each launch group, at end); the panel plain SHA-256 and its recorded build hash, checked the same way;
- the block as parsed (canonical text and hash); the numerics defaults used; launch capacity inputs (free memory read, f);
- chunk list in plan order: id, key, hash, arm names, status (ok, failed, pending, paused), attempt, backend, fallback reason, orbit count, steps, wall seconds, first-attempt reasons, flagged orbit ids by flag (diagnostics exceeded, drift, excluded);
- per-arm totals: steps, wall seconds, thread seconds, measured cost per orbit-step against the budget line; session list with UTC start and end; total wall time against the cap.

### R8 Resume

1. At start the store is scanned. A complete file whose chunk hash equals the plan's is skipped. A final failed file (status failed, attempt at the limit) is skipped. A file whose hash differs (stale: the code version or an input changed) stops the run listing the files; with an explicit recorded option it is moved to a stale area and recomputed, never deleted. A plan chunk without a file is run.
2. Resume trusts the files, not the manifest, which is rebuilt from the files and the previous manifest's session list.
3. Resume results equal an uninterrupted run (I14).

### R9 Pilot mode

1. Purpose: estimate the cost of every arm against its budget line and the wall cap before any study chunk runs, and calibrate the setup check.
2. Orbits: not panel orbits. For each K of the panel, `[run.pilot].orbits_per_k` starts drawn uniformly on the torus from a stream keyed by (seed_label, K index) built as E15; a start within torus distance 1e-6 of any panel start is replaced by the next draw (proposed; the run refuses if none is found after 1000 draws). Pilot starts use the run types of the plan at horizon `[run.pilot].horizon` and the run's thread count and group capacity.
3. Output: a report (JSON) and a pilot store in a separate directory marked pilot, never read by resume, by the manifest of the study or by analysis. The report holds: measured thread-seconds and wall-seconds per orbit-step for each (method, precision, resolved backend); per arm the planned unique steps times the measured cost, projected thread-hours and wall-hours at the run's thread count with the parallel efficiency observed in the pilot, against the budget line and the first-chunk cap, and against the wall cap; the K19 records; per K the step at which Double64 and BigFloat orbit coordinates first leave Float64 by more than setup_check_tol; the share of orbits above the diagnostics thresholds per method. It states that its numbers are not study data.
4. A pilot under a dirty tree is allowed with the override recorded; the report says so.

### R10 Schema change (proposed): run store version 2

`schema/run-store.md` is bumped to `schema_version` 2 (its header allows a bump by the first Experiments spec). Additions only; version 1 files are not produced.
- Root attributes: `chunk_key`, `chunk_hash`, `plan_sha256`, `panel_sha256`, `code_version`, `method`, `precision` (as v1), `horizon`, `tau`, `vectors` (k), `coordinate_mode`, `direction` (text), `perturbation` (L2 only), `grid_sha256`, `backend_request`, `status` (ok or failed), `attempt`, `first_attempt_reasons`, `failure_reasons`, `pilot` (bool), `arms` (list), and the provenance fields proposed in `tangent-core-spec.md` (renorm_interval_tau, deviation_vectors_k, seed, chunk_size, gpu_chunks, steps per launch, launches per chunk) and `lyap-gram-schmidt-spec.md` P3 (orthonormalizer, implementation). `config_sha256` is the hash of the canonical text of the block. `complete` means the file was written to the end (R6), whatever the status.
- Orbit attributes: `item_hash`, `design_class` (the schema's `class_label`), `flags` (diagnostics exceeded, drift, excluded), `steps_recorded`.
- Datasets per orbit: `t` (int64, grid steps), `state` (n x 2, binary64), `winding` (n x 2, int64, wrapped mode only), `lyap/<method>` (n x k, binary64), `diagnostics/<name>` (n, running maxima, binary64) with attributes `threshold` and `first_exceedance_step`, `cost/<method>` (steps, vectors, wall seconds, thread seconds, resident bytes).
- `/grid/` is unused by this module. A failed chunk file holds the root attributes and the orbit groups that exist.
Why: the version 1 attributes cannot tell two run types of one study apart, cannot hold a failure, and have no place for the recorded orbit point on which three preregistered rules depend.

### Compute (amendment)

Policy: `_config/architecture.md`, "Compute" and "Scalability".
- Data parallel: work items (orbits within a launch group). CPU: dynamic scheduling over orbits, BLAS threads 1 when worker threads exceed 1. Sequential and cheap: planning, hashing, health checks, file writes (one writer after each group, so the store never has concurrent writers), the manifest.
- GPU candidates: Float64 methods whose chain has no CPU-only reducer, on the conditions of R4. CPU only: Double64 and BigFloat (K20), the library Householder path.
- Memory per orbit: the stream and reducer bytes of the lower specs plus 8 x columns x grid steps for the series (R3); about 16 kB at 201 steps, which dominates the 100 to 250 bytes of state. The hot loop allocates nothing after warm-up; the series buffers are allocated per launch group.
- Cost of the module itself (derived): hashing and writing about 16 kB per item, about 20 000 items: seconds compared with the 29.6 thread-hours of the preregistration's Budget.
- Reproducibility: the stored values depend on (item inputs, code version) only (I12); random numbers: none in the runner (pilot starts use the E15 construction).

### Invariants (amendment)

- I11 Plan determinism: the plan, ids and hashes are a function of (preregistration bytes, panel bytes, block, defaults, code version); not of thread count, free memory, backend, host or time.
- I12 Result independence: on the CPU backend every stored dataset of a work item (except wall and thread seconds) is bit-identical for any thread count, launch capacity, chunk grouping and run order.
- I13 No incomplete file under a final name; a killed run leaves only complete files and temporary files.
- I14 A resumed campaign equals an uninterrupted one in every stored dataset and attribute except times, host fields, session lists and wall seconds, on one machine, one language version and one resolved backend table.
- I15 Pilot isolation: no pilot file is in the study store; no pilot start equals a panel start.
- I16 The module holds no study value (D53r).
- I17 Every chunk of the plan is, at campaign end, complete (ok), final failed with reasons, paused with reason, or pending with the campaign's stop reason; none is silently missing.

### Oracle (amendment)

In the package suite (synthetic, analytic or self-contained):
- O8 Independent hash: item and chunk hashes recomputed from the canonical text by a second implementation (the platform's command-line SHA-256) equal the module's.
- O9 Direct call: the value stored at a grid step n equals the final value of the verified estimator run directly to n with the same inputs (same system, K, start, direction, tau, element type, coordinate mode, run seed), bit for bit on the CPU backend. This also fixes that a chunk is a prefix-consistent record of the estimator.
- O10 Resume: an uninterrupted fixture campaign against a campaign killed at seeded points and resumed.
- O11 Y5: the control of E19(b) in the stored series: lambda_1(n) = ln mu + ln(c) / n up to the bound of `lyap-householder-qr-spec.md` AC5, where c (a function of the start direction and the symmetric block) is computed at 256 bits; for the direction along the unstable eigenvector c = 1.
- O12 CPU reference rerun: an item rerun on CPU equals the stored item bit for bit if it ran on CPU, and within backend_agreement if it ran on the device.

In the separate verification environment (stage 04, `verify/`):
- O13 Independent reader: the files are read by a reader written outside the package (Python or the platform's HDF5 tools); every dataset and attribute of the layout is present with the stated dtype and equals the package's read-back bit for bit.
- O14 Independent hash and plan: the canonical item text, hashes and the plan item count for the reduced campaign recomputed by a script in `verify/`.
- O15 The reduced campaign of D53w, with the CPU-reference rerun of O12 on the stored sample and, local, the device record resolution.

### Acceptance criteria (amendment)

Package-suite criteria use a fixture of at most 12 panel-like orbits in 3 cells plus 2 controls and 2 extra starts, horizons at most 2000 steps (tau in {1, 2, 4}), all nine methods at Float64, Double64 on 2 orbits, BigFloat on 1 orbit at horizon 200, fixture blocks written for the test; the added suite time is at most 120 s on 4 threads (proposed). Criteria marked [full] run in stage 04. Tolerances: eps_53 = 2^-52.

- D53a Block validation. At least 30 malformed blocks, each refused before any computation, with an error naming the key and writing nothing: missing or unknown key; unknown method, precision, subset or backend request; empty arm; duplicate arm name; horizon not a multiple of tau; N / 10 not a multiple of tau when 1/10 is among the extra fractions; extra fraction outside (0, 1); points_per_decade or first_steps not positive integers; fail_fraction or stop_failed_fraction outside [0, 1); safety below 1; cost factor or wall cap not positive; control_bound not positive; setup_check_steps beyond the shortest horizon; two h4 starts with the same label; a pilot horizon above the shortest arm horizon; panel hash outside the accepted list; preregistration hash not equal to its header value; thread count differing from `[run.k19].threads` without override. Pass: all refused, 0 files, message names the key.
- D53b Plan. On the fixture: the item count equals the hand count (Cartesian products per arm minus merged duplicates); ids run 1..M with no gap in the order of R1 item 4; the plan bytes are identical on repeated planning, for 1, 4 and all threads, and for a block whose tables list their keys in another textual order (arm order unchanged); the planned steps per arm before the merge equal the sum of products, and the merge reports its saving; two arms that produce the same item give one item listing both arms. [full] With a synthetic panel of the preregistration's caps (1100, 200, 100) and the study block, the planned orbit-steps per arm equal the rows of the Budget table (relative 1e-9 of the printed digits) and the Float64, Double64 and BigFloat totals equal the table's totals; with the real panel the counts are those of the panel's subsets.
- D53c Hashes. Changing any single field of an item listed in R1 item 3 changes its hash (one case per field, at least 14); changing backend request, thread count, launch capacity, arm name or time does not; the code version changes with a source change and not with a change to a file outside the library source and lock; item and chunk hashes equal the independent implementation (O8) on 1000 seeded items; the chunk hash changes when fail_fraction changes.
- D53d Grid. - D58c Manifest. A campaign started with the record read from a file writes it as `prior_record` (threads, cpu and gpu cost, date) next to the unchanged `device_record`; a run without the option still writes `"absent"`.

## Amendment D59 (2026-10-20)

The first study campaign (2026-10-20, 377 of 1363 chunks done after 35 minutes) stopped with `IOError: open(".../p1-le-benchmark-manifest.json.2"): permission denied (EACCES)`: another process held the numbered backup for a moment while the manifest writer rotated the backups. M1 (D55) retries the final replace of the manifest and of chunk files on the codes busy, access denied and not permitted, but the rotation of `manifest.json.1` to `.3` and the write of `manifest.json.partial` had no retry, and a failed backup copy ended the campaign although the manifest itself was intact. D53 to D58 are otherwise unchanged. P-numbers: none new.

**Retry.** A single helper tries an operation again, with a growing pause, when it fails with one of the three codes: 12 tries, pause 0.1 s times the attempt number (about 6.6 s in all); the pause is a settable seam for tests. It is used for the write of the temporary file, the replace (as M1 did, with the same helper), and every backup copy.

**Best effort.** A backup copy that still fails with one of the three codes after the retries is skipped: the write goes on, the manifest is replaced, a warning is printed and the failure is kept in the session (`backup_failures`, one text per skipped copy). A later manifest of the session lists them under the key `backup_failures`; the key is absent when there were none, so a manifest without failures has the keys of R7. Any other error of a backup copy, and a failure of the temporary write or of the replace after the retries, still ends the write with the error (the previous manifest stays whole, M1).

**Acceptance criteria.**
- D59a Retry. A backup copy that fails twice with a busy, access-denied or not-permitted code and then works gives the same files as an undisturbed rotation; so does a temporary write that fails twice; a replace behaves as in M1.
- D59b Best effort. A backup copy that always fails with one of the three codes does not end the write: the manifest holds the new content, the older backups that did copy are kept, and the failures are returned to the caller; an error of another kind in a backup copy is raised.
- D59c Manifest. A campaign whose backup copies always fail ends `complete`; its manifest has `backup_failures` (non-empty); a campaign without failures has no such key.
- D59d No change. `keep = 0`, the final replace and the numbering of the backups behave as before (the tests of M1 pass unchanged).
