# Spec: fli-ofli

Library layer: Indicators (`_config/architecture.md`, "Module map" row Indicators). Milestone M4 (decision D65). Status: approved at the stage 01 checkpoint, 2026-10-22 (D71): FLI only (I5), OFLI deferred to M5, chain option (b) with the one-replacer rule, other open points as proposed. Shared definitions are cited, not repeated: the Benettin spec as "L1 S3", "L1 E3", "L1 Amendment D35" (conventions and symbols S1, identical orbit S2, same-orbit bound B_S and amplification sum Psi_n S3, statistical rule S5, panel and starts S7, equations E1 to E14); the sali spec as "sali A7", "sali criterion 18 (D68 form)", "sali Amendments D67, D68" (symbols S_i(n), L(n), Lambda_n, B_L, "resolved", "regular class"). Spec-local equation labels Q1 to Q13, findings F1 to F5, open points P1 to P8. Element types: Float64, Double64 (effective epsilon 2^-100) and BigFloat(256) for oracle runs; Float32 is out (D24). "n" counts map steps, handoffs fall at n = j tau (L1 S1). Page numbers are pages of the PDFs as fetched on 2026-10-22; printed pages for Skokos2010 (`data/literature/sali/arxiv_0811.0882.*`), arXiv PDF pages for the others (`data/literature/fli-ofli/`).

## Scope

- Catalog row I5 (`_config/catalogs/indicators.md`, section A): the Fast Lyapunov Indicator, for the 2D symplectic maps of the P2 panel (Y1 standard map, Y5 linear maps), in the log form. Row I6 (OFLI) is not delivered: finding F1, contract question P3 (recommended: defer to M5, flows). Row I7 (OFLI2) is catalog only. The build-order row M4 names the module `fli-ofli`; if P3 is accepted the module delivers I5 only and the name and rows are the owner's to change at stage 05.
- Prerequisites (catalog statuses read 2026-10-22): tangent-core, standard-map, precision, L1 (row I1) and L2, and sali (row I2) are `verified`; sali report `sali-verification.md` (criteria 1 to 18 passed). The tangent-core stream, seeded frame, health errors, scaled norms (now in Foundation, D69), compensated sums and the D66 chain are used as they are, with the one chain question P1.
- The module is a reducer that never changes the orbit. Dimension: Q1 to Q5, Q11 and the ordering in Q10 hold for any dimension and any number of unit columns; Q6, Q7 and the closed forms Q9 use d = 2 and det M = 1 and are labelled so. Flows are out of scope (M5).
- Out of scope: classification thresholds and the saturation cap (a study concern: pre-registered per study, `_config/numerics-policy.md`; the module never stops or caps an orbit, as sali), the running-average smoothing of FroeschleLega2000 (a post-processing of the retained series), FLI for d > 2 (M5), LGALI (row I4).
- Keys: no `numerics-defaults.toml` key is proposed. tau stays `renorm_interval_tau`, default 1. Unlike L1 and sali, the result depends on tau (Q10), so tau is a recorded parameter of the indicator, not only of the arithmetic.

### Findings for the owner

- F1. OFLI has no definition for maps in the readable sources. Fouchard2002 (abstract only, F4) introduces the orthogonal FLI for continuous flows because periodic orbits of a flow need a new value "to fully recover the results obtained for mappings"; Darriba2012 and Maffione2013 define it as the FLI of the component of each deviation vector orthogonal to the flow (Q13). A map has no flow direction, so there is no component to remove, and the case it repairs (an isolated periodic orbit has constant FLI, Fouchard2002 abstract; elliptic fixed point, Q9e) does not arise. Derived, not printed for maps. Recommendation P3: defer row I6 to M5.
- F2. Overlap with L1 (the question raised by D70). The source prints the single-vector FLI as the running maximum of the L1 accumulated sum (Q1, Q4). Hence FLI is not a function of the L1 value at the final time (the GALI_2 versus SALI situation of D70) but a functional of the whole path of the sum: it adds memory (the drawdown D(n), Q4). It is also not an independent classifier: the sources' own thresholds for FLI (N) and for the finite-time exponent (ln N / N), Maffione2011a Table 1, are the same condition on the sum (Q5). What FLI adds over L1 for claim C3 is only (i) the memory, (ii) the maximum over a basis of two vectors instead of one (within ln sqrt 2 of a basis-free value, Q7), (iii) the n-scaling of the threshold and the log versus unlogged representation (Q3). Expect FLI and L1 labels to agree except on orbits whose sum crosses the threshold from above; the recorded line R1 measures this. The reducer is still needed (neither L1 nor sali retains the per-handoff, per-column sums), P1.
- F3. The initial vector issue of row I5 is quantified. A single vector can have FLI exactly 0 for all n (the K = 0 start along the invariant line, Q9a; a start along the stable direction of a hyperbolic point, Q9b), so the single-vector value has no lower bound in terms of the system. The basis maximum of the orthonormal seeded frame lies in [F_* - ln sqrt 2, F_*] with F_* the basis-free value (Q7). FLI is also schedule dependent: unlike L1 and sali, tau changes the value (Q10).
- F4. Sources. Full texts obtained (arXiv): Maffione2011a, Darriba2012, Maffione2013; Skokos2010 was already under `data/literature/sali/`. Not obtained: Froeschle1997, FroeschleLega2000 and Fouchard2002 (Springer, paywalled; only the abstracts were read, saved as `*.abstract.txt`) and Mestre2011 (the open-access PDF at OUP is behind an automated-access challenge, which was not circumvented). No equation or number is cited from these four; statements attributed to them are as reported in the three arXiv texts or the abstracts, and say so. The definitions Q1 to Q3 are therefore sourced to Skokos2010, Darriba2012, Maffione2013 and Maffione2011a, which describe the primary definition.
- F5. Benchmarks row "FLI growth (norm-based convention)" says the logarithmic definition and its laws were not confirmed. Q1 (Skokos2010 p.56) confirms the log definition and the linear growth of the norm for regular orbits (Skokos2010 Eq. (62) p.35, L1 E5) and the exponential growth for chaotic orbits. Not edited here; P7.
- Contract questions: P1 (reducer and chain), P2 (which forms), P3 (OFLI).

### Contract question P1: does FLI need a reducer, and where does it sit on the D66 chain

Facts. (i) L1 retains X(n) at every handoff for the first column only; a post-processed running maximum of n X(n) gives the single-vector FLI (Q4) with no new reducer, if the series is stored at every handoff (tolerance in criterion 8). (ii) sali retains L(n) = -(S_1(n) + S_2(n)) and only the final S_i, so the basis form (Q2) cannot be recovered from it: max(S_1, S_2) needs the difference S_1 - S_2 at every handoff (Q6). (iii) Two reducers that each replace the columns by unit vectors cannot both see the lengths (gali spec F2): the second gets unit columns. FLI needs the lengths of the columns before normalisation.
- (a) Derived quantity only: single vector from the L1 series; the basis form is lost. Cheapest; no basis, no F3 answer.
- (b) Recommended. A small reducer that reads the arriving columns, keeps its own log sums S_1, S_2 and the two running maxima (single: column 1; basis: both), and does not replace the columns when a later reducer of the chain does. Rule added to D66: in a chain of column reducers exactly one replaces the columns at each handoff, and it is the last of them; a chain of FLI alone makes FLI the replacer. The duplicated work is two scaled norms and two logs per handoff, with the same operations as sali and L1, so the sums are bitwise equal to theirs (sali I8). No change to a verified spec. Cost: one rule, and the reducer state of Compute.
- (c) Extend the sali reducer with the two running maxima: one owner of the lengths, but it amends a verified module and re-opens sali criteria 1 to 18. As recommended for gali at M5, revisit then.
- (d) A separate pass with FLI as the replacer on the bitwise identical orbit (L1 S2): no rule, no contract change, but a second pass for P2 (D66 revisit trigger).
Criteria 1 to 11, 12(a)-(c), 12(e) and 14 to 16 hold under (b), (c) and (d); criteria 12(d) and 13(b) change under (d) (no shared chain) and under (c) (sali amended). This spec writes its criteria for (b).

## Equations

Notation. W_0 = (w_1(0), w_2(0)): the stream's seeded orthonormal frame, first two columns (L1 S2; the single-vector form uses w_1(0), the same vector as L1 with k = 1); w_i(n) = Y_n w_i(0) with Y_n the tangent product (L1 E1); alpha_i the Euclidean norm of the arriving column over a window (L1 E3); S_i(n) = ln norm(w_i(n)) = sum of the ln alpha over the handoffs up to n (unit start). "ref" = BigFloat(256) at the realized orbit points (L1 S3). In the closed forms the point is a map-state-independent tangent where stated.

## Algorithm

Per orbit (ensemble member, orbit id j, run seed s), on the stream with k = 2, d = 2 (state length s >= d allowed, tangent-core Amendment D28):
1. Initialisation. The pair is the first two seeded columns, orthonormal; both running maxima start at 0 (the s = 0 term). A supplied frame is checked by the caller before the stream (sali Amendment D67): the columns must be unit vectors (else the convention S(0) = 0 is wrong); orthonormality is needed only for Q6 and Q7 and is reported by the caller.
2. At each handoff n = j tau, for i = 1, 2: alpha_i = scaled Euclidean norm of the arriving column i; if zero or not finite, a numerical health error naming the deviation matrix, with orbit id, column and handoff step (as sali Algorithm item 2). Add ln alpha_i to the compensated sum S_i, with the same operations as sali and L1, so S_i is bitwise equal to theirs (sali I8).
3. Update FLI_1 = max(FLI_1, S_1) and FLI_B = max(FLI_B, S_1, S_2); record the handoff and column at which each was last attained (the maximisers of Q11).
4. Replacement: per the chain rule of P1 (b), exactly one reducer of the chain replaces the columns by unit vectors (a diagonal S, tangent-core E7); the FLI reducer does so only when no later reducer does.
5. Emit FLI_1(n) and FLI_B(n) at every handoff (storage schedule chosen by the caller, as L1 S8); at the end the final S_i with compensation terms, the two maximisers, tau and the chain position.

Representation. FLI is stored in the log form as computed, never clipped; the unlogged value is exp of it and is a display conversion only: above 709.78 in Float64 the exponential overflows and the display says so (K = 10, n of the order of 440 or more). The log form is finite at any depth. No early stop, no cap (the 1e20 of the sources is a study choice, Q3).

Parameters recorded per run: tau, element type, state mode (wrapped with counts, or lifted), seed, frame source, chain position (replacer or not). The frame source and chain order are recorded by Experiments (sali Amendment D67 item 2).

## Invariants

- I1 Monotone: FLI_1 and FLI_B are nondecreasing in n; FLI_B >= FLI_1 >= max(0, S_1); FLI_B >= max(S_1, S_2) (Q4, Q6).
- I2 No transparency in tau: S_i at a common n is tau independent (L1 E8), FLI is not; FLI_tau <= FLI_1 and the gap is bounded by Q10.
- I3 The orbit is unchanged by the module (L1 S2).
- I4 Symmetry: FLI_B is bitwise unchanged by exchanging the columns and by a sign change of either column (the columns evolve independently, tangent-core E5; max is symmetric); FLI_1 is not symmetric.
- I5 Basis-free sandwich (Q7): F_* - ln sqrt 2 <= FLI_B <= F_*, FLI_1 <= F_*.
- I6 Column independence: S_1 and S_2 of the reducer are bitwise equal to the sums of sali and of an L1 run per column (sali I8, verified bitwise at sali stage 04).
- I7 Orbit independence and execution invariance: orbit j's series depends only on (system, parameters, initial point, seed, j, tau, N, T, state mode, frame), not on threads, chunk or position in the ensemble; across backends only to criterion 16. The hot loop allocates nothing after warm-up (BigFloat excepted).
- I8 No floor: the computed FLI is within B_FLI of the reference at every n (Q11).

## Compute

Policy `_config/architecture.md`, "Compute" (D17, D25). Per-orbit, data-parallel, fused into the stream's single kernel: per handoff two scaled norms, two logs, two compensated adds, two comparisons; no dense factorization, so no "reducer is CPU-only" fallback reason. Reducer state per orbit, proposed: two compensated log sums (4 values), two running maxima (2 values), and two integers (maximiser handoff and column): 64 bytes in Float64, 112 in Double64, added to the tangent-core memory formula as reducer bytes (sali R6); under P1 (c) the sums are shared and only 2 values and the integers are added. GPU candidate for Float64 and Double64 (isbits); BigFloat is CPU-only with the reason "kernel does not compile for the element type" on a GPU request; GTX 1050, compute capability 6.1, weak Float64 (K15): GPU is the default for an element type only after the benchmark records `gpu_faster` (tangent-core AC13; per-method record D54). The step-chunked relaunch of tangent-core Amendment D44 must carry the running maxima and the maximisers as reducer state across launches: this is state of the reducer, not of the stream, and is flagged for stage 03 (P8). CPU-vs-GPU agreement: criterion 16 (D68 form). CI has no GPU: CPU backend.

## Oracle

Package suite (analytic, invariant, cross-method, self-contained; D21): the closed forms Q9 in BigFloat(256); the BigFloat(256) norm-form reference of Q11 at the realized orbit points; the basis-free value F_* of Q7 (closed form for a 2 x 2 determinant-one product: sigma_1^2 = (G + sqrt(G^2 - 4))/2 with G the squared Frobenius norm); the identities Q4 and Q6 against the L1 and sali sums; schedule bound Q10; health; execution invariance. The closed forms and the reference are the primary oracles.

External oracle, verification environment `verify/` (D21, D27). ChaosTools 3.5.4 (`verify/Manifest.toml`; installed source `~/.julia/packages/ChaosTools/0SbsT/`, read 2026-10-22): there is no FLI routine. A search of `src/` and `docs/src/` finds no occurrence of "FLI" or "fast Lyapunov". The nearest routines do not compute it: `lyapunov` is the two-trajectory method (L1 Oracle: the oracle of lyap-two-trajectory, finite separation, not the tangent norm); `lyapunovspectrum` is the tangent QR method (L1 oracle for X(n) of a k = 1 run, with the identity frame, L1 Amendment D43); `local_growth_rates` is log(g/g0)/Delta t over one interval, not a running maximum; `gali` is GALI_k (sali Oracle). So the primary oracles are the closed forms and the L1 cross-check on the identical orbit (criteria 2 to 8). The one external line uses `gali` (k = 2, Delta t = 1, threshold 0, hand-coded Jacobian of the lifted rule, seeded frame supplied, as sali criterion 16): through sali A7, -ln g_oracle / 2 = (S_1 + S_2)/2 <= max(S_1, S_2) <= FLI_B, a one-sided check that FLI_B is not below an independent evaluation of the mean of the two sums (criterion 15). The oracle's blindness below about 1e-15 limits it to resolved handoffs (sali A14). No external package computes the running maximum; REBOUND and the Python adapters are N-body only (project P6).

## Amendment D72 (2026-10-22)

Approved by the owner at the stage 02 checkpoint (test plan `../../02-tests/output/fli-ofli-test-plan.md`, section on deviations).

1. One-replacer rule: a reducer cannot detect its position in a chain, so the rule is carried by a reducer option: the FLI reducer replaces the columns by default (alone in a chain) and, in a chain with SALI, runs as a non-replacing reader placed before SALI. Criterion 12(e) (run record) is tested on FLI alone, since in a chain the later reducer's indicator name is the recorded one (D34 A2).

3. Criterion 9(a): the transient rule "FLI_B below ln n at 1e4" is replaced by the slope of FLI_B against ln n over the first decade [1e4, 1e5]; a start counts as transient when that slope is outside the regular-law interval of the criterion.
4. Criterion 1: FLI_1 = 0 is asserted for j up to 15 (at j = 16 the exact partial sum with the stored Float64 coefficients is +1.1e-16); the running maxima are asserted exactly for all j.
5. Maximiser ties: the recorded maximiser is the handoff of the last strict increase.
6. Criterion 13(c): the 1 versus N threads comparison in child processes is a stage 04 check; the package test compares the parallel path with the serial per-orbit body.
7. Frame check: a supplied column is accepted as a unit vector when its norm defect is at most 8 eps.
8. Criterion 9(b): the allowance 4/180 is kept; it is about ten times the realized difference and is recorded as loose.
