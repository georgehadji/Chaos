## Scope

- Catalog row I3 (`_config/catalogs/indicators.md`, section A): GALI_k, the norm of the wedge product of k unit deviation vectors, 2 <= k <= d. This run delivers k = 2 on the 2D maps of the P2 panel (Y1 standard map, Y5 linear maps), tested. The definition and the evaluation are stated for general d and k (B1 to B3, B5, B9) so that M5 (k > 2, needs d >= 4, row I3 "M5") extends them without a new definition. Row I4 (LGALI) is not touched (risk K6: no source confirmed).
- Prerequisites: sali is `verified` (catalog row I2, sali stage 04 report; its criteria 1 to 18 passed, 185 PASS and 0 FAIL on the verify log, GPU record under Amendment D68). Through sali: standard-map, tangent-core, precision, L1 and L2 are `verified`. The D69 move of the shared norm into Foundation is in the working tree; this spec does not depend on it.
- Out of scope: classification thresholds and the stopping rule (a study concern: thresholds pre-registered per study), a stream for k > 2 (M5), early termination of an orbit, LGALI, wedge products of vector fields on flows.
- Keys: no `numerics-defaults.toml` key is proposed.

### Findings for the owner

- F1. Overlap with sali. For d = k = 2 the GALI_2 value is exp(L) of the sali reducer for an orthonormal W_0 (B5 = sali A7) and is a monotone function of SALI (B4 = sali A4). A GALI_2 reducer on a 2D map computes the same number a second time and adds no information. Consequence for P2 (claim C3): on 2D maps SALI and GALI_2 are one indicator in two scalings, not two independent indicators; with thresholds mapped by B4 their classifications are identical, and with the same numerical threshold below 0.1 they differ by at most 0.13 percent in threshold value (B4). The study should report them as one, with the recorded line R1.
- F2. Chain. Two column-normalising reducers cannot both own a log form in one chain. The stream hands later reducers the replaced matrix (tangent-core Algorithm, Contract; sali P1): the first column-normaliser in the chain sees the true lengths, the second sees unit columns, so its own log sums are zero. A separate GALI reducer therefore gets either the direct form only (placed after SALI) or takes the lengths and leaves SALI without its log form (placed before). D66 ("share one reducer chain") did not address this; the sali reducer already holds everything GALI_2 needs.
- F3. Log form for k < d and the SVD route. (i) The log form B5 exists only for k = d (the volume of d unit vectors follows from det M = 1). For k < d the volume of the propagated frame is not invariant, so a column-normalised chain has no floor-free log form (the QR-factor route of sali P1(c) is excluded by D66). (ii) Skokos2008 p.4 (after Eq. (11)) states that the singular-value route permits "accurate determination of large negative values of log(GALI_k)" in double precision. That holds for the singular values of the stored matrix; the stored unit columns already carry rounding errors of about eps, so the true GALI_k is resolved only down to the floor B9. The ChaosTools `gali` measurement of sali stage 04 agrees (values 0 to 0.206, median 1.1e-16, at n = 30 where exp(L) is of order 1e-25). (iii) Of the three equivalent evaluations of B2 the Gram-determinant route squares the quantity and has a floor near sqrt(eps) (drafting check (b)), so it is not acceptable as the evaluation (criterion 7).
- F4. Sourcing upgrade for 2D maps. Skokos2007 p.38 (Conclusions) prints that Eqs. (43) and (80) are expected to hold for symplectic maps and that for regular orbits of 2D maps GALI_2 decays as 1/t^2. The sali spec (A9, P5) had the regular exponent as derived only; for the generic case it is now printed. The chaotic exponent for 2D maps (-2 lambda_1) is still derived (B6). Catalog row I3 and the benchmarks row "GALI_k, regular orbit on N-dim torus" do not state the 2D-map case (P3).

## Equations

Notation as sali (unit columns u_i, norms alpha_i = norm w_i, S_i(n) = ln norm w_i(n) from unit initial columns, phi in [0, pi/2] the angle between u_1 and u_2 modulo pi). Hat = unit vector. U is the d x k matrix of the k unit columns (the sources write it as A, k x 2N, rows). g(n) = GALI_2(n) on a 2D map.

## Algorithm

Where it sits: pure evaluations in the Indicators layer (no import of a peer layer; the shared scaled norm comes from Foundation, D69), and a derived series that reads the output of the sali reducer. Nothing is added to the stream under the recommended option (P1(b)).

1. Evaluation for any d and k. Input: k nonzero finite vectors of length d, 2 <= k <= d. Each column is normalised with a scaled norm (no overflow or underflow, as sali Algorithm item 2). The result is GALI_k of the unit set by B2. The evaluation must reach the error bound B9 (criterion 1(b), 7); the Gram-determinant evaluation does not (F3) and is the negative control. Invalid k, or a set with a zero or non-finite column, never returns a finite number (criterion 8).
2. Frame check for k columns. A supplied initial frame is accepted iff GALI_k(0) >= 10 B_meas(T, k), else a numerical health error of kind initial frame (as sali Algorithm item 1 and Amendment D67 item 1; the caller runs it before the stream). For k = 2 this and the sali rule agree up to the factor 1.0013 of B4. The seeded orthonormal frame has GALI_k(0) = 1.
3. Derived series on a 2D map (k = d = 2). From the sali output at each retained handoff: the log form ln g(n) = L(n) (a caller with a non-orthonormal frame adds ln abs(det W_0)); the plain value g(n) = exp(L(n)) clipped to 1, reported where it is representable (exp(L) underflows Float64 at L about -745, n of the order of 300 steps in a chaotic case); the direct-derived value g from SALI(n) by B4. Neither form is replaced by a placeholder; a display of log10 g from the plain value uses max(g, B_meas(T, 2)) and says so (as sali Representation).
4. Parameters recorded per run: those of the sali run (tau, element type, state mode, seed, frame source, B_meas), plus which form (log-derived or direct-derived) a reported g came from.

## Invariants

- I1 Range and algebra (B3): 0 <= GALI_k <= 1 within B_meas; sign, permutation and orthogonal-map invariance; nesting GALI_{k+1} <= GALI_k within 2 B_meas.
- I2 k = 2 equivalence (B4): g = SALI sqrt(4 - SALI^2)/2 and SALI/sqrt 2 <= g <= SALI, each within 2 B_meas.
- I3 Determinant identity (B5): GALI_d(n) = abs(det W_0) exp(-sum S_i(n)) for symplectic tangent products; it fails for k < d.
- I4 Transparency: g(n) is independent of tau in exact arithmetic (B1; sali I1).
- I5 Floor (B9, B10): no value below B_meas is reported as resolved from the direct form; the log form is resolved to any depth within B_L.
- I6 The orbit is unchanged and no state is added (the series is a pointwise function of the sali output): orbit independence and execution invariance are those of sali (I3, I7).
- I7 The log-derived series never reports 0 or a non-finite value where the direct SALI is exactly 0 (sali A16 concerns the direct form only).

## Compute

Policy `_config/architecture.md`, "Compute" (D17, D25). Under the recommended option M4 adds no kernel and no state: the 2D-map series is a pointwise function (an exponential, a square root) of the sali reducer output, so memory per orbit is the sali formula with 0 bytes added, the CPU-GPU behaviour is that of sali criterion 18 (Float64 only; Double64 falls back with the recorded reason "kernel does not compile for the element type"), and CI has no GPU. The evaluation for general d and k is a CPU function on small dense matrices (d x k transient entries, O(k^2) extra); it is not part of a kernel in M4. For M5 (not decided here, P7): a minors or wedge evaluation is kernel-friendly for small fixed k, a singular-value evaluation is a dense factorization and would resolve the chain to the CPU under the existing reason "a reducer in the chain that is CPU-only".

## Oracle

Package suite (analytic, invariant, cross-method, self-contained; D21): the closed forms B8 in BigFloat(256); the three equivalent evaluations of B2 in BigFloat(256) against each other and against the standard-library singular values (independent code paths); closed forms for prescribed Gram matrices (criterion 2); products of constructed symplectic matrices for B5; the B4 algebra against the sali difference-norm evaluation; the BigFloat reference of sali A15.

Verification environment `verify/`, driven from stage 04 (D21, D27): ChaosTools 3.5.4 `gali`, k = 2, with the behaviours recorded in sali Oracle (1) to (5) and confirmed in the sali stage 04 report ("P8 confirmations"): (1) it steps a tangent system, normalises each column every step and records the product of the singular values, which for k = d = 2 is abs(det) of the unit pair, i.e. sin theta, the quantity g of B8; (2) the default `threshold = 1e-12` stops a chaotic run after 9 to 14 steps, so the threshold must be 0; (3) a restart with an explicit initial matrix stores it, so the seeded frame can be supplied (`gali` value at step 1 matches our exp(L(1)) to 6.7e-16); (4) with a hand-coded Jacobian and the lifted rule the oracle orbit is bitwise the Chaoslab orbit (0 differences in 202400 steps); (5) the oracle is blind below about 1e-15 (values 0 to 0.206, median 1.1e-16, at n = 30, K = 5), so below the floor the closed forms B8 and the BigFloat reference are the oracles. ChaosTools has no standalone function of an arbitrary vector set and Systems has no 4D system, so a stream oracle for k > 2 does not exist in M4 (P8). Independent analytic oracles named: B8 (sali A10 to A13 in g form), the Gram closed forms of criterion 2, the k = d identity on constructed symplectic products.

Loose sanity lines (reported, never pass/fail, K18): ln g(n) = L(n) has the slope -2 lambda_1 (B6), so the sali sanity rates apply unchanged (2.33, 1.92, 3.25 against 2 ln(K/2) = 2.29, 1.83, 3.22 at K = 2 pi, 5, 10, measured in sali stage 04); the regular slope of ln g against ln n is -2 (B7; measured -2.19 to -1.90).

Drafting checks (not sources, not citable; throwaway Python scripts in the session scratchpad, never in the repo; Float64 unless stated; to be reproduced at stage 02/04): (a) the three evaluations of B2 agree to 2.6e-14 absolute on 1200 random unit sets (d, k) in {(2,2), (3,2), (4,3), (6,4), (8,3), (4,4)} (the largest difference is not attributed to one route); (b) k = 2 in d = 4, random orthogonal rotation, theta = 10^-m: relative error exceeds 50 percent at m = 9 (median, range 8 to 9) for the Gram route, m = 16 (16 to 18) for the singular-value route, m = 17 (16 to 19) for the minors route; B9 predicts the lower bound 14.75; (c) B5 on products of 6 random symplectic matrices, random orthonormal W_0, relative difference 2.8e-16, 1.1e-14, 1.5e-13 for d = 2, 4, 6; the same formula used for the first 2 columns of d = 4 and 6 is off by factors 44 and 930; (d) nesting GALI_{k+1} <= GALI_k: 0 violations in 2000 random 5 x 5 sets for k = 2..5; (e) k = 3, equal pairwise cosine c, embedded by a Cholesky factor: product of singular values equals sqrt((1 + 2c)(1 - c)^2) to 2e-16 relative for c = 0, 0.5, -0.4, 0.9 and to 9e-14 relative at c = 1 - 1e-4; (f) threshold map factors as in B4.

## Acceptance criteria

Tags: (S) package suite, (V) verification environment, (G) local GPU. T in {Float64, Double64} unless stated; "exact" = BigFloat(256) evaluation of the same (already rounded) input vectors, for which the three evaluations of B2 coincide; B_meas(T, k) = 2 k eps(T) (B9); B_L, B_SALI, B_g, Psi_n^(i), D_orb as in B10, B11 and sali; starts, seeds, orbit ids, the K panel and the regular class as sali (L1 S7); tau = 1 unless stated. Multipliers of B_meas are proposals (P2); stage 04 reports the realized ratios. Items tagged [k>2] are removed together if P1b is answered no.

1. (S) Evaluation accuracy. Random sets of (d, k) in {(2,2), (3,2), (4,2), (8,2)} and [k>2] {(4,3), (4,4), (6,3), (8,5)}, 1000 sets per pair and type, raw column norms spread over 10^-3 to 10^3: (a) in BigFloat(256) the three evaluations of B2 agree to relative 1e-60; (b) abs(GALI_T - exact) <= 2 B_meas(T, k); (c) negative control: a test double that skips the normalisation fails (b), and for k = d = 2 a double returning the product of the norms fails (b).

Unit-diagonal Gram matrices G, vectors built in BigFloat(256) from a Cholesky factor, embedded in d in {k, 4, 8} by a random orthogonal map, rounded to T; GALI_k = sqrt(det G); pass: abs(GALI_T - closed form) <= 3 B_meas(T, k) (the rounding of the inputs adds one B_meas).
