# Spec: lyap-two-trajectory

Library layer: Lyapunov (`_config/architecture.md`, "Module map" row Lyapunov). Branch m2-p1-modules. Status: approved at the Batch B 01-spec checkpoint (D30). Float32 is out of M2 (decision D24). Shared definitions (conventions and symbols S1, identical orbit S2, rounding bound S3, cross-method relations S4, statistical rule S5, CPU-vs-GPU pointer S6, panel and starts S7, retained outputs S8, items E8 to E14) are in `lyap-benettin-spec.md`; they are cited as "L1 S3", "L1 E12" and so on and not repeated. Renamed symbols of the earlier draft: M is M_state (L1 S1); tau_max(d0) is tau_valid(d0), to keep it apart from the tangent-core tau_max (overflow bound on tau). Spec-local open points are P1 to P4; the owner's answers to the Batch B review are decision D30, cited as (D30). Double64 uses the effective epsilon 2^-100 (precision spec, Amendments).

## Scope

- Catalog row L2 (`_config/catalogs/lyapunov.md`, section A): approximate maximal exponent from the separation of a second ("shadow") orbit that is periodically brought back to a fixed distance d0 from the reference orbit. No tangent map is used. Milestone row M2 of `_config/build-order.md`. The catalog names three issues: perturbation too large (nonlinear saturation), too small (round-off), wrapped vs lifted coordinates. All three are criteria below.
- Prerequisites (Batch A, stage 04 reports in `workspaces/module-build/stages/04-verify/output/`): standard-map (forward step, wrapped system with counts), tangent-core (stream, seeding, health, memory formula, Amendment D28), precision (element types, per-step rounding model, Equations item 3). Sibling: lyap-benettin (L1), the pathwise comparator.
- Out of scope: threshold-triggered rescaling (the oracle's schedule, see Oracle), systems without periodic coordinates, flows (M5), second and higher exponents (the shadow orbit gives one direction).
- Keys: no `numerics-defaults.toml` key is proposed. `_config/numerics-policy.md` says the perturbation size is swept, not fixed. d0 and tau are recorded run parameters; the sweep grids proposed in Algorithm are for the study's preregistration.
- Contract question for the owner (P1, (D30)): the tangent-core stream requires 1 <= k <= d and lets a reducer replace only the deviation matrix; L2 has no tangent and must hold and reset a second orbit. Candidates: (a) amend the stream so a reducer may own extra state components and reset them at a handoff (the state is already allowed to be longer than the tangent dimension, D28), with the shadow orbit as the extra components of a paired system of state length 2s, carrying orbit 1's tangent so L1 and L2 run on one stream; (b) a separate per-orbit loop for L2 with the same backend, seeding, health, provenance rules. Either way criterion 5 (reference orbit bitwise equal to the stream orbit) must hold. This spec writes its criteria for the recommended default (b) and does not decide for the owner (D30); criterion 5 holds either way.

## Algorithm

Per orbit (ensemble member, orbit id j, run seed s):
1. Reference orbit: the tangent-core orbit (L1 S2). Direction u_0: the first seeded unit deviation vector of the stream for (s, j). Shadow start: reference + d0 u_0 on the lifted coordinates (in wrapped mode reduce, and set the winding counts so that the lifted separation is exactly the minimal-image one, T3). Compute d_0^+ from the stored states; if it is zero, not finite, or outside [d0/2, 2 d0], reject the run before any work with a numerical health error of kind separation (d0 is not resolved at this point and element type).
2. Advance both orbits tau map steps (same map, same element type, no tangent).
3. At the handoff: delta = minimal-image difference (T3); d = Euclidean norm, evaluated without overflow or underflow as in L1 Algorithm step 1. If d is zero or not finite, raise a numerical health error of kind separation, with orbit id and handoff step. Add ln(d / d_prev^+) to the compensated sum (tangent-core spec, Accumulated logarithms). Reset the shadow (T2), recompute d^+ from the stored states, set d_prev^+ = d^+.
4. Emit X2(j tau) = sum / (j tau) at every handoff (L1 S8).

Parameters recorded per run: d0, tau, element type, state mode, seed. Proposed sweep grids for a study (preregistered there): Float64 d0 = 10^-m, m = 3..12; Double64 m = 3..28; tau in {1, 2, 4, 8} within tau_valid(d0) (T6). K = 5, tau = 1: tau_valid(1e-8) = 7. The grids must bracket d0* (T8). The sweep is part of the experiment; the module accepts any d0 and reports X2.

## Invariants

- I1 The reference orbit is bitwise the stream's orbit (L1 S2), so L1 and L2 share one orbit.
- I2 After every reset the realized separation is within [d0/2, 2 d0] or the run has failed with a health error.
- I3 Every coordinate of delta lies in (-pi, pi]; in wrapped mode the lifted separation equals the minimal-image one (T3).
- I4 Linear maps: X2 does not depend on d0 beyond rounding (T9).
- I5 Every term of the sum is at most ln(pi sqrt 2 / d_prev^+) (T7).
- I6 Orbit independence and thread, chunk invariance (L1 I4); the hot loop allocates nothing after warm-up (BigFloat excepted).

## Compute

Policy `_config/architecture.md`, "Compute" (D17, D25). Data-parallel over orbits, one kernel for CPU and GPU, no dense factorization, so no "CPU-only reducer" fallback. Two orbits advance per member: about the same work as the tangent stream (two sines instead of one sine and one cosine plus a matrix-vector product), no deviation matrix. Memory per orbit (derived, structure-of-arrays): sizeof(T)(2s + 3) + 16 bytes (reference state, shadow state, running sum, compensation term, previous realized separation; step index and orbit id); s = 2 Float64: 72 bytes, s = 4 Float64: 104 bytes, s = 2 Double64: 128 bytes. Chunk size from free memory as in the tangent-core spec (Compute). GPU candidate for Float64 and Double64 (isbits); BigFloat CPU-only with the reason "kernel does not compile for the element type" on a GPU request; GTX 1050, cc 6.1, weak Float64 (K15). CPU-vs-GPU agreement: tangent-core AC12 via L1 S6, on X2 never on trajectories (K16). CI has no GPU: CPU backend. The shadow reset needs a reducer-owned state reset inside the kernel (see Scope, P1).

## Oracle

Package suite (analytic, invariant, cross-method, self-contained; D21): linear-map and fixed-point closed forms (T9, L1 E10 to E13), the minimal-image control, pathwise comparison with L1 on the identical orbit, the d0 and tau sweeps, Double64, health, invariance. BigFloat(256) products at the realized points, as L1 S3.

Verification environment `verify/`, driven from stage 04 (D21, D27): ChaosTools `lyapunov` (installed source read 2026-10-13, `ChaosTools/src/chaosdetection/lyapunovs/lyapunov.jl`): two neighboring orbits, rescaling of the test orbit only when the distance leaves [d0_lower, d0_upper] = [1e-3 d0, 1e3 d0] (defaults d0 = 1e-9), test state started at u1 + d0/sqrt(D) in every coordinate unless an `inittest` function is given, the exponent being the sum of ln(d/d0) over rescalings divided by the elapsed time. Consequences for the comparison. (i) Its schedule is threshold-triggered and ours periodic, and its default start direction is the diagonal, so the comparison is at ensemble level (L1 S5), not pathwise; an `inittest` along the seeded u_0 aligns the start direction. (ii) Its distance is the plain coordinate difference, so the oracle system must be defined on lifted coordinates (no wrap); with the wrap rule used in the standard-map oracle, pairs that straddle a boundary inject the artifact of T3 (recorded line R2). (iii) On lifted coordinates a regular orbit reaches coordinate magnitude about n p (3e5 at n = 1e5), where the resolution is about 3e-11, so the oracle default d0 = 1e-9 gives a 3 percent noise level per step and a second-order bias of about 5e-4 in the exponent, above the 1e-4 of criterion 13; both sides use d0 = 1e-6 in criteria 13 to 15 (noise level 3e-5 per step, bias about 5e-10; the first-order worst case E_ro at M_state = 3e5 is 6e-4 but the rounding signs are random, so the realized value is smaller by about 1/sqrt(n)). Chaoslab side: Delta_2T(1e-6) = 1.5e-6 at K = 0.5, M = 2 pi. Also in `verify/`: the GPU comparison. Loose sanity lines (reported, never pass/fail, K18): the benchmarks rows used in L1 Oracle, applied to X2 at the Delta_min grid point.

## Acceptance criteria

Tags (S) package suite, (V) verification environment, (G) local GPU. B_S, "ref", starts and seeds as in L1 (S3, S7); Delta_2T, E_nl, E_ro, T5 to T8 as above, with M_state = max(1, abs(K), 2 pi) in wrapped mode and the measured M_state in lifted mode, eps of the element type; "X" is the L1 series on the identical orbit and direction; tau = 1 unless stated.

1. (S) Linear map at the origin: Y5 map A = [[2,1],[1,1]], start 0, shadow at d0 u_0 with u_0 = (1, 0) and d0 = 2^-20, tau in {1, 5, 10}, n in {20, 100, 1e3}, T both. Pass: |n X2(n) - ln(norm of A^n u_0)_ref| <= B_S(n).
2. (S) K = 0 shear at the origin (T9, L1 E11): seeded unit u_0 = (a, b), d0 in {2^-20, 1e-9}, tau in {1, 10}, n in {10, 100, 1e4}: |n X2(n) - ln sqrt((a + n b)^2 + b^2)| <= B_S(n).
3. (S) Hyperbolic fixed point (0, 0), K in {1, 2, 6}, d0 in {1e-6, 1e-9}, tau = 1, 100 seeded u_0, n in {20, 100, 1e3}: |n X2(n) - [n ln mu_+ + ln(abs(c_1) norm(v_u))]| <= B_S(n) + 2 n E_nl(d0) (L1 E12; the true nonlinearity at the origin is cubic, the bound is the general T5 one).
4. (S) Minimal image (T3): wrapped state, K = 0, p = 0, d0 = 2^-20. Orbit fixed, delta stays (d0, 0), so n X2 = 0 in exact arithmetic. Pass: for a pair straddling the boundary (reference x = 2 pi - d0/2 built in T, shadow across x = 0) and for the same pair placed at x = 1: |X2(n)| <= 2 E_ro(d0) for n in {1, 10, 100}, and the two results differ by at most 2 E_ro(d0). Negative control: a test double that takes the plain wrapped difference gives |n X2| >= 10 at n = 1 for the straddling pair (ln(2 pi / d0) = 15.7), so the criterion discriminates. Mirror case: reference p = 2 pi - d0/2 built in T, shadow across p = 0 (mod 2 pi), K = 0, u_0 = (0, 1): |n X2(n) - ln sqrt(n^2 + 1)| <= B_S(n) + 2 n E_ro(d0) for n in {1, 10, 100} (L1 E11 with a = 0, b = 1).
5. (S) Identical reference orbit: reference orbit points bitwise equal to the stream orbit and to the orbit of an L1 run (L1 S2) at every handoff, K in {0.5, 2 pi}, 100 starts, n = 1e3, tau in {1, 4}, T both.
6. (S) Pathwise agreement with L1: K in {0.5 (regular class, S7 screening), 2, 5, 2 pi}, 50 starts each, Float64, wrapped mode, tau = 1, d0 = 10^-m, m = 3..12, n in {100, 1e3}, and 1e4 for K = 0.5. Pass: |X2(n) - X(n)| <= Delta_2T(d0) + B_S^L1(n)/n whenever the validity limits of T5 hold; points outside the limits are reported, not dropped. The realized ratio |X2 - X| / Delta_2T per d0 is reported.
7. (S) U-shape (the catalog's "too large / too small"): Float64, K = 5, wrapped, 200 starts, n = 1e3, m = 2..13. Let e(m) be the median over starts of |X2 - X|. Pass: (a) least-squares slope of log10 e against log10 d0 over m in {2, 3, 4} lies in [0.8, 2.2] (E_nl is linear in d0; averaging over sin x can raise it to 2); (b) over m in {10, 11, 12, 13} the slope lies in [-1.3, -0.7] (E_ro proportional to 1/d0); (c) the grid minimum lies at d0 in [d0*/100, 100 d0*] with d0* from T8 and its value is at most Delta_2T(d0*). Loose, proposal (K18).
8. (S) Double64, K = 5 and 2 pi, 50 starts, n = 1e3, d0 = 10^-m, m = 3..28: criterion 6 with eps = 2^-100. Plus: at K = 5 the grid-minimum error is at most 1e-9 and at least 1e3 times smaller than the Float64 grid minimum of criterion 7 (T8 predicts the ratio sqrt(2^-52 / 2^-100) = 1.7e7).
