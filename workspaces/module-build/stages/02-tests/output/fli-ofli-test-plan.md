## API proposal for stage 03

Added to the existing layer `Chaoslab.Indicators` (`src/Indicators/`), next to SALI; `using Chaoslab` is enough (the re-export loop in `src/Chaoslab.jl` picks up new exports). Same reducer protocol as `SALI` (`reducer_init`, `reducer_step`, `reducer_update`, `reducer_final`, `reducer_failed`, `reducer_error`, `reducer_provenance` of `Chaoslab.Tangent`); the scaled norm is `safe_norm` of Foundation (D69), the sums are `CompensatedSum`/`add`/`total`, with the same operations as `SALI` and `Benettin`, so the sums are bitwise equal to theirs (sali I8). Names the tests use:

| Name | Signature and meaning |
|------|----------------------|
| `FLI(; replace = true)` | reducer for `propagate` with `k = 2`; `reducer_init(FLI(), T, Val(d), Val(k))` throws `ArgumentError` with message `"FLI needs k = 2, got k = $k"` for `k != 2` (as `SALI`). Isbits reducer and state (GPU-compatible). `replace` is the chain position of the one-replacer rule (D71): `FLI()` is the replacer (alone in a chain, or last), `FLI(replace = false)` reads the arriving columns and leaves `W` untouched, for a chain in which a later reducer (SALI) replaces them. The reducer cannot see the chain, so the flag is the caller's (Experiments) and no test can check that a chain obeys the rule; the tests check what each position does (AC13). |
| `reducer_step(FLI(), st, n, x, W)` | at the handoff: scaled norms `alpha_i` of the two arriving (unnormalised) columns; if `alpha_i` is zero or non-finite, record the failure (kind `"deviation matrix"`, the failing `column` 1 or 2, value, handoff step) in the state, leave sums, maxima and `W` unchanged, no throw; else add `log(alpha_i)` to the compensated sums `S_1`, `S_2`, set `FLI_1 = max(FLI_1, S_1)` and `FLI_B = max(FLI_B, S_1, S_2)` (S_i = `sum[i] + comp[i]`, both maxima start at 0, the s = 0 term, P4), record the handoff step and column of the last strict increase of each maximum, and return `W` replaced by the column-normalised matrix when `replace` (the same `c / alpha` operations as `SALI`) or unchanged when not. |
| `reducer_update`, `reducer_failed`, `reducer_error` | as `SALI`: `reducer_update` throws `reducer_error(r, st, 0, :cpu)`; `reducer_error(r, st, orbit, backend)` is `NumericalHealthError("deviation matrix", value, threshold, step, orbit, backend, column)` with `column` 1 or 2 (0 for non-finite entries caught by the stream). |
| `reducer_final(FLI(), st)` | `(n, fli, fli1, sum, comp, stepB, colB, step1)`: `n` last successful handoff; `fli::T` = FLI_B(n) (log form, both columns, the primary); `fli1::T` = FLI_1(n) (log form, first column); `sum`, `comp` `SVector{2,T}` the compensated sums S_1, S_2 and their compensation terms; `stepB`, `colB` the handoff step (0 = the s = 0 term) and column (1 or 2; 0 with step 0) at which FLI_B last strictly increased, `step1` the same for FLI_1 (column 1). These are the maximisers of Q11. At `n = 0` everything is zero. |
| `reducer_provenance(FLI())` | `(indicator = "fli",)`, merged into the `propagate` run record next to `tau`, `k`, `precision`. |
| `check_frame(FLI(), W0; orbit = 0)` | frame check of Algorithm item 1, run by the caller before the stream (sali Amendment D67 form): both columns must be unit vectors to roundoff (the convention S(0) = 0); returns the larger norm defect `max_i abs(norm(w_i) - 1)` (type `T`) or throws `NumericalHealthError("initial frame", defect, threshold, 0, orbit, :cpu, column)` with the offending column; `ArgumentError` if the frame does not have 2 columns. Independence and orthogonality are not checked (FLI does not need them; the caller reports orthonormality). The threshold constant is not fixed by the spec (Deviations item 7): the tests accept a defect of at most 2 eps and reject 1000 eps and more; the proposal is 8 eps. |
| `fli_unlogged(F)` | the display conversion of the log form: `exp(F)` in the type of `F` when it is finite, `nothing` when the exponential overflows (above 709.78 in Float64); never an infinity (spec, Representation; criterion 11(d)). |

Series are read as in the Lyapunov and sali suites: the stream has no emission channel (L1 Q9), so the tests wrap `FLI()` (and the other reducers of a chain) in a probe reducer (`fl_Probe`, test side) that records `reducer_final` at chosen handoffs, and run it through `propagate_orbit`; the kernel path (`propagate`) is used in AC12, AC13b and the record test.

## Conventions

Element types Float64 and Double64 (D24), BigFloat(256) in AC11 (b), (c); tolerances in units of `effective_eps(T)` (Float64 eps, Double64 2^-100). Reference: BigFloat(256) products `Y_n w_i(0)` at the realized orbit points (`fl_ref_steps`: the squared norms `q_i(n)` and the squared Frobenius norm of `Y_n`; no logarithm per step, because the running maximum of `ln` is `ln` of the running maximum, Q3), the running maxima over the handoffs of tau with the s = 0 term (`fl_ref_at`), and `F_*` of Q7 from the largest squared Frobenius norm over the handoffs. `B_FLI` is the two-point rule of Q11: `8 eps max(Psi_{j_a}^(i_a), Psi_{j_b}^(i_b))`, the computed maximiser `(i_a, j_a)` from the reducer final and the reference maximiser `(i_b, j_b)` from the BigFloat series, `Psi` the `lb_Psi` of `test/lyap-benettin/lb_psi.jl` (L1 Amendment D35, evaluated in Float64 from the stored tangents; zero for the s = 0 term). The K = 0.5 regular class has the same ids, starts and screening seed as `lb_regular()` (L1 S7: X(1e5) <= 5e-4, seed 20261012 + 21070).

The suite includes only `lb_psi.jl` of the lyap-benettin folder, behind the `LB_PSI_LOADED` guard. `lb_helpers.jl` cannot be included from here: `test/fli-ofli` sorts before `test/lyap-benettin`, whose `runtests.jl` includes `lb_helpers.jl` unguarded, and a second include would redefine its constants. So `fl_regular` (the S7 screening) and `fl_rho_M` (rho_j and M_state for AC14) are copies of `lb_regular` and `lb_ref_full`, and must follow them if those change.

Missing-module behaviour: every testset starts with a line `_ = (FLI, ...)` naming the `Chaoslab.Indicators` symbols it uses, so without the module the testset errors on its first statement (UndefVarError) and nothing else; no top-level code and no helper calls an Indicators name at include time.

Seeds (base 20261012 + 33000 = 20294012, distinct from sali 31000, lyap-benettin 21000; `fl_seed(ac, sub) = base + 50 ac + sub`; `StableRNG` throughout): shared panel starts and frames `fl_seed(0, 1..3)` = 20294013 (K = 2 pi), 20294014 (K = 10), 20294015 (K = 5); K = 0.5 regular class: lyap-benettin screening seed 20282082 (ids and frames); AC2 20294112 (start draws, frames); AC3 20294162; AC4 20294212; AC5 20294262; AC9b 20294463, 20294464, 20294465 (K = 2 pi, 5, 10; starts and frames); AC12 20294613 to 20294618 (sub 1 to 6); AC13a 20294662 (+1 for the starts: 20294663); AC13b 20294672 (+2: 20294674); AC13c 20294682; AC14 20294712 (dyadic starts); API prefix invariance 20294782. Frames are `initial_deviations(seed, orbit, Val(2), Val(2), T)`, the first two seeded columns. AC1 and AC11 (a)-(c) draw nothing beyond the shared panel.

Runtime (D38, 3 minute ceiling): the package suite runs the sizes of the spec except where marked: the chaotic classes of AC6/AC7/AC10 run to n = 1e4 for 20 starts in both types; the checkpoints are 10 per decade (n = 10, 20, ..., 100, 200, ..., 1e4) instead of every multiple of 10 (the Psi sum costs O(n) per checkpoint); AC2 runs n = 1e6 for Float64 only (3 seeded starts and the identity; Double64 sin and cos at |x| about 1e6 cost 10 us per step); AC5(b) samples n in 1..100 and every 10th up to 1000. `verify/fli-ofli.jl` (stage 04) sets `FL_FULL_RUN = true` before including `runtests.jl` for every multiple of 10. Measured against the throwaway stub below: 47 to 51 s wall for the whole suite on 2 threads including compilation (263 533 passes, 27 testsets); the real module adds the first compile of the kernel path for two chains, so the expected package runtime is 1 to 2 minutes.

## Deviations and spec items not testable as written

Resolved by the owner at the stage 02 checkpoint, 2026-10-22: all eight items as proposed, recorded as spec Amendment D72.

All are proposals for the stage 02 checkpoint; none changes a criterion that could fail on a correct implementation, except where marked.

1. The one-replacer rule cannot be enforced inside a reducer (it does not see the chain) and its violation is not detectable from the output. The API carries the position as `FLI(replace = false)`. Tested: what each position does (AC13a/b, AC8, AC12), not that a chain obeys the rule. The run record cannot name FLI in a two-reducer chain: `reducer_provenance` is merged with later reducers winning a shared key (D34 A2), so the record of {FLI, SALI} says `indicator = "sali"`. Criterion 12(e) is therefore tested on {FLI} alone; chain position and frame source are recorded by Experiments (as sali D67 item 2). Proposal: a second provenance key (for example `chain = "fli,sali"`) written by Experiments, no change here.
2. Criterion 3 with the supplied unit frames abs(c_1) = 1e-3 and 1e-6 cannot hold with `B_S(n) = 8 eps (n + G_first)`: the first-order error of a start almost along the contracting direction is amplified by about 1/abs(c_1) (L1 P6, Q11 "constants borrowed"). Measured against the throwaway stub, the largest error / B_S is 0.001 to 0.09 for every seeded frame of criteria 3 to 5 (Float64 and Double64), 0.076 and 0.0026 for abs(c_1) = 1e-3, and 21.1 (Float64) and 6.6 (Double64) for abs(c_1) = 1e-6, while error / (8 eps Psi_n) stays below 0.08. The test uses `max(B_S(n), 8 eps Psi_n^(i))` (the per-vector form of L1 Amendment D35, which Q11 uses for the standard map) for the two supplied frames only, and the plain `B_S` for everything else. Spec change proposed: state this in criterion 3.
3. Criterion 1 (i): "FLI_1 = 0 until the sum turns positive at j = 17" holds for the real number -0.3; the test map stores `c_m` as Float64, and ten times the Float64 value of -0.3 plus six times 0.5 is +1.1e-16 at j = 16, which is not inside B_S for Double64. The test asserts FLI_1 <= B_S for j <= 15 and the exact running maxima (BigFloat of the stored `c_m`) for all j. "FLI_B = 3 from j = 10 until then" is read as through j = 22 (the running maximum of abs(S_1) of the partial sums), which is what the exact comparison checks.
4. Criterion 5(b): the closed form of Q9e, `FLI_1(n) = max(0, ln norm(M w_1(0)))`, ignores that the stored frame has norm 1 + O(eps), so S(n) at even n is `ln norm(w_i(0))`, of order eps, not 0. The reference includes these terms (the helper check of the closed form uses them); the effect is far inside B_S. Not a spec change.
5. Maximiser convention (Algorithm item 3, Q11): "the handoff and column at which each was last attained" does not say what happens for ties. The tests pin only: the value at the recorded (step, column) is the maximum, bitwise; a strict increase at a handoff makes that handoff the maximiser; step 0 means the s = 0 term. Ties are untested. Proposal for the spec: record the handoff of the last strict increase (the strict `>` update), column 1 before column 2.
6. Criterion 13(c) "1 versus N threads" needs separate processes (the thread count of a running Julia cannot change). The package test compares `propagate` (the run's threads, 2 under `Pkg.test`) with the serial `propagate_orbit` map for chunk 64 and 1000, 4096 orbits, as sali criterion 14(b); the explicit thread counts 1, 2, 4 in child processes with output hashes are a stage 04 (V) check, as in sali stage 04.
7. Criterion 12(c): the spec requires "unit vectors" without a tolerance. The tests reject a column of norm 2, 3, 0 or 1 + 1000 eps and accept 1 and 1 + eps, with the defect returned at most 2 eps; the threshold itself (proposal 8 eps) is left to stage 03 and may be anything between. The frame check does not test independence, so an identical pair of unit columns is accepted (the SALI check rejects it): FLI of a dependent pair is defined (FLI_B = FLI_1).
8. Criterion 9(a): the transient detector "FLI_B below ln n at n = 1e4" is not a transient detector. FLI_B = ln(n c) with c below 1 whenever the orthonormal frame has no component of modulus 1 across the invariant curve or the twist is below 1: 8 of 20 regular-class starts are below ln n at n = 1e4 with slope 1.00 to 1.03 over [1e4, 1e6], so the rule "at most 20 percent excluded" fails for a correct implementation. The test defines a transient start by a slope outside [0.7, 1.3] over the first decade [1e4, 1e5], reports the count of starts below ln n, and keeps the 80 percent rule. Spec change proposed: replace the detector.
9. Criterion 9(b)/(c): the allowance 4/180 is about ten times the realized difference on the stub (mean window slope minus mean X: 0.0022 at K = 2 pi, 0.00004 at K = 5, 0.0030 at K = 10; the combined standard errors are of the same order), so the test is loose by design (K18); stage 04 reports the realized values and the interval may be tightened to the sali 2/180.
10. Criterion 8(a) is tested as bitwise equality of the totals `sum + comp` and, separately, of `sum` and `comp` (the same operations in the same order, sali I8), against the sali reducer and against the L1 sums of k = 1 runs from the first and from the second seeded column (I6); sali AC9 used a tolerance because it tested before the bitwise identity was measured. The stub, written with the same operations, passes it, and sali stage 04 measured the identity.
11.
