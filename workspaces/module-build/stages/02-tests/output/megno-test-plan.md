## API proposal for stage 03

Added to the existing layer `Chaoslab.Indicators` (`src/Indicators/`), next to SALI and FLI; `using Chaoslab` is enough (the re-export loop in `src/Chaoslab.jl` picks up new exports). Same reducer protocol as `FLI` and `SALI` (`reducer_init`, `reducer_step`, `reducer_update`, `reducer_final`, `reducer_failed`, `reducer_error`, `reducer_provenance` of `Chaoslab.Tangent`); the scaled norm is `safe_norm` of Foundation (D69), the log sums are `CompensatedSum`/`add`/`total` with the same operations as `SALI`, `FLI` and `Benettin`, so the sums are bitwise equal to theirs (sali I8, fli I6). Names the tests use:

| Name | Signature and meaning |
|------|----------------------|
| `MEGNO(; replace = true)` | reducer for `propagate` with `k = 2`; `reducer_init(MEGNO(), T, Val(d), Val(k))` throws `ArgumentError` with message `"MEGNO needs k = 2, got k = $k"` for `k != 2`. Isbits reducer and state (GPU-compatible). `replace` is the chain position of the one-replacer rule (D71, D72): `MEGNO()` is the replacer (alone in a chain, or last), `MEGNO(replace = false)` reads the arriving columns and leaves `W` untouched, for a chain in which a later reducer (SALI) replaces them. Valid chains: `{MEGNO}`, `{MEGNO(false), SALI}`, `{FLI(false), MEGNO(false), SALI}`, `{MEGNO(false), FLI(false), SALI}`. The reducer cannot see the chain, so no test can check that a chain obeys the rule; the tests check what each position does (AC7, AC12). |
| `reducer_step(MEGNO(), st, n, x, W)` | at the handoff `n = K tau` (K counted by the reducer, so `tau = n / K`): scaled norms `alpha_i` of the two arriving (unnormalised) columns; if `alpha_i` is zero or non-finite, record the failure (kind `"deviation matrix"`, the failing `column` 1 or 2, value, handoff step) in the state, leave every sum, series and `W` unchanged, no throw; else per column `a = log(alpha_i)`, add `a` to the compensated log sum `s_i`, then (spec Algorithm item 2, M5) `R1 += n a`, `R2 += n^2 a` (weights formed in the element type), `Y = 2 R1 / n`, `Q += Y`, `Ybar = Q / K`, `Y20 = 3 R2`, `Q2 += Y20`, `Ybar20 = tau Q2 / n^3`; return `W` replaced by the column-normalised matrix when `replace` (the same `c / alpha` operations as `SALI`) or unchanged when not. The equivalent Abel forms of M6 may be used inside; the final fields below fix the observable meaning. |
| `reducer_update`, `reducer_failed`, `reducer_error` | as `FLI`: `reducer_update` throws `reducer_error(r, st, 0, :cpu)`; `reducer_error(r, st, orbit, backend)` is `NumericalHealthError("deviation matrix", value, threshold, step, orbit, backend, column)` with `column` 1 or 2 (0 for non-finite entries caught by the stream). A failed state stays failed and unchanged. |
| `reducer_final(MEGNO(), st)` | `(n, handoffs, Y, Ybar, Ybar20, sum, comp, R1, R2, Q, Q2)`: `n` the last successful handoff (map step), `handoffs = K`; `Y`, `Ybar`, `Ybar20` `SVector{2,T}` (column 1 primary): Y(n) = Y_(1,-1), Ybar_(1,-1)(n) and Ybar_(2,0)(n) of M5; `sum`, `comp` the compensated log sums s_1, s_2 and their compensation terms (bitwise those of L1, SALI, FLI); `R1`, `R2`, `Q`, `Q2` `SVector{2,T}` totals (sum + compensation) of the weighted sums of Algorithm item 2 (the "auxiliary sums"; `Y20` itself is not delivered). At `n = 0` everything is zero. |
| `reducer_provenance(MEGNO())` | `(indicator = "megno", convention = "weights at the end of the window, mean over the handoffs 1..K")`, merged into the `propagate` run record next to `tau`, `k`, `precision` (the convention tag of the spec, Representation). |
| `check_frame(MEGNO(), W0; orbit = 0)` | frame check of Algorithm item 1, run by the caller before the stream (sali Amendment D67, fli Amendment D72 item 7): both columns unit vectors to roundoff (defect at most 8 eps); returns the larger defect or throws `NumericalHealthError("initial frame", defect, threshold, 0, orbit, :cpu, column)`; `ArgumentError` if the frame does not have 2 columns. Independence and orthogonality are not checked. Tests accept a defect of 2 eps and reject 1000 eps. |

Series are read as in the Lyapunov, sali and fli suites: the stream has no emission channel (L1 Q9), so the tests wrap the reducers of a chain in a probe reducer (`mg_Probe`, test side) that records `reducer_final` at chosen handoffs, and run them through `propagate_orbit`; the kernel path (`propagate`) is used in AC11a/b/e and AC12b.

## Conventions

Element types Float64 and Double64 (D24), BigFloat(256) in AC10 (b), (c); tolerances in units of `effective_eps(T)`. Reference: BigFloat(256) exact sums `s_i(k) = ln(norm(Y_k w_i(0)) / norm(w_i(0)))` at the realized orbit points (`mg_ref_s`; dividing by the norm of the stored frame column makes the convention s(0) = 0 exact for a frame that is unit only to roundoff), then the three series by the weighted-sum form M5 (`mg_M5`, handoff sums `s(k tau)`), kept at the checkpoints. The Abel form M6 (`mg_M6`, recurrences; `mg_Ybar_harmonic`, the harmonic-weight form) is an independent second evaluation: AC1 checks that M5 and M6 agree to 1e-60 on test sequences, AC7(b) and the API test use M6 as the post-processing of stored series. Bounds: `6 B_S(n)` with `B_S = 8 eps (n + G_first)` for constant tangents (coefficient sum of the three series below 6, M11), `B_M(n) = 48 eps Psi_max^(i)(n)` for the standard-map panel, `Psi_max` the maximum of `Psi_g` (`lb_Psi`, L1 Amendment D35, Float64 from the stored tangents) over the checkpoints `g <= n`. The K = 0.5 regular class has the ids, starts and screening of `lb_regular()` (L1 S7: X(1e5) <= 5e-4, seed 20282082).

Helpers of the lyap-benettin folder (`lb_regular`, `lb_Psi`, `lb_tangents`) are used through the guard `@isdefined(lb_regular) || include(".../lb_helpers.jl")` as the sali suite does, not copied: `test/megno` sorts after `test/lyap-benettin`, so under `Pkg.test` they are already loaded (and the K = 0.5 screening is the memoized one), and `verify/megno.jl` including the suite alone loads them itself. fli-ofli sorts before lyap-benettin and had to keep copies; the copies are not needed here. If `lb_helpers.jl` changes its names, `mg_helpers.jl` line 8 and `mg_case` are the two places that follow.

Missing-module behaviour: every testset starts with a line `_ = (MEGNO, ...)` naming the `Chaoslab.Indicators` symbols it uses, so without the module the testset errors on its first statement (UndefVarError) and nothing else; no top-level code and no helper calls an Indicators name at include time. Failure reports are kept short (`mg_nbad`, booleans instead of `all(...)` over rows) so that a failing stage 03 run does not dump orbits.

Seeds (base 20261012 + 35000 = 20296012, distinct from sali 31000, fli 33000, lyap-benettin 21000; `mg_seed(ac, sub) = base + 50 ac + sub`; `StableRNG` throughout): shared panel starts and frames `mg_seed(0, 1..3)` = 20296013 (K = 2 pi), 20296014 (K = 10), 20296015 (K = 5); K = 0.5 regular class: lyap-benettin screening seed 20282082 (ids, starts and frames); AC2 20296112 (start draws, frames); AC3 20296162; AC4 20296212; AC5 20296262; AC8 20296413, 20296414, 20296415 (K = 2 pi, 5, 10; starts and frames), R5 orientations 20296422; AC11 20296563 to 20296568 (sub 1 to 6); AC12a 20296612 (+1 for the starts: 20296613), AC12b 20296622 (+2: 20296624), AC12c 20296632; AC13 20296662 (dyadic starts); API prefix invariance 20296732. ## Deviations and spec items not testable as written

Resolved by the owner at the stage 02 checkpoint, 2026-10-22: all nine items as proposed, recorded as spec Amendment D74; the tests apply items 2 and 3 (exclusion removed, 16 eps).

All are proposals for the stage 02 checkpoint. Items marked (changes the spec) alter a criterion as worded; the others record a reading or a size.

1. (changes the spec) Criterion 3(c) cannot hold as worded. For the supplied frame with abs(c_1) = 1e-3, column 1 starts nearly along the contracting direction, so its s falls first and its Y is negative (exact reference Y_1(4) = -3.07; the module stub gives the same), not above 0.5; "Ybar_(2,0) is below 0.5 of its limit-scale" has no defined limit scale at n = 4. The test asserts what M10(b) implies and the stub confirms: column 1 Y(4) < 0, column 2 (the expanding one) Y(4) > 0.5 (4.81), and that all three series are within the bound of the BigFloat sums; the values are reported. Proposal for the spec: replace 3(c) by this statement.
2. Reference convention. `s_i(k) = ln(norm(Y_k w_i(0)) / norm(w_i(0)))` divides by the norm of the stored frame column, so that s(0) = 0 holds exactly for a seeded frame that is unit to roundoff (the module's sum is exactly that quantity). fli deviation item 4 (a closed form off by O(eps) at AC5(b)) therefore does not arise: the M10(e) closed forms hold for the BigFloat reference to 1e-60.
3. Criterion 1: the "exact forms of M8(a)" are evaluated with lambda the stored Float64 constant as a BigFloat (0.05, 0.1), not the real number 1/20 or 1/10; the printed M7 values 2.05 and 1.05 are asserted to 1e-12 only, the tight comparison is against M5 on the stored values. (ii) uses the exact ratio (m+1)/m as the tangent entry in the element type, so that the closed form with true logarithms holds within 6 B_S in Double64 too. (iii) reads "tending to 0" as abs(Ybar(200)) and abs(Ybar20(200)) <= 0.1 for both columns. (v) runs Float64 only (Double64 at 1e5 with `MG_FULL`); the Int64 control is applied at 4e6 (1e5 cubed, 1e15, fits in 64 bits).
4. Criterion 3 exclusion: applied as worded (ids with abs(c_1) < 0.05 for column 1; 2 of the 100 ids, both types), but the stub shows it is not needed: the largest error / (6 B_S) over all seeded ids, both columns, is 0.019 (Float64) and 0.001 (Double64), the smallest abs(c_1) of any seeded column is 0.0042.
