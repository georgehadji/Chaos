## API proposal for stage 03

One new file `src/Indicators/naff.jl` in the Indicators layer; every name is exported there (the `Chaoslab` re-export loop picks them up, `using Chaoslab` is enough). No change in Tangent, Systems or Foundation is required: the reducer is a reader, its state is isbits with no workspace, and the series path is plain functions. No name collides with an existing export (checked by grep over `src/` and `ext/`; `pair_distance` of the rli run is avoided on purpose). The tests call only the names below; where this section is silent they assume nothing.

### Surface 1: the series path (E1, I12 and I12b), pure functions

| Name | Signature and meaning |
|------|----------------------|
| `window_weights(T, N; order = 1, positions = :half) -> Vector{T}` | the weights `chi_p(t_j)` of NF20 in the Laskar normalisation (sum N), `p = order` in 0:5, `t_j = -1 + (2j+1)/N` for `positions = :half` (sample positions `(j+1/2)/N`) and `-1 + 2j/N` for `:edge` (positions `j/N`), `j = 0..N-1`. Evaluated as `c_p 2^p sin(y)^(2p)` with `y = pi (j+1/2)/N` (or `pi j/N`) and the index mirrored (`min(j, N-1-j)` for `:half`, `min(j, N-j)` for `:edge`), so that the weights are bitwise symmetric and have no cancellation near the ends; `1 + cos` must not be formed (D80b(i) asks for relative accuracy at the end weights). `ArgumentError` naming `order` (outside 0:5) or `positions` (not `:half`, `:edge`). |
| `window_frequency(z; order = 1, positions = :half, pad = 8, mean_removal = false, mirror_ratio = 0.9) -> WindowFrequency{T}` | the fundamental frequency of ONE window `z::AbstractVector{Complex{T}}` of N samples (NF17, NF2): optional subtraction of the window mean; weights as above; coarse search of `|phi|` on the grid `nu_m = -1/2 + m/(pad N)`, `m = 0..pad N - 1` (the transform may be Float64 for any `T`: it only locates the bin), the lowest index among values within the tie tolerance (64 eps of Float64) of the largest wins and sets `tie`; Newton on the stationary point of `|phi|^2` in `[nu_c - 1/M, nu_c + 1/M]` in the element type, `S_m = sum chi_j z_j (-2 pi i j)^m exp(-2 pi i nu j)` with compensated sums and exactly reduced phases (`fma` for the product `nu j`); the result reduced to `[-1/2, 1/2)`. Fields: `nu`, `amplitude = |phi(nu)|/sum(chi)` (NF18), `mirror_amplitude` (`|phi(-nu)|/sum(chi)`, 0 when `-nu` lies within `2(p+1)/N` of `nu` on the circle), `second_ratio` (largest local maximum of the coarse values outside `[nu - 2(p+1)/N, nu + 2(p+1)/N]` over the peak), `bin` (0-based `m` of the coarse maximum), `tie`, `near_zero` (`abs(nu) < (p+1)/N`), `mirror` (`mirror_amplitude > mirror_ratio amplitude`), `refined` (false if no Newton iterate with negative second derivative stayed in the bracket: the coarse value is then kept), `status` (`:ok`, `:degenerate`, `:failed`). `:degenerate`: the series is constant after the optional mean removal and either mean removal is on or the constant is zero (Items 8); `nu`, `amplitude`, `mirror_amplitude`, `second_ratio` are `NaN`. `:failed`: a non-finite sample, same `NaN`s. Arguments are validated before any work: `ArgumentError` naming `window` (length below `8 (p+1)`), `pad` (not positive), `order`, `positions`, `mirror_ratio` (outside (0, 1]). |
| `frequency_map(series, N; order = 1, positions = :half, pad = 8, mean_removal = false, mirror_ratio = 0.9, floor_multiplier = 32) -> FrequencyMap{T}` | the pair `[0, N)`, `[N, 2N)` for one plane (`series::AbstractVector{Complex{T}}`) or several (`series::AbstractVector{<:AbstractVector{Complex{T}}}`, one series per plane); a series longer than `2N` uses its first `2N` samples. Fields: `w1`, `w2` (`Vector{WindowFrequency{T}}`, one per plane), `dist` (per plane, NF9, the smaller of `circle_distance(nu1, nu2)` and `circle_distance(nu1, -nu2)` when either window carries `mirror`; `NaN` where undefined), `delta` (NF9, `sqrt(sum(dist.^2))`, never clipped, `NaN` unless every plane is `:ok`), `D` (`log10 max(delta, floor_multiplier eps)`, `NaN` with delta), `below_floor`, `status` (per plane: `:ok`, `:degenerate`, `:failed`), `failure` (`nothing`, or `(plane, window, sample)` of the first non-finite sample, sample 1-based in the series), `settings` (the identifiers of P11: `estimator = "windowed-fourier"`, `weight = "cosine"`, `window_order`, `positions`, `pad`, `mean_removal`, `mirror_ratio`, `floor_multiplier`, `window = N`, `eltype = precision_label(T)`, `planes`, `min_window = 8 (order+1)`). `ArgumentError` naming `window` (N below the minimum), `series` (fewer than `2N` samples), `pad`, `order`, `positions`, `mirror_ratio`, `floor_multiplier`. |
| `check_frequency_map(r; orbit = 0) -> r` | the host check: returns `r`, or throws `NumericalHealthError("series", value, Inf, step = sample, orbit, :cpu, column = plane)` for a recorded failure (kind `"series"` is new in the list of kinds). |
| `circle_distance(a, b)` | `abs(d - round(d))`, `d = a - b`, in the type of the arguments (NF9). |
| `frequency_distance(nu1, nu2)` | the Euclidean norm of the plane circle distances (NF9), vectors of equal length. |
| `frequency_index(delta; floor_multiplier = 32) -> (D, below_floor, delta_floor)` | NF10: `delta_floor = floor_multiplier effective_eps(T)`, `D = log10(max(delta, delta_floor))`, `below_floor = delta <= delta_floor`; the type of `delta` is kept. |

The coarse search and the stationary point are the module's own business (an FFT for the bin and Newton, or anything else); the tests fix only the results (bin, frequency, amplitude, flags). The transform library's own thread count (1 when orbit threads exceed 1, Compute) is an implementation obligation, checked in the stage 04 child-process run.

### Surface 2: E2, the weighted mean phase advance (I12, I13 sums)

|------|----------------------|

| `LiftedAngleObservable(iq, im = 0)` | isbits; the sample is the pair `(x[iq], x[im])` of a wrapped coordinate and its winding count (`im = 0`: a lifted coordinate with no count), the increment `(q' - q) + tp (m' - m)` with `tp = 2 pi_T` as in `lift` (D28); for the standard map this is the lifted post-kick momentum, the weighted rotation number NF5 in radians. |
| `WeightedPhaseAdvance(; window, observable, birkhoff_order = 1)` | reader reducer for `propagate` with any `k >= 1` (it ignores `W` and returns it unchanged; the stream still needs one column, spec P1 fact (iii)). `window` is N, or a tuple of N for several horizons of one run (one set of sums each, F9); every N at least 16, else `ArgumentError` naming `window`; `birkhoff_order >= 1`, else naming `birkhoff_order`. `check_frame` has no analog: the reducer reads no column. The reducer and `weighted_phase_frequency` share one update, so the tests require bitwise equality between the stream result and the function on the series sampled at the handoffs for the planar observable (criterion 10(c)). Recorded lines R2 and R8 need only these names.

### What Experiments must supply, and what it does not yet do

Obligations, as for the stretching numbers (nothing is built or tested in this run, see Items 2): (i) a transient window feed for E1: the recorder loop (already on the shared tangent body, so the orbit stays the identical orbit) copies the observable (`exp(i q)` from the wrapped coordinate by default, `q + i p` for planar maps) at each handoff of the window pair into a per-chunk buffer of `32 N` bytes per orbit (Float64) and calls `frequency_map`; only the frequencies, flags and identifiers are stored (about 50 bytes per orbit and horizon, P11); the capacity formula gains the series bytes (`32 N`, `64 N`); (ii) chains containing `WeightedPhaseAdvance` built under the one-replacer rule (it is a reader and goes anywhere before the replacer), `check_run(r, tau, N)` before the stream, the chain, the observable, `window`, `tau` and `birkhoff_order` recorded with the run (the stream record holds only `reducer_provenance`); (iii) the series is the sample at the handoffs `1..2N` (E1) or `1..2N+1` (E2); (iv) the 4D case passes one series (or one reducer) per plane. What exists today: the recorder with `first_steps` set to `2N` holds every sample but stores the orbit point and the method columns for every orbit in the run store (spec P1 (a1), a pilot only); it has no NAFF method id, no window feed, no E2 chain and no path that allocates a workspace (no workspace is needed here).

## Conventions

Element types Float64 and Double64 (D24); BigFloat(256) for the references and, for the pure E2 function only, as an element type (criterion 8(c)); tolerances in units of `effective_eps(T)` (Double64: `2^-100`), copied from the spec unless marked `amended` in the table. State mode: wrapped (`WrappedStandardMap`, state `(x, p, m, n)`), the observable `exp(i q)` built from the wrapped coordinate (`cos x + i sin x` in `T`), `q + i p` from the wrapped pair, the lifted increments from the state and its winding counts. Y5: `LinearSymplecticMap` of `rotation_block` direct sums ordered `(q_1..q_N, p_1..p_N)`, observable `q_k + i p_k`, `z' = exp(-i theta) z` (NF14). Signals (lines, drift, NF15) are generated in BigFloat(256) by exact recurrences and rounded once to `T`. References (all in `nf_helpers.jl`, tested in `nf_selftest.jl` before stage 03): the cosine windows `nf_chi` and the closed form `nf_phi_closed` (Eq. (57)); the direct sums `nf_S` (`S_0, S_1, S_2`, hence `f = |S_0|^2`, `f'`, `f''`); the coarse maximum `nf_coarse` (direct for N up to 1024, two-stage above); the stationary point `nf_stat_ref` (a 33-node sign scan of `f'` in Float64 to certify one `+ -` change in the bracket `[nu_c - 1/M, nu_c + 1/M]`, then Newton in BigFloat to 1e-60, `f'' < 0`); the weighted phase advance `nf_E2_ref` at 512 bits; `nf_compare_window` (bin check by value, so that a tie is counted and a wrong bin fails; frequency within 16 eps and amplitude within 64 eps of the reference). The regular class is `lb_regular()` of the lyap-benettin folder (L1 S7: K = 0.5, screening by `X(1e5) <= 5e-4`, seed 20282082), included once behind a guard; K = 2 pi, 5, 10 draw from `StableRNG(nf_seed(0, i))`.

Missing-module behaviour: every new testset starts with a line `_ = (name, ...)`, so without the new code it errors on its first statement (`UndefVarError`) and nothing else; no top-level code and no helper calls a new name at include time (helpers call them only inside function bodies that the testsets call). `nf_selftest.jl` uses no new name and must pass now.

Seeds (base 20261012 + 38000 = 20299012, distinct from sali 31000, fli 33000, megno 35000, rli 36000, stretching 37000; `nf_seed(ac, sub) = base + 50 ac + sub`; `StableRNG` throughout): panel starts and frames of K = 2 pi, 5, 10: `nf_seed(0, 1..3)` = 20299013 to 20299015; self-test 20299013 and 20299014; AC6 starts 20299313; AC7a starts `nf_seed(7, 21..24)` = 20299383 to 20299386 (one per theta) and frames 20299364; AC7b `q_0` 20299372, frames 20299373; AC10 frames `nf_seed(10, 1..4)` = 20299513 to 20299516; AC11 frame 20299563 and the `propagate` seed 20299564; AC12 starts 20299617 (K = 0.5) and 20299613 (K = 2 pi), frames 20299627 and 20299623; AC13 frames 20299663. The K = 0.5 screening seed is the one of lyap-benettin (20282082). Draws that appear without a seed: none.

Runtime (D38 class): sizes follow the spec except where marked in the table; `NF_FULL_RUN = true`, set before including `runtests.jl` by `verify/naff-fma.jl` (stage 04), selects the spec sizes (20 starts, N up to 4096 and 10001, N = 16000 in AC8(c)). ## Dry run against a throwaway stub (not in the repo)

To check that the tests and the tolerances are not broken, the suite was run against a throwaway implementation of the API above in a scratch copy of the package (`scratchpad/nf-stub`: a copy of `src/` and `ext/` with one added file `src/Indicators/naff.jl` of about 420 lines, plain arrays and the Foundation helpers `CompensatedSum`, `add`, `total`; the precompile workload removed; nothing of it is in the repository). The stub is a correct implementation by the spec as worded: Float64 direct-summation coarse search (two-stage above N = 1024), Newton on `f'` in `T` with compensated sums and `fma`-reduced phases, mirrored weights, the reducer with the state sizes above. Result of the final run: **797 passed, 0 failed, 0 errors, 30 testsets, 87 s** (2 threads, whole folder including the one-time `lb_regular` screening).

Defects found in the first drafts, all fixed (the test was wrong unless stated):

- `frequency_index(1e-3; floor_multiplier = 1e20)` is not below the floor in Double64 (multiplier 1e30); the hand value of `phase_increments` must use the T values of the phases (Double64 `1.9 - 1.3` differs from `0.6` by 1e-16); `circle_distance` and `frequency_distance` references must be formed from the widened inputs, not from decimals.

## Items for the owner

Each item is a proposal for the stage 02 checkpoint; items marked (changes the spec) alter a criterion or a section as worded, the others record a reading or a requirement for stage 03.

1. (changes the spec) Run length of E2. The reducer is called at the handoffs `tau, 2 tau, ...`; `reducer_init` receives no initial point, so the sample 0 of the series is the first handoff and a pair of windows of N increments needs `2N + 1` handoffs, not `2N` (criterion 10(c), Algorithm E2, I9 wording "2N + 1 samples" is right, "a run whose length differs from 2N handoffs" is not). The tests use `2 max(window) + 1`. Alternative: pass the initial point to `reducer_init` (a Tangent change, rejected).
2. Criterion 16 (the series feed) is conditional on option (a2) being built; the plan assumes it is not built in this run, as the stretching run did for its Experiments obligation, and writes no test. Proposal: confirm, the criterion then moves to the study spec; or order a separate feed run, for which the tests would be: capacity formula exactly, bytes per orbit and horizon, buffer released, stored frequencies bitwise those of `frequency_map`, orbit points bitwise those of the stream. Criterion 11(a) "a failed chunk stores nothing" is the same obligation (the stream part is tested: `propagate` raises and returns nothing).
3. (changes the spec) Criterion 7(c): the series `exp(i q)` built from the wrapped coordinate of the K = 0 orbit is not within 4 eps per sample of the exact orbit in Float64 for long windows: the wrapped map reduces by `2 fl(pi)`, which differs from `2 pi` by 2.4e-16, once per winding (2151 windings in 4096 steps: 2234 eps; Double64 34 eps). The frequency is unaffected (the drift is `|2 pi_T - 2 pi| p_0/(2 pi)^2` per step, 0.1 eps; criterion 7(b) holds). It is a statement about the caller's series, not the module; `nf_selftest.jl` gates a derived bound. Proposal: restate 7(c) as that bound, or drop it.
4. (changes the spec) Criterion 7(b), mean removal on: the window mean of a line is a nonzero DC term and its leakage moves the frequency by about `192 m/(N^4 (2 pi nu)^3)` (Laskar2003 Eq. (63) form), 1e-9 at N = 1000, p_0 = 0.1; "within 16 eps" holds only when `m` is 0. The tests gate 16 eps + 4 times that bound. Proposal: that wording, or drop the mean-removed clause (criterion 9 gates the mean-removed algorithm against its reference already).
5. (changes the spec) Criterion 4(e): the line at -nu leaks into the line at +nu; `delta <= 32 eps` (e = 0.01) and `delta = 2 nu` within 32 eps (e = 0.2) are not attainable (1.8e-15 and 6.2e-12 realized, identically in both element types, 8 eps and 2.8e4 eps). Gated instead: the flags, delta equal to the reference delta within 32 eps, the nominal value within twice the leakage bound plus 32 eps (realized 0.2 of the bound). Proposal: that wording.
6. (changes the spec) D80b(i): "within 4 eps relative" is the p = 1 bound; the relative rounding of `sin^(2p)` grows with 2p (realized worst 4.7, 6.1, 8.1, 10.9 eps for p = 2 to 5). The tests use 2 (p+1) eps. The weights must be computed from the `sin` form with mirrored indices (a `1 + cos` form loses N^2 eps near the ends); (iv), (ii) and the symmetry hold as worded.
7. (changes the spec) Tie rule (Algorithm E1 step 3, criteria 9 and 11(d)): ties "within 8 eps relative" cannot be decided by a Float64 coarse transform (the exact cosine pair differs by 14 eps in a direct sum, an FFT adds its own rounding) and not at all for Double64. Proposal: the coarse search ties are values within `64 eps(Float64)` = 1.4e-14 of the largest for every element type, the lowest index wins, and the same tolerance is used where criterion 9 counts ties. A genuine near-tie closer than 1.4e-14 in a Double64 series is then decided by the Float64 transform (which bin is returned), and the refined frequency of either bin is within the bracket; flagged.
8. (changes the spec) Degenerate series (Algorithm E1 step 1, criterion 11(b)): "a series that is constant afterwards has no line" and "with mean removal off the frequency is 0 with the near zero flag" contradict each other for a constant nonzero series. Proposal: `:degenerate` when mean removal is on and the series is constant afterwards, or when the series is identically zero; a nonzero constant with mean removal off is a DC line (frequency 0, `near_zero`). The planar observable at the origin (`z = 0`, undefined increment) is not tested: proposal, record it as `:degenerate` in the reducer and leave `nu` undefined.
9. Criterion 1 amplitude within 8 eps: naive summation of `S_0` gives 15 eps at N = 4096 (4.5 to 15 eps in the first stub); compensated (Neumaier) or pairwise summation gives 0.9 eps. Stage 03 must sum with compensation, in the transform too if one is used for the refinement.
10. Criterion 8(a) "symmetry within 4 eps relative" holds only if `w(j/N)` is evaluated at `min(j, N-j)/N` (the weight of `t` and of `1 - t` differ by `u eps`, `u = 1/(t(1-t))` up to 1e5, relative); the API fixes that and the same for the reducer (the symmetry is then bitwise, and the weighted mean of `j` is exactly `N/2`, which the hand values of the API testset use).
11. Criterion 10(a) chains {empty} and {E2 alone} overflow the deviation columns at K = 2 pi over 2001 steps (growth rate about 2 per step); the tests append a test-side column normaliser to those chains and to the trace-only chain. Same orbit, same bitwise comparisons.
