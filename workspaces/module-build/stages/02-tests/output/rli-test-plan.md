## API proposal for stage 03

Two new surfaces, both additive. `using Chaoslab` is enough (the re-export loop in `src/Chaoslab.jl` picks up new exports). The reducer follows the protocol of `MEGNO`, `FLI` and `SALI` (`reducer_init`, `reducer_step`, `reducer_update`, `reducer_final`, `reducer_failed`, `reducer_error`, `reducer_provenance` of `Chaoslab.Tangent`); the scaled norm is `safe_norm` of Foundation (D69), the log sums are `CompensatedSum`/`add`/`total` with the same operations as `Benettin`, `SALI`, `FLI` and `MEGNO`, so the sums are bitwise those of L1 (criterion 8(b)).

**Surface 1: the product construct (layer `Systems`, new file `src/Systems/pair.jl`).**

| Name | Signature and meaning |
|------|----------------------|
| `PairMap(sys)` | subtype of `AbstractMap` for any base map `sys` (tests: `StandardMap`, `WrappedStandardMap`, `LinearSymplecticMap` with d = 2 and d = 4, and four test maps). The pair state is the concatenation (state A; state B) of two states of the base map, so its length is 2 s (s = 2 lifted, 4 wrapped); `dimension(PairMap(sys)) = 2 dimension(sys)`. `forward`, `inverse` are bitwise the two halves; `tangent(P, z)` has size 2d x 2d, `Matrix(tangent(P, z))` is the block-diagonal matrix of the two single tangents with exact zeros, `inverse_tangent` likewise; nothing couples the blocks. **The action `tangent(P, z) * W` that the stream forms must be bitwise the product of each single tangent with its own block rows of W** (the same d x d times d x k operation as the single-orbit stream): a dense 2d x 2d times 2d x 2 product is not enough in Double64 (test "PAIR block action", Deviations 5), so `tangent` should return a block-aware object (its own type with a `*` method and `size`/`Matrix`) or the stream must multiply per block; the tests ask only for `size`, `Matrix` and `*`. No allocation. The caller builds the starts and the frame (below). |

**Surface 2: the reducer and the pair start (layer `Indicators`, new file `src/Indicators/rli.jl`).** `pair_start` and `pair_distance` live here, not in Systems, because they raise `NumericalHealthError` and use `safe_norm`, and Systems imports nothing from Foundation (D23): the spec's P11 ("the pair construct lives in Systems") is amended accordingly (Deviations 4). Both use the internals `Systems._pi` and `Systems._reduce` as `Lyapunov/separation.jl` does.

| Name | Signature and meaning |
|------|----------------------|
| `RLI(; replace = true)` | reducer for `propagate` with `k = 2` on a pair system (state of the pair, `d = 2 d_base` even). `reducer_init(RLI(), T, Val(d), Val(k))` throws `ArgumentError` with message `"RLI needs k = 2, got k = $k"` for `k != 2` and `"RLI needs an even dimension, got d = $d"` for odd d. Isbits reducer and state (GPU-compatible). `replace` is the chain position of the one-replacer rule (D71, D72): `RLI()` replaces the columns by the column-normalised matrix (alone in a chain, or last), `RLI(replace = false)` reads the arriving columns and returns `W` unchanged, for a chain in which a later reducer (`MEGNO()`) replaces them. Valid chains tested: `{RLI}`, `{RLI(false), MEGNO}`, `{MEGNO(false), RLI}`. The reducer cannot see the chain. |
| `reducer_step(RLI(), st, n, x, W)` | at the handoff `n = K tau` (K counted by the reducer): scaled norms `alpha_A`, `alpha_B` of the two arriving columns (column 1 = orbit A, column 2 = orbit B; zeros in the other block add nothing); if one is zero or non-finite, record the failure (kind `"deviation matrix"`, the failing `column` 1 or 2, column 1 when both fail, the value, the handoff step) in the state, leave every sum, series and `W` unchanged, no throw; else `a = log(alpha)` added to the compensated log sums `s_A`, `s_B`, `DL = abs((s_B + comp_B) - (s_A + comp_A)) / n` (the correction terms included, F5), `Q += DL` (compensated), `RLI = Q / K`; `W` replaced by the column-normalised matrix when `replace`, unchanged otherwise. |
| `reducer_update`, `reducer_failed`, `reducer_error` | as `MEGNO`: `reducer_update` throws `reducer_error(r, st, 0, :cpu)` on a failure; `reducer_error(r, st, orbit, backend)` is `NumericalHealthError("deviation matrix", value, threshold, step, orbit, backend, column)` with threshold `0.0` for a zero norm and `Inf` for a non-finite one; a failed state stays failed and unchanged. |
| `reducer_final(RLI(), st)` | `(n, handoffs, DL, RLI, sum, comp, Q)`: `n` the last successful handoff (map step), `handoffs = K`, `DL` and `RLI` scalars of type T (the raw DL_k and the smoothed value at the last handoff, linear, never clipped or floored), `sum`, `comp` `SVector{2,T}` (compensated log sums `s_A`, `s_B` and their correction terms, bitwise those of L1), `Q` the total (sum + compensation) of the DL series. At `n = 0` everything is zero. |
| `reducer_provenance(RLI())` | `(indicator = "rli", convention = "same xi_0, shadow along xi_0, mean over the handoffs 1..K")`, merged into the `propagate` run record next to `tau`, `k`, `precision`. |
| `check_frame(RLI(), W0; orbit = 0)` | the caller's frame check before the stream (sali Amendment D67, fli D72 item 7), a method next to those of `SALI`, `FLI`, `MEGNO`. Checks in this order: both columns unit vectors to roundoff (norm defect at most `8 effective_eps(T)`, column 1 first); column 1 supported in the first half of the rows and column 2 in the second half (exactly zero elsewhere); the two block vectors bitwise equal. Returns the larger norm defect, or throws `NumericalHealthError("initial frame", value, threshold, 0, orbit, :cpu, column)` with the offending column (1 or 2; column 2 when the block vectors differ), threshold `8 eps` for a norm defect and `0` for the support and equality checks. `ArgumentError` if the frame does not have 2 columns or has an odd number of rows. The block frame itself (column 1 = (xi_0, 0), column 2 = (0, xi_0)) is built by the caller (`rl_frame` in the tests), xi_0 the first seeded unit vector of the pair id (`initial_deviations(seed, id, Val(d), Val(1), T)[:, 1]`; it does not depend on k). |
| `pair_start(sys, x0, u, Dx; orbit = 0)` | `sys` the base map, `x0` the lifted base point (an `SVector{2}` for the standard maps, any state for other maps), `u` the unit direction (xi_0, P3), `Dx` the nominal separation (must widen exactly into the element type, else `ArgumentError`). Returns `(z, Dx, Dx_r, mode)`: `z` the pair state (state A; state B), A = `x0` (`torus_state(x0)` for `WrappedStandardMap`), B = A + Dx u (for the wrapped map reduced to [0, 2 pi) with the reduction counts added to those of A, so the lifted separation is exactly the minimal-image one: bitwise `displaced(sys, zA, Dx * u)` of lyap-two-trajectory), `Dx` the nominal value in T, `Dx_r` the realized separation (the norm of the minimal-image difference of the stored states, within 4 eps of `safe_norm(separation(...))`), `mode` `"wrapped"` or `"lifted"`. A `Dx_r` that is zero, not finite, or outside `[Dx/2, 2 Dx]`, or a `Dx` that is not finite and positive, throws `NumericalHealthError("separation", value, threshold, 0, orbit, :cpu)` with the pair id as `orbit`, threshold `0.0` for a zero, `Inf` for a non-finite value and `Dx` for a value outside the interval, before any map call. |
| `pair_distance(sys, z)` | the Euclidean (`safe_norm`) norm of the minimal-image separation of a pair state `z`: for `StandardMap` and `WrappedStandardMap` each coordinate difference reduced modulo 2 pi to (-pi, pi] (for any magnitude of the lifted difference), for other maps the plain difference. Used for `Dx_r` at the start and for the final pair distance from the final states. |

Series are read as in the Lyapunov, sali, fli and megno suites: the stream has no emission channel (L1 Q9), so the tests wrap the reducers of a chain in a probe reducer (`rl_Probe`, test side) that records `reducer_final` at chosen handoffs, and run them through `propagate_orbit`; the kernel path (`propagate`) is used in AC11a, AC11b, AC11e, AC12b and AC12d.

## Conventions

Element types Float64 and Double64 (D24), BigFloat(256) in AC4, AC7c, AC10 (b), (c); tolerances in units of `effective_eps(T)`. State mode: wrapped (the default, P5) unless stated; the lifted mode in AC2 (K = 0), AC7a (the distance), AC7d (R8) and AC13. Pair starts are built in the tests with `displaced` and `separation` of the verified lyap-two-trajectory module (an oracle independent of the new construct, `rl_pair`), so that `pair_start` is tested against it and the numerical criteria do not depend on `pair_start`. Reference: BigFloat(256) exact sums `s_i(k) = ln(norm(Y_k xi_0) / norm(xi_0))` at the realized points of each orbit (`rl_ref_s`; dividing by the stored vector's norm makes s(0) = 0 exact), then DL_k and the mean by RL4 (`rl_ref_rli`, with switches for the faulty doubles of AC1). Bounds: RL11, `B_R(n) = 8 eps (Psi_max^A + Psi_max^B) H_K / n + 4 eps RLI_ref`, `Psi_max` the maximum of `Psi_g` (`lb_Psi`, L1 Amendment D35, Float64 from the stored tangents of each orbit) over the checkpoints `g <= n` (10 per decade; every multiple of 10 with `RL_FULL`); the DL bound is the first display of RL11 plus `4 eps DL_ref` for the subtraction and the division (a test-side reading, Deviations 10). For T1 the bound is `8 eps (n + G_first)` per orbit (K_s = 0). The K = 0.5 regular class has the ids, starts and screening of `lb_regular()` (L1 S7: X(1e5) <= 5e-4, seed 20282082); helpers of the lyap-benettin folder (`lb_regular`, `lb_Psi`, `lb_tangents`) are used through the guard `@isdefined(lb_regular) || include(".../lb_helpers.jl")` as the megno suite does (`test/rli` sorts after `test/lyap-benettin`).

Missing-module behaviour: every testset starts with a line `_ = (RLI, PairMap, ...)` naming the new symbols it uses (33 testsets, all checked), so without the new code the testset errors on its first statement (UndefVarError) and nothing else; no top-level code and no helper calls a new name at include time. Failure reports are kept short (`rl_nbad`, booleans) so that a failing stage 03 run does not dump orbits.

Seeds (base 20261012 + 36000 = 20297012, distinct from sali 31000, fli 33000, megno 35000, lyap-benettin 21000; `rl_seed(ac, sub) = base + 50 ac + sub`; `StableRNG` throughout): shared panel starts and frames `rl_seed(0, 1..4)` = 20297013 (K = 2 pi), 20297014 (K = 10), 20297015 (K = 5), 20297016 (K = 0); K = 0.5 regular class: lyap-benettin screening seed 20282082 (ids, starts and xi_0); AC2 20297112 (xi_0 of ids 1..100); AC7 20297363 (start draws and xi_0); AC9 20297463; AC11 20297563 to 20297568 (sub 1 to 6); AC12 20297612 (and the starts of AC12b 20297624, frames 20297622, AC12c 20297632, AC12d 20297642); AC13 20297662 (dyadic starts, xi_0); PAIR 20297713 to 20297716; API 20297765; R1 20297813; R5 20297814. AC1 draws nothing (dyadic starts), AC3, AC4, AC5, AC6, AC8, AC10 draw nothing beyond the shared panel. Frames are `initial_deviations(seed, id, Val(2), Val(1), T)`, the first seeded column, which the AC9 test shows equal to the first column of the k = 2 frame.

Runtime (D38, 3 minute ceiling): the package suite runs the sizes of the spec except where marked (Deviations 8). Measured against the throwaway stub below, whole `rli` suite on 2 threads, precompiled: 47 s (64 469 passes, 33 testsets; per testset: AC3 8.5 s, AC4 6.5 s, AC10 5.7 s, AC5 4.5 s, AC7c 3.5 s, AC12b 3.1 s, AC6 2.6 s, AC2 2.4 s, AC1 2.0 s, the rest below 1.5 s). The real module adds the first compile of the kernel path for three chains; expected package runtime 1.5 to 2.5 minutes. `verify/rli.jl` (stage 04) sets `RL_FULL_RUN = true` before including `runtests.jl`: 20 starts to n = 1e4 in AC3, n = 1e4 in AC4, 1000 starts in AC5 at 1e4, the spec sizes in AC10(a), n = 1e5 in AC2 for Double64, every multiple of 10 for the Psi grid, Double64 starts of AC6.

## Deviations and spec items not testable as written

All are proposals for the stage 02 checkpoint. Items marked (changes the spec) alter a criterion or a section as worded; the others record a reading, a size or a requirement for stage 03.

1. (changes the spec) Criterion 7(a), "Dx_r ... equals the BigFloat difference of the two stored initial points with tolerance 0": Dx_r is a norm, which cannot be exact. Proposed wording: the two components of the minimal-image difference of the stored initial points equal the BigFloat differences exactly (Sterbenz, tolerance 0), and Dx_r equals their norm within 4 eps (the test also pins `Dx_r` to `safe_norm(separation(...))` of the verified module within 4 eps; the norm function itself is not prescribed).
2. (changes the spec) Criterion 7(b), the example "Dx near 5e-16 at |x| near 3, where each coordinate of the start is a multiple of 4.4e-16" does not raise the error: with both coordinates on the same grid of spacing h the rounding moves each coordinate by at most h/2, so Dx_r/Dx stays inside [1/2, 2] (checked by hand for Dx = 3e-16, 5e-16 and 3.15e-16 along several directions). A nonzero Dx_r outside the interval arises only when a coordinate on a coarse grid is lost and the other is on a fine grid. Proposed wording: "Dx = 4.5e-16 along u = (0.2, sqrt(0.96)) from (x, p) = (0.1, 5.0) (p lies on a grid of spacing 8.9e-16, x on a fine one; the p component 4.4e-16 is lost and Dx_r = 9e-17 < Dx/2)". The test computes the precondition from the verified `separation` before asserting the error. The zero case (Dx = 1e-18 at |x| near 3) is kept as worded.
3. (changes the spec) Criterion 4. (a) The proposed `abs(rho(Dx_2)/rho(Dx_1) - 1) <= 20 Dx_2` fails for 6 of the first 20 regular-class starts at n = 100 and 6 at n = 1e3 (BigFloat(256) own orbits; the realized coefficient `abs(rho_2/rho_1 - 1)/Dx_2` is 40, 4.6e3, 21, 70, 20.3 and 336 at n = 100 and reaches 5.9e3 at n = 1e3): the second-order coefficient of the RLI is large near a resonance, the drafting value 0.5 was one start. The test asserts instead that the deviation of rho = RLI / Dx_r from its smallest-Dx value is O(Dx) (dev_i <= 2 (Dx_i/Dx_{i+1}) dev_{i+1} for consecutive Dx) and reports the realized coefficient; the slope in [0.99, 1.01] is kept. (b) "the same two tests" cannot include the pair test for Double64 (its rounding noise at Dx = 1e-20 and 1e-16 is far above 20 Dx_2); the Double64 test is the slope plus rho within 1e-3 of the BigFloat rho (realized worst 6.4e-10). (c) is tested in Double64 and BigFloat with the same rules.
4. (changes the spec) P11 and Algorithm item 1 place the pair start with its health error in Systems. Systems imports nothing from Foundation (D23) and the error type and `safe_norm` live there. Proposed wording: Systems holds only `PairMap` (the product map, pure); `pair_start` and `pair_distance` (with the rejection of Algorithm item 1) live in Indicators next to `RLI`, using `Systems._pi` and `Systems._reduce` as `Lyapunov/separation.jl` does. The tests use public names only and do not depend on the layer; the first dry run of the stub failed on exactly this (`NumericalHealthError` not defined in `Chaoslab.Systems`).
5. (requirement for stage 03, changes the cost note of P1(c)) The pair tangent action must be block aware. With a dense 2d x 2d tangent the stream's product `tangent * W` runs through the zero blocks; in Double64 the accumulation (fused multiply-add chains over the zero entries) rounds differently from the d x d product, so block B is no longer bitwise the single-orbit evolution and the exchange symmetry I3 / criterion 9(a), the exact zero of criterion 2 and RL5(d) can fail in the last bit (measured on the stub: 40 failures in AC9 and 2 in "PAIR block action" with a dense `SMatrix` product in Double64; Float64 passes). The test "PAIR block action of the tangent" pins the required behaviour. The cost note "a dense one costs four times" of P1(c) should be struck: a dense action is not acceptable for the pair. Criterion 8 (Float64 only) holds for either.
6. Criterion 8(a): "the chains {empty}" cannot run 1e4 steps on a chaotic orbit (the deviation matrix is never rescaled and overflows after about 600 steps at K = 2 pi). The empty chains run 300 steps and are compared with the first 300 handoffs of the normalising chains; the normalising chains run to 1e4. (Reading.)
7. Criterion 11(e), "the run record carries Dx, Dx_r, the direction rule, tau, precision, state mode, the indicator name and the convention tag": the stream's record cannot hold Dx or Dx_r. The tests check tau, precision, k, the indicator name and the convention tag in the `propagate` record, and Dx, Dx_r and the mode in the record returned by `pair_start`; the direction rule, the seed, the frame source and the chain are recorded by Experiments (as sali D67 item 2 and fli D72 do), the convention tag names the direction rule.
