## API proposal for stage 03

New layer `Chaoslab.Indicators` (`src/Indicators/Indicators.jl`; the `Indicators` entry of the layering test already exists; `src/Chaoslab.jl` adds it to the include list and to the re-export loop, so `using Chaoslab` is enough). The same reducer protocol as the Lyapunov layer (`reducer_init`, `reducer_step`, `reducer_update`, `reducer_final`, `reducer_failed`, `reducer_error`, `reducer_provenance` of `Chaoslab.Tangent`). Names the tests use:

| Name | Signature and meaning |
|------|----------------------|
| `SALI()` | reducer for `propagate` with `k = 2`; `reducer_init(SALI(), T, Val(d), Val(k))` throws `ArgumentError` with message `"SALI needs k = 2, got k = $k"` for `k != 2` (as `Benettin`). Isbits state (GPU-compatible). |
| `reducer_step(SALI(), st, n, x, W)` | at the handoff: scaled norms `alpha_i` of the two columns; if `alpha_i` is zero or non-finite, record the failure (kind `"deviation matrix"`, the failing `column` 1 or 2, value, handoff step) in the state, leave accumulators and `W` unchanged, no throw; else add `log(alpha_i)` to the compensated sums, replace `W` by the column-normalised matrix, compute `SALI(n) = min(d_-, d_+)` from the stored unit columns (no second normalisation, so A16 holds on the stored columns) and `L(n) = -(S_1 + S_2)` (the `ln abs(det W_0)` of A7 is taken as 0: seeded or orthonormal frame, see Deviations item 3). |
| `reducer_update`, `reducer_failed`, `reducer_error` | as `Benettin`: `reducer_update` throws `reducer_error(r, st, 0, :cpu)`; `reducer_error(r, st, orbit, backend)` is `NumericalHealthError("deviation matrix", value, threshold, step, orbit, backend, column)` with `column` 1 or 2 (0 for non-finite entries caught by the stream). |
| `reducer_final(SALI(), st)` | `(n, sali, L, sum, comp, floor)`: `n` last successful handoff; `sali::T` = SALI(n); `L::T` = `ln GALI_2(n)` (log form); `sum`, `comp` `SVector{2,T}` the compensated sums S_1, S_2 and their compensation terms (`S_i = sum[i] + comp[i]`); `floor::T` = `B_meas(T)`. At `n = 0`: all zero except `floor` (SALI(0) is returned by `check_frame`, a reducer does not see `W_0`). |
| `reducer_provenance(SALI())` | `(indicator = "sali",)`, merged into the `propagate` run record next to `tau`, `k`, `precision`. |
| `alignment_indices(a, b)` | `(d_minus, d_plus)::Tuple{T,T}` of two nonzero vectors of any dimension: each input divided by its scaled norm, then the scaled norms of the difference and the sum (A2). |
| `sali_pair(a, b)` | `min(alignment_indices(a, b)...)`. Bitwise unchanged by a sign change of either vector and by exchanging them (I2). |
| `sali_from_log(L)` | the A4 conversion `SALI = sqrt(2) g / sqrt(1 + sqrt(1 - g^2))`, `g = min(exp(L), 1)` (valid for SALI well above `eps`). |
| `sali_floor(T)` | `B_meas(T) = 4 * effective_eps(T)` (A14). |
| `check_frame(SALI(), W0; orbit = 0)` | frame check of Algorithm item 1: returns `SALI(0)` (type `T`) if `SALI(0) >= 10 B_meas(T)`, else throws `NumericalHealthError("initial frame", value, threshold, 0, orbit, :cpu, 0)`. `propagate` and `propagate_orbit` must call it for a supplied `W0` before any map evaluation (see Spec items not testable as written, item 1). |

Series are read as in the Lyapunov suites: the stream has no emission channel (L1 Q9), so the tests wrap `SALI()` in a probe reducer (`sl_Probe`, test side) that records `reducer_final` at chosen handoffs, and run it through `propagate_orbit`; the kernel path (`propagate`) is used in AC13, AC14 and the record test.

## Conventions

Element types Float64 and Double64 (D24), BigFloat(256) in AC12(b); tolerances in units of `effective_eps(T)` (Float64 eps, Double64 2^-100). Constants of the spec in `sl_helpers.jl`: `B_meas = 4 eps` (`sl_meas`), `B_SALI(n) = 8 eps [Lambda_n + SALI_ref(n)(Psi_n^(1) + Psi_n^(2))] + B_meas` (`sl_BSALI`), `B_L(n) = 8 eps (Psi_n^(1) + Psi_n^(2))` (`sl_BL`). `Lambda_n` from the reference at every map step (`sl_Lambda`, ratio clipped at e^700, a scale); `Psi_n` is `lb_Psi` of `test/lyap-benettin/lb_psi.jl` (one definition, evaluated in Float64 from the stored tangents). Reference: BigFloat(256) products `Y_n W_0` at the realized orbit points (`sl_ref`), `SALI_ref = 2 sin(atan2(abs(det W_0), abs(w_1 . w_2))/2)` at the kept steps (stable also for an almost orthogonal pair) and `L_ref = ln abs(det W_0) - ln norm w_1 - ln norm w_2` from the exact widened frame. The K = 0.5 regular class uses `lb_regular()` of the lyap-benettin helpers (L1 S7 screening, shared and cached); `test/sali/sl_helpers.jl` includes `lb_helpers.jl` once if the lyap-benettin suite has not already loaded it.

Missing-module behaviour: every testset starts with a line `_ = (SALI, ...)` naming the `Chaoslab.Indicators` symbols it uses, so without the module the testset errors on its first statement (UndefVarError) and nothing else; no top-level code and no helper calls an Indicators name at include time.

Seeds (base 20261012 + 31000, `sl_seed(ac, sub) = base + 50 ac + sub`): AC1 20261012+31050 (random pairs, `StableRNG`); AC3 +31150 (start draws and frames, `initial_deviations` seed); AC4 +31200; AC5 +31250; AC6 +31300; the shared panel uses `sl_seed(0, 1..3)` = 31000 + 1, +2, +3 (K = 2 pi, 10, 5 starts and frames) and the lyap-benettin screening seed 20261012 + 21070 for the K = 0.5 regular class; AC10 +31500 + class index; AC13 +31650 + sub (1..6); AC14 +31700 (+1 orbit starts, +2 ensemble starts); AC15 +31750 (+20 for the prefix test). Frames are `initial_deviations(seed, orbit, Val(2), Val(2), T)`, the first two seeded columns.

Runtime: D38 sizes (3 minute ceiling per slug). The package suite runs the sizes below; `verify/sali.jl` (stage 04) sets `SL_FULL_RUN = true` before including `runtests.jl` for the full sizes (20 starts for every Double64 panel, checkpoints at every multiple of 10). Reductions in the package suite: Double64 panel 8 starts instead of 20 (AC7, AC8); checkpoints at 10 per decade (n = 10, 20, ..., 100, 200, ..., 1000, ..., 10000) instead of every multiple of 10 (the Psi_n sum costs O(n) per checkpoint); AC3 n = 1e6 for Float64 only (3 starts), Double64 4 to 8 starts at 1e4; AC4/AC5/AC6 Double64 30 ids instead of 100; AC6(b) n in 1..100 and every 10th up to 1000. Measured against a throwaway stub of the module (below): 52 s wall on 2 threads with compilation; the real module may be slower (first-compile of the kernel path, allocations), so the expected package runtime is 1 to 3 minutes.

## Deviations and spec items not testable as written

Resolved by the owner at the stage 02 checkpoint, 2026-10-21: all items as proposed, recorded as spec Amendment D67. Item 1 is resolved without a stream hook: the caller runs the frame check before the stream, and the testset "AC13c rejection before any work" checks that order; item 5 is amended to 16 eps.

1. "Rejected before any work" (criterion 13(c)) cannot be expressed in the reducer protocol as it stands: `reducer_init(r, T, Val(d), Val(k))` does not see `W_0`. The tests require a frame check ahead of the launch: `check_frame` is also called by `propagate` (supplied `W0`, every orbit, before the kernel launch) and by `propagate_orbit`. This needs a small hook in the stream (a `reducer_check_frame(r, W0, orbit)` no-op default that the chain calls), that is a change to the verified tangent-core code and is therefore an owner decision; the testset "AC13c rejection before any work" is the only one that depends on it (the other "AC13c" testset tests `check_frame` alone). SALI(0) is likewise returned by `check_frame` and not by `reducer_final`, for the same reason.
2. Criterion 13(e): the run record can carry `tau`, `precision`, `k` and the indicator name, and the final carries `floor`. "Frame source" and "chain order" are not part of the record the reducer protocol can build (`reducer_provenance(r)` sees neither); not tested.
3. A7 writes `L(n) = ln abs(det W_0) - S_1 - S_2`. A reducer never sees `W_0`, so the proposal is `L = -(S_1 + S_2)` (the seeded and every orthonormal frame has `abs(det W_0) = 1`); the tests use only such frames for L. For a supplied non-orthonormal frame the caller adds `ln abs(det W_0)`. The reference uses the exact widened frame, whose `ln abs(det)` is of order eps, far inside B_L.
4. Criterion 5(b) states the correction as `mu_+^(-2n)`. The neglected term is `(b_i/a_i)(v_u . v_s)/norm(v_u)^2 mu_+^(-2n)` per vector, with a coefficient above 1 for some frames; in Float64 this is far below B_L, in Double64 at n = 20 it is not (stub run: errors 1e-23 against `mu_+^(-40)` = 1.3e-23, up to 14 times larger for some ids). The test uses 1.01 (coefficient + 1) mu_+^(-2n) with the coefficient computed per id; the spec constant should say so.
5. Criterion 1(b), `abs(d-^2 + d+^2 - 4) <= 8 eps`: for unit vectors held with relative norm errors e_1, e_2 (at most about 2 eps each, A14) the sum is `4 + 2(e_1 + e_2) + ...` in exact arithmetic, i.e. up to 16 eps before the rounding of the squares. A faithful throwaway implementation (one scaled norm and one division per input) reached 14 eps (ratio 1.75 to the bound) over 11 000 pairs. The test keeps the spec constant 8 eps, so on a correct implementation it can fail by this margin; a spec amendment (16 eps) is suggested at the stage 03 checkpoint, as D35 did for B_S.
6. Criterion 2: `2 B_SALI` is taken as `B_SALI^tau + B_SALI^1` (each run's own bound; they coincide because the reference does not depend on tau).
7. Criterion 4(a) and 5(a) list n in {1,2,4,8}; for tau = 5 the handoffs are used (n in {5,10}). Criterion 12(b): the BigFloat(256) run is compared with a 512-bit reference, since a reference at the precision it checks has rounding of the size of the bound. Criterion 7/8: checkpoints are 10 per decade in the package suite (D38), every multiple of 10 under `SL_FULL`. Criterion 11: starts in the transient count as not passing (at most 20 percent of the starts may be in it and 80 percent must pass).
8. Criterion 13(d): "no error at n = 200 for tau = 200" relies on the columns being normalised before they overflow, and on an exact SALI = 0 (both columns along e_1) not being an error (A16); asserted as such.
9. Float64 only for the kernel path (`propagate`), as in the Lyapunov suites (one more argument-type combination per element type costs seconds of compile time); Double64 goes through the per-orbit body.

## Dry run against a throwaway stub (not in the repo)

To check that the helpers and the tolerances are not broken, the suite was run against a throwaway implementation of the API above in a scratch copy of the package (`scratchpad/sali-stub`, a copy of `src/` with a 90-line `Indicators` module and the frame hook of Deviations item 1; nothing of it is in the repository). A first version of the stub that normalised the columns a second time inside the SALI evaluation violated the absorbing zero (AC14(d): 32 of 300 starts), which is why the plan says that SALI is computed from the stored unit columns.
