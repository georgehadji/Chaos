## API proposal for stage 03

Two surfaces, both additive. `using Chaoslab` is enough (the re-export loop in `src/Chaoslab.jl` picks up new exports). The tests call only the names below; where this section is silent the tests assume nothing.

### Surface 1: the Tangent workspace (P1 (c); layer `Tangent`; the one change to a verified module)

What was read: the kernel `_orbit_kernel!(x, W, st, code, hstep, sys, n0, steps, N, tau, reducers)` runs one thread per orbit and calls `_orbit_body`, which applies the chain through `_apply` with `reducer_step(r, state, n, x, W) -> (state, W)`; a reducer state is a returned isbits value (`propagate.jl`, `orbit.jl`). Five chunk buffers (`x, W, st, code, hstep`) are allocated once per chunk by `_alloc_bufs` and carried between the launches of the step-chunked relaunch (D44); on the first launch (`n0 == 0`) the kernel draws fresh reducer states, on later launches it reads `st[i]`; `_run_chunk!` reads the states back with `reducer_final(r, state)`; the chunk size is `chunk_size(free; reducer_bytes = sizeof(s0))`. The workspace is the sixth buffer of the same kind.

| Piece | Proposal |
|-------|----------|
| `reducer_workspace(r, T, Val(d), Val(k)) -> Int` (new, exported) | number of `UInt32` the reducer wants per orbit; default method returns `0`. `StretchingNumbers` returns `2 (B + 2)` and throws `ArgumentError` for `k != 2` (same message as `reducer_init`). Called once on the host, before any launch. |
| `reducer_step(r, state, n, x, W, ws) -> (state, W)` (new six-argument method) | `ws` is the orbit's own slice, an `AbstractVector{UInt32}` of the requested length (a `view(ws_matrix, :, i)` in the kernel). Default method forwards to the existing five-argument `reducer_step`, so no existing reducer changes. A workspace reducer writes `ws` in place and returns its scalar state; on a recorded failure it writes nothing. `reducer_update(r, state, n, x, W, ws)` is the throwing form (orbit 0, backend `:cpu`), like the five-argument one. |
| `reducer_final(r, state, ws)` (new three-argument method) | host summary with the workspace; the default forwards to `reducer_final(r, state)`. The counts returned are a fresh array (a copy). The two-argument form stays valid and returns the scalar part. |
| `reducer_bytes(r, T, Val(d), Val(k)) -> Int` (new, exported) | `sizeof(reducer_init(...))` when isbits (else 0) plus `4 * reducer_workspace(...)`: the "reducer bytes" of the memory formula; `propagate` uses it for `chunk_size(...; reducer_bytes = ...)` in place of `sizeof(s0)`. |
| `propagate_orbit(...; workspace = nothing)` (new keyword) | the per-orbit body takes the workspace of the chain; `nothing` allocates `zeros(UInt32, m)` inside; a vector of a length other than `m` is an `ArgumentError` whose message contains `workspace`, before any work. The body zero-fills the workspace before the first step (the `n0 == 0` rule of the kernel). Returns the same `(x, W, states)`. |
| chain rule | at most one reducer of a chain may request a workspace (`ArgumentError` containing `workspace`, before any work); the whole per-orbit vector is then passed to every `reducer_step` of the chain, and the ones that request nothing ignore it. This avoids offsets; a chain with two workspace reducers needs offsets and is not needed by any module so far. |

What must change (stage 03, written as a short additive section appended to the tangent-core family, as the spec says):

- **Tangent, CPU and the kernel (same source, T-AC14 keeps one per-step update)**: `Tangent.jl` (three new generic functions with their default methods, two exports); `orbit.jl` (`_apply` and `_orbit_body` carry `ws`; `propagate_orbit` gets the keyword and the length check); `propagate.jl` (`_orbit_kernel!` gets the argument `ws` and zero-fills `view(ws, :, i)` when `n0 == 0`, with an explicit loop rather than `fill!` so that it compiles on the device; `_alloc_bufs` allocates `KernelAbstractions.allocate(backend, UInt32, m_ws, chunk)`; `_run_chunk!` reads it back with `_host` and calls the three-argument `reducer_final` on `view(ws_host, :, i)`; `_propagate` adds `4 m_ws` to `rbytes`; the `_before_launch` hook receives `workspace = ws` in its carried tuple). The buffer is carried between launches exactly as `st` is, so the D44 relaunch needs no other change; a chunk that falls back to the CPU after a failed device launch is rerun from its initial state, which zero-fills again. `out.finals` must be typed from the three-argument final at a zero workspace (the two-argument final has a different field set).
- **CUDA extension**: `ext/ChaoslabCUDAExt.jl`, `compiles(T)` calls `_orbit_kernel!` with the old argument list; it needs the extra (empty) workspace argument. Nothing else: the buffers are allocated through KernelAbstractions.
- **Could not be determined here (no GPU in this session, nothing in the repository settles it)**: whether `view(ws, :, i)` of a `CuDeviceMatrix` and a `UInt32` increment compile and run in the kernel for B near 1000 (the `compiles(T)` probe of the extension is the check; the GPU criterion 16 is the test), whether a zero-row workspace matrix for the reducers that request nothing is accepted by `CUDA.jl` (fallback: allocate one row), and the layout (`m x chunk`, orbit-major, is proposed; a chunk-major layout would coalesce neighbouring threads better and changes nothing in the tests). Cost of the two scattered 4-byte increments per handoff on the GTX 1050 is the benchmark's question (R6).

### Surface 2: the reducer and the pure functions (layer `Indicators`, new file `src/Indicators/stretching.jl`; exports `StretchingNumbers, spectral_distance, spectrum_cell, spectrum_density, stretching_range, check_run` and the new `check_frame` method)

| Name | Signature and meaning |
|------|----------------------|
| `StretchingNumbers(; range, bins = 1000, interval = 100, min_per_cell = 100, replace = true)` | reducer for `propagate` with `k = 2` (any dimension `d`). `range = (s_lo, s_hi)` is required: the reducer cannot see the map (the derived default is `stretching_range(sys)`, passed by the caller). `bins` B, `interval` in map steps (recorded; the evaluations of D are made by whoever reads the counts, see below), `min_per_cell` for the under-sampling flag (keys proposed in P4: `spectrum_bins`, `spectrum_interval`, `spectrum_min_per_cell`), `replace` the chain position of the one-replacer rule (D71, D72, D75; P6). | `check_run(r, tau, N) -> nothing` | the caller's check before the stream (the protocol gives `reducer_init` neither `tau` nor `N`): `ArgumentError` containing `interval` if `interval % tau != 0`, containing `handoffs` if `N / tau > 10^9` (P4). |
| `reducer_init(r, T, Val(d), Val(k))` | `ArgumentError` `"StretchingNumbers needs k = 2, got k = $k"` for `k != 2`. | `reducer_step(r, st, n, x, W, ws)` | at the handoff `n = K tau` (`tau = n / K` is recovered from the count): scaled norms `alpha_j` (`safe_norm`) of the two arriving columns; if one is zero or non-finite, record kind `"deviation matrix"`, the failing `column` (1, or 1 when both fail), the value and the handoff step in the state, leave sums, counts, `ws` and `W` unchanged, no throw; else `a_j = log(alpha_j)` added to the compensated sums, `a_j^2` to the second sums, `z_j = a_j / tau`, the cell of SN4 incremented in `ws` (column `j` owns entries `(j-1)(B+2)+1 .. j(B+2)`, cell `c` at offset `c + 1`); `W` replaced by the column-normalised matrix when `replace`, unchanged otherwise. A failed state stays failed and unchanged. |
| `reducer_final(r, st)` | scalar part: `(n, handoffs, sum, comp, sum2, comp2, mean, std)`; `sum`, `comp` (the log sums of a column and their correction terms, bitwise those of L1), `sum2`, `comp2` (of `a^2`), `mean`, `std` are `SVector{2,T}`; `mean_j = total(sum_j) / n` (the L1 value), `std_j = sqrt(max(total(sum2_j) / (tau n) - mean_j^2, 0))` (division by the count, SN7). At `n = 0` everything is zero. |
| `reducer_final(r, st, ws)` | the above plus `D::T` (SN5 on the two count columns), `undersampled::Bool` (`handoffs < min_per_cell * bins`), `counts::Matrix{UInt32}` of size `(B+2, 2)` (row `c + 1` is cell `c`, column `j` the vector `j`; a copy), `below`, `above::SVector{2,Int}` (the counts of cells 0 and `B + 1`). D is a function of the counts, so its series is read by calling `reducer_final` at the evaluation handoffs (multiples of `interval`, and the last): the stream has no emission channel (L1 Q9), so the tests wrap the reducer in a test-side probe (`sn_Probe`, as `rl_Probe`) that records the final at chosen handoffs. |
| `reducer_provenance(r)` | `(indicator = "stretching", convention = "cumulative spectra, D at every interval, columns renormalised separately, no orthogonalisation, overflow cells of width h", spectrum_bins, spectrum_lo, spectrum_hi, spectrum_cell_width, spectrum_interval, spectrum_min_per_cell, replace)`, merged into the `propagate` run record. The state mode, frame source and chain are recorded by Experiments (sali D67 item 2, fli D72, rli D76 item 6). |
| `reducer_workspace`, `reducer_bytes` | see Surface 1. |
| `check_frame(r, W0; orbit = 0)` | the caller's frame check (sali D67, fli D72 item 7), in this order: both columns unit to roundoff (`abs(norm - 1) <= 8 effective_eps(T)`, column 1 first; non-finite counts as a failure), then not parallel (`min(norm(w1 - w2), norm(w1 + w2)) > 8 eps`). | `spectrum_cell(z, lo, hi, B) -> Int` | the cell rule of SN4 in the type of the arguments: `0` below `lo`, `B + 1` above `hi`, `min(floor((z - lo) / h) + 1, B)` inside with `h = (hi - lo) / B` (so `z == hi` is cell `B`, `z == lo` cell 1). The kernel uses this function. |
| `spectral_distance(N1, N2, h) -> typeof(h)` | SN5: `sqrt(S) / (k sqrt(h))`, `S` the exact `Int` sum of squared differences, `k = sum(N1)`; `ArgumentError` if the totals differ, `DimensionMismatch` (or `ArgumentError`) if the lengths differ, `0` for `k = 0`. | `spectrum_density(counts, h) -> Vector` | SN3: `N_c / (k h)` for `c = 1..B` of a count column of length `B + 2` (`k` the column total including the overflow counts). |
| `stretching_range(sys) -> (lo, hi)` | the symmetric derived range of SN12, `hi = L (1 + 8 eps)` rounded so that `hi` lies between `L (1 + 4 eps)` and `L (1 + 16 eps)` (`L` the BigFloat value) and `lo = -hi`, for `StandardMap`, `WrappedStandardMap` (`L_sigma = ln sigma(K)`, L1 E14) and `LinearSymplecticMap` (`ln` of the largest singular value); `ArgumentError` for a map without stretching (singular values at most 1). Series are read as in the sali, fli, megno and rli suites: the stream has no emission channel, so the tests run chains through `propagate_orbit` with a probe around each reducer; the kernel path (`propagate`) is used in AC11a, AC11d, AC11e, AC12b, AC12d, AC12f, AC13b and the API run-record test.

## Conventions

Element types Float64 and Double64 (D24), BigFloat(256) in AC13c (against a 512-bit reference); tolerances in units of `effective_eps(T)`. State mode: wrapped (the conventions line of the spec) unless a lifted test map is used. The seeded pair of columns of orbit id `j` is the first two columns of `initial_deviations(seed, j, Val(2), Val(2), T)` (`sn_frame`), supplied frames are built in the tests. Starts and seeds of the panel: the K = 0.5 regular class is `lb_regular()` of the lyap-benettin folder (L1 S7: 50 candidates screened by `X(1e5) <= 5e-4`, seed 20282082, their ids and frames), K = 2 pi, 10, 5 and 0 draw from `StableRNG(sn_seed(0, i))`. References: BigFloat(256) exact sums `s_j(m) = ln(norm(Y_m w_j) / norm(w_j))` at the realized points of each orbit (`sn_ref_s`, the tangent product of L1 E1; dividing by the stored vector's norm makes `s(0) = 0` exact), `z_k = (s(k tau) - s((k-1) tau)) / tau`; the histogram of the reference series by the cell rule of SN4 in BigFloat (`sn_hist_ref`) and D by the exact integer formula (`sn_D_ref`); the edge certificate of SN14 (`sn_envelope`: `N-`, `N+`, `U`) with `B_j(n) = 8 eps Psi_max^(j)(n)`, `Psi` of L1 Amendment D35 (`lb_Psi`, Float64, from the stored tangents of each orbit), `Psi_max` the maximum of `Psi_g` over the grid `g = 1..9` and ten per decade up to `n` (a test-side reading, as rli RL11: `Psi_n` for every `n` is quadratic in `n`), `eps_k = (B(k tau) + B((k-1) tau)) / tau + 4 eps max(|s_lo|, |s_hi|)`. The line is unresolved, and reported, where `max eps_k >= h/2`. The independent reference code lives in `sn_helpers.jl`, never calls the module, and is itself tested against hand values in `sn_selftest.jl` (green before stage 03).

Edge condition (spec, Acceptance criteria): closed-form values must lie at least 1e-9 from every cell edge, verified from the BigFloat series before the comparison (`sn_edge_ok`); `sn_pick_B` raises B from the value of the spec to the smallest value for which it holds, and the testset reports how often (Item 2). At the two end edges of a padded default range the closed-form values of Y5 sit about 8 eps inside, so the test requires 2 eps there instead (Item 3).

Interval: the printed interval of 100 map steps is not a multiple of tau for tau in {3, 5, 16}, so the tests use `sn_interval(tau)`, the smallest multiple of tau not below 100 (Item 5).

Missing-module behaviour: every testset starts with a line `_ = (StretchingNumbers, ...)` naming the new symbols it uses, so without the new code the testset errors on its first statement (`UndefVarError`) and nothing else; no top-level code and no helper calls a new name at include time (the one probe method that extends a new generic function, `reducer_workspace`, is defined under `isdefined(Chaoslab, :reducer_workspace)`). `sn_selftest.jl` uses no new name and must pass now. Failure reports are kept short (`sn_nbad`, booleans) so that a failing stage 03 run does not dump orbits.

Seeds (base 20261012 + 37000 = 20298012, distinct from sali 31000, fli 33000, megno 35000, rli 36000, lyap-benettin 21000; `sn_seed(ac, sub) = base + 50 ac + sub`; `StableRNG` throughout): the panel starts and frames of K = 2 pi, 10, 5, 0: `sn_seed(0, 1..4)` = 20298013 to 20298016 (the frame of orbit id `j` is `initial_deviations(seed, j, ...)` of the same seed); self-test 20298052; AC2b 20298113; AC2c 20298115; AC7a 20298363; AC8c 20298415; AC8e 20298417; AC10 20298513; AC11a 20298563; AC11c 20298565; AC12b 20298614 (frames and ids; the starts use 20298615); AC12d 20298616; AC12f 20298618; AC13b 20298664 (starts) and 20298665 (frames); AC13c 20298666; API 20298763. The K = 0.5 screening seed is the one of lyap-benettin (20282082). AC1, AC3, AC4, AC5, AC6, AC8a, AC9 draw nothing beyond the shared panel; the starts of AC3 and AC1 are supplied. Draws that appear without a seed: none.

Runtime (D38 class): sizes follow the spec except where marked (Item 7). `SN_FULL_RUN = true`, set before including `runtests.jl` by `verify/stretching-numbers.jl` (stage 04), selects the spec sizes (20 starts to n = 1e4 in the reference criteria, k up to 1e5 in the shear, 4000 repeats at Z = 20000).

## Items for the owner

Each item is a proposal for the stage 02 checkpoint; items marked (changes the spec) alter a criterion or a section as worded, the others record a reading or a requirement for stage 03.

1. (changes the spec) P4 and Algorithm item 1: the default interval of 100 map steps is not a multiple of tau for tau in {3, 5, 16} (criteria 3, 9, 7(a)). The tests use the smallest multiple of tau not below 100 (`sn_interval`). Proposal: say so in P4, or key the interval in handoffs. Related: `reducer_init` receives neither tau nor N, so the checks "interval is a multiple of tau" and "at most 10^9 handoffs" cannot sit in the reducer; the plan adds the caller-side `check_run(r, tau, N)` (as `check_frame`).
2. (changes the spec) Criterion 1 and the edge condition: the spec's own parameters put closed-form values on cell edges (p_0 = 0, B = 1000: z = 0.03 is the edge 515 of [-1, 1]; p_0 = 1/50, B = 1000 and tau = 1: every z lies on an edge, being a multiple of 0.002). The tests raise B to the smallest value for which the 1e-9 condition holds: B0 = 1000 becomes 1001 for every p_0 and tau (9 of 18 combinations per type), B0 = 101 is never raised. Proposal: word it so ("B is the smallest B >= B0 for which...") or shift the range.
3. (changes the spec) SN12 and criterion 7(a): for Y5 the stretching numbers approach ln mu to 1e-30, so the default range of exactly [-ln mu, ln mu] puts about half of them in an overflow cell by rounding, contradicting "both overflow counts 0, tolerance 0". The plan requires `stretching_range` to pad the bound outward by 8 eps relative (accepted: 4 to 16 eps); the edge test then asks for 2 eps at the two end edges. A padding of 8 eps changes h by the same relative amount.
4. State size (Compute): the spec's 80 and 144 bytes of reducer scalars (eight sums, count, code) leave no room for the failure record (value, step, column) that the health error needs, as in MEGNO. The stub's state is 104 bytes in Float64 and 176 in Double64; the tests accept 80 to 112 and 144 to 192 and report the size. Proposal: restate the figures with the record, or drop one of count and step.
5. (changes the spec) Criterion 1(iii): "within 2 eps relative" cannot hold: z = 0.03 is formed as the log of a number near 1, an absolute error of about eps/2 is 17 eps relative; and for the decimals p_0 = 1/50, -1/20 the orbit itself rounds (x_j accumulates), so the closed form differs from the realized sum by up to 4500 eps at n = 5000. The tests gate the mean against the realized orbit within the L1 S3 bound plus 2 eps abs(mean), and against the closed form itself on dyadic starts. Proposal: that wording.
6. (changes the spec) Criterion 2(ii): "every z within 2 eps of 0" is attained, not undercut: the rotation block by 0.3 in Float64 gives a worst z of exactly 2 eps (alpha = 1 + 2 ulp from `safe_norm`), so the criterion sits at its limit (12 of 20 columns). The test keeps 2 eps with a 1e-9 relative allowance for the decode. Proposal: 4 eps.
7. The series D_k cannot be delivered by the reducer (Algorithm item 5, P2): the stream has no emission channel (L1 Q9). D is a function of the counts, so `reducer_final(r, st, ws)` gives D_k at any handoff and the series is read with a probe or by the recorder at the evaluation handoffs; `interval` is then a recorded and validated parameter. Proposal: word item 5 so.
8. (changes the spec) Criterion 13(a) names no reference: "both lie inside the reference envelope" for two different orbits. The test uses each precision's own BigFloat reference at its own realized points and then bounds the cross-precision difference by the larger envelope width, which holds here only because the orbit divergence (1e-12) is far below the edge distances; the orbit divergence term of the precision spec (Equations item 4) is not in SN14. Proposal: say so, or add the term.
9. Memory of the host summary: `propagate` returns `finals` for every orbit, and a final now holds a count matrix of 8 (B + 2) bytes (8 kB at B = 1000); P9 (retention) is silent on `propagate` itself. At 10^6 orbits the host holds 8 GB of finals. Proposal: the Experiments recorder consumes chunk by chunk, or a keyword drops the counts of orbits outside a named subsample (not tested here).
10. (stage 03 hint, found by the dry run) `floor(Int, x)` of a `Double64` allocates 304 bytes on this Julia and DoubleFloats (two per handoff in the first draft of the stub: 608 bytes per handoff, caught by "AC12c"); `floor(Int, x.hi)` with the low part considered does not. The cell index in the hot loop must avoid it.
11. Criterion 4(c) asks for the column-1 sums only; the tests assert exactly that. Criterion 5 "every handoff that is a multiple of 10" is read as k a multiple of 10 (steps 10 k tau). Criterion 7(c) "one unit in the last place" is a `nextfloat` in Float64 and a 2^-104 offset in Double64. Criterion 9 includes the cell-index term of SN14 in the half-widths (harmless slack). Criterion 12(b) 1 vs N threads in child processes is stage 04, as in rli.
12. D38 reductions (package suite; `SN_FULL_RUN` selects the spec sizes): AC3 k up to 10^4 (10^5 with SN_FULL: 10^5 BigFloat closed-form samples per case cost minutes); AC5 10 starts in Float64 and 4 in Double64 with N = 1000; AC6 and AC8d the `sn_panel()` sizes (6 starts to 1e3, 2 to 1e4); AC9 Double64 on 6 starts; AC10 1000 repeats at Z = 20000; AC13a 4 starts. Psi in SN14 is taken as the maximum over a grid (1..9, ten per decade), the rli RL11 reading, because Psi_n for every n costs O(n^2).
13. Stage 04 criteria 14 to 16 are not written here. For 16, the plan's Surface 1 must work in the device kernel: not determinable here (Surface 1, last bullet).
