### Surface 1: the series path and the index (pure functions)

| Name | Signature and meaning |
|------|----------------------|
| `weighted_birkhoff(series, window; order = 1, weights = nothing) -> (avg1, avg2, S, B)` | WB14 for a stored series of any float type (Float64, Double64, BigFloat at the ambient precision). `series` is a vector (one observable) or an `n x K` matrix (a column per observable); `window` is `N` or a tuple of `N` (horizons, all starting at sample 0: the pair `[0, N_h)`, `[N_h, 2 N_h)` of the first `2 N_h` samples; samples beyond `2 max(window)` are ignored). `avg1`, `avg2`, `S` are `K x H` matrices of the element type (`H = 1` for an integer), `B` a vector of `H` weight totals. `avg = A/B`, `A = sum w_jj f` and `B = sum w_jj` Neumaier sums over the unnormalised weights, window 2 restarting the weight index at 0, one `B` for both windows; `S` the largest `abs(f)` of the `2 N_h` samples of that horizon (the samples of weight zero count). `weights` is an optional vector of `N` unnormalised weights used as given (single window only; the recorded lines R2 and R7: equal, `t (1 - t)`, `sin^2`, the width form). The reducer and the function share one update, so the reducer is bitwise the function on the series sampled at the handoffs (I6, criterion 6). `ArgumentError` naming `window` (an `N` below 16), `birkhoff_order` (`order < 1`), `series` (fewer than `2 max(window)` samples), `weights` (a length other than `N`, or with a tuple window). |
| `birkhoff_index(avg1, avg2, S; floor_multiplier = 32) -> (delta, absdig, reldig, dig, below_floor, zero)` | WB15 for one average pair of the type of its arguments, broadcastable over the `K x H` matrices. `delta = avg1 - avg2` (never clipped); `phi = floor_multiplier effective_eps(T) S`; `absdig = -log10 max(abs(delta), phi)`; `m = (abs(avg1) + abs(avg2))/2`; `reldig = -log10(max(abs(delta), phi)/m)` where `m > phi`, else `NaN`; `dig = max(absdig, reldig)` where `reldig` is defined, else `absdig`; `below_floor = abs(delta) <= phi`; `S = 0`: the three digits `NaN` and `zero = true`. `ArgumentError` naming `floor_multiplier` (not positive). |

### Surface 2: the observable kinds (n4)

An observable is any isbits callable of the orbit point `x` (the wrapped state `(q, p, m, n)` of `WrappedStandardMap`, a lifted point, a plane of a block map); its value is converted to the element type of the orbit (`T(o(x))`). The module ships the kinds of spec P6:

| Name | Meaning |
|------|---------|
| `CosObservable(i, k = 1)`, `SinObservable(i, k = 1)` | `cos(k x[i])`, `sin(k x[i])` with integer frequency `k`: exact on the wrapped coordinate whose circle is the rounded `2 pi` (standard-map W-E6). |
| `LiftedObservable(iq, im)` | `x[iq] + 2 pi_T x[im]`, the coordinate rebuilt from the winding count with `2 pi` in the element type, bitwise the corresponding entry of `lift` (D28); for the standard map `LiftedObservable(2, 4)` is the lifted `p`. |
| `observable_name(o)` | the identifier recorded in the provenance (a `String`: kind, index and frequency for the three kinds, `"function"` for any other callable). |

The caller guarantees smoothness (F5); the module cannot check it, records the names (R3), and accepts a discontinuous observable. Device demands (P6): isbits, allocation-free, type-stable, no string-building throw; a dry-run kernel built from a closure over tuples did not compile, so `K` is carried in the type by the tuple.

## Conventions

Element types Float64 and Double64 (D24); BigFloat(256) for the references and, for the pure function only, as an element type (criterion 12(a)). Tolerances in units of `effective_eps(T)` (Double64: `2^-100`), copied from the spec; `c_p = 4^p` (WB18); `S` is the reference `S` of the 2N samples; "reference" is the independent BigFloat(256) evaluation at the same realized samples (observables evaluated in BigFloat from the exactly widened wrapped states; the lifted `p` with `2 pi` as realized in `T`). State mode: wrapped (`WrappedStandardMap`, state `(x, p, m, n)`), the observables `cos q`, `sin q`, `cos p`, `sin p` of the wrapped coordinates and the lifted `p`; signals (constants, exact rotation) are generated in BigFloat(256) by exact recurrences and rounded once to `T`. Reference code in `wb_helpers.jl`, tested in `wb_selftest.jl` before stage 03: the weights from the definition in 256 bits (`wb_wref`), the window sums (`wb_ref_avgs`: `(avg1, avg2, B, S)`), the index (`wb_ref_index`), the rotation signals (`wb_rot_big`), the Poisson form by trapezoid quadrature of `W(s)` in 128 bits (`wb_Wint`, `wb_poisson_avg`), the independent BigFloat standard-map orbit (`wb_orbit_big`). The regular class is `lb_regular()` of the lyap-benettin folder (L1 S7: K = 0.5, screening by `X(1e5) <= 5e-4`, seed 20282082), included once behind a guard; K = 2 pi, 5, 10, 0.9, 0 draw uniform starts from `StableRNG(wb_seed(0, sub))`. Chains of readers end with a test-side column normaliser `wb_Norm` (K_std = 2 pi grows by about 2 per step and K_std = 10 by about 5, so a column overflows within 1000 steps in Float64), and `wb_Trace` records the orbit point at each handoff.

Missing-module behaviour: every new testset starts with a line `_ = (name, ...)`, so without the new code it errors on its first statement (`UndefVarError`) and nothing else; no top-level code and no helper calls a new name at include time (the observable sets `wb_std5()`, `wb_std4()` and `wb_idx` are functions that name the new kinds only when called). `wb_selftest.jl` uses no new name and must pass now.

Seeds (base 20261012 + 39000 = 20300012, distinct from sali 31000, fli 33000, megno 35000, rli 36000, stretching 37000, naff-fma 38000; `wb_seed(ac, sub) = base + 50 ac + sub`; `StableRNG` throughout): panel and class starts `wb_seed(0, sub)`: K_std = 2 pi `sub` 1 = 20300013, 0.9 `sub` 2 = 20300014, 10 `sub` 3 = 20300015, 0 `sub` 4 = 20300016, 5 `sub` 6 = 20300018; self-test frames 20300013, 20300014. ## Items for the owner

Each item is a proposal for the stage 02 checkpoint; items marked (changes the spec) alter a criterion or a section as worded, the others record a reading or a requirement for stage 03.

1. (changes the spec) Run length of the chains with E2. Criterion 10 chains {this reader, E2, MEGNO} and {E2, this reader, MEGNO} have the 2N + 1 handoffs of E2 (naff-fma D81 item 1), while the host check of the spec demands exactly 2 max(window) handoffs. The tests run those chains without `check_run` and require the completed horizons to be unaffected (the (2N + 1)-handoff result is bitwise the 2N result in every field but the counters, I4); `check_run` itself stays exact for a stand-alone run. Recommendation: say in criterion 10 that a chain takes the longest run its members need and that the reader's frozen horizons make the extra handoff harmless.
2. (changes the spec) The observable interface. The spec says "a caller-supplied pure function of the orbit point returning K values". The proposal is a tuple of K scalar isbits callables (kinds and any callable), so that K is carried in the type, the host check can name the failing observable, and the device compiles (the closure-over-tuples kernel of the spec's dry run did not). "Not of K values" becomes "not a finite real number" (`observable`). Recommendation: the tuple form; a single function returning an `SVector{K}` can be wrapped by the caller if wanted.
3. (changes the spec) I5 "digits never above -log10 phi" holds for `absdig` only. `reldig` and `dig` reach `-log10(32 eps)` = 14.15 when `m` is close to `S`, which is above `-log10 phi` whenever `S > 1`: for `S = 1000`, `avg_1 = avg_2 = 1000` the module of the stub returns `-log10 phi = 11.15`, `absdig = 11.15`, `reldig = dig = 14.15`. The tests gate `absdig <= -log10 phi` and `reldig <= -log10(phi/m)`. Recommendation: restate I5 that way.
4. (restated) "within 2 eps relative" for the digits (criterion 5(a)): a logarithm of an argument within 1e-2 of 1 cannot be matched to a relative 2 eps in the element type (the argument carries an absolute eps). The literal form holds for 300 of 300 entries of a dry-run sample (54 of them below 1 in absolute value), but it is unattainable by construction for `abs(Delta)` within a few percent of 1. The tests gate `2 eps max(abs(value), 1)`. Recommendation: the same wording in the spec; criterion 1(a) (value 14.15) is unaffected.
5. (reading) `below_floor` when `S = 0`: WB15 literally gives `phi = 0` and `abs(Delta) = 0 <= phi`, so the flag is set together with `zero`; the spec's I5 says "exactly when". The tests assert `zero`, `Delta = 0` and `NaN` digits but not `below_floor` for `S = 0`. Recommendation: state it either way in criterion 5(c); the literal reading (both set) is what the stub does.
6. (numbers) The spec's p = 2 dry-run values for criterion 4 (7.2 eps S for the averages, 8.2 for Delta) are not reproduced: the stub gives 1.45 and 2.87 (2.06 and 2.87 at 20 starts). The gates (16 and 32 eps S) are the spec's and hold with a margin; no tightening is proposed. Criterion 12(b): realized 7.4e-14 at 20 starts against the spec's 3.4e-14 and the gate 1e-12.
7. (restated) Criterion 2 premise: the exact (BigFloat) average that the criterion calls "limit 0" is not negligible for Double64 at N = 1000 with `w^[1]`: window 2 of theta_0 = 1/7 has 2.1e-32 = 0.027 eps_T (the spec's 4.9e-35 is the window-1 value), still far below the bound 4 eps_T = 3.2e-30. The tests require the exact average to be below a tenth of the bound (the spec's reading "limit 0" needs that margin) and then gate the bound as worded.
8. R4 (sticky orbits) has no panel and no definition of the regular range in the spec (the method must be fixed at stage 02, D77); it is not written. Recommendation: define the sticky panel in the study spec (the module supplies `delta` per `N`, which R1 and R2 already report).
