## Checked and found correct

Block and plan
- Grammar (`run_indicator.jl`): required keys per kind with no default, unknown key refused (so no threshold key can enter), `members` rules (SALI last only, no repeat, empty refused by `_rb_list`), strictly increasing windows (`issorted(w; lt = <=)` is correct), minimum windows 8 x (order + 1) and 16, the 31-observable cap, coordinate 1 or 2 and frequency >= 1, mode rules of E26, BigFloat refusal naming `arm[i].precisions`, unique lowercase ids not equal to a catalog id, window horizon equal to tau x run length with a single tau, budget per precision of the using arms, spec used by no arm, `control_methods` refusal.
- Item hash (E27): `kind` and `spec` printed last, after `hash_version`; `eps` and `direction` printed only when present, so every old item text is unchanged (I18 by reading `item_text`, `_chunk_key`, the `_arm_products` loop order, `_plan_text`, `_steps`); chunk key form of R12 item 3 with the first 16 hex digits; spec text via `_canon!` with `budget` dropped, keys sorted, lists of tables indexed from 1 (correction 3).
- A spec without direction is enumerated only for the first direction of the arm, so a sweep does not multiply window kinds.
- Run lengths E22 (2 W, 2 W + 1) and `check_run` arguments at plan time (stretching interval and 10^9 handoffs, E2 handoff count and observable indices with `d = 2` against the 4-vector of wrapped mode, Birkhoff with `x0` as a 4-vector in wrapped mode so the lifted observable `x[c + 2]` is in range).

Recorder (CPU)
- Chain construction: every member but the last non-replacing, the last replacing; SALI only last; window kinds are `(monitor, reader)`; series kinds are `(members..., monitor)`; the pair monitor reads orbit A on the base map.
- Column order and counts of E24 (SALI 2, FLI 2, MEGNO 6 in the order Y1, Ybar1, Ybar20_1, Y2, ...; RLI 2; D 1) equal `IND_MEMBER_COLUMNS`; the device row writer uses the same `_put!` methods.
- Sample convention E21: buffer index j (1-based) holds `f(x_{j tau})`, filled after each handoff of the one-handoff loop, `2 W_max` samples, windows read as `view(buf, 1:2W)`; the E2 and Birkhoff readers see the same handoffs (first handoff = sample 0); the last handoff is the 2 W_max-th (frequency, Birkhoff) or the (2 W_max + 1)-th (E2) with `complete` read at the end.
- Window kinds reset the deviation column to (1, 0) at every handoff, so no unnormalised column can overflow in a run of 8000 handoffs; series kinds are normalised by the last (replacing) member at every handoff.
- Pair start: block frame `(xi_0, 0)`, `(0, xi_0)`, xi_0 from the seeded rule (run seed and pair id) or from the arm direction, `check_frame(RLI())` per pair, the `pair_start` separation refusal becomes a recorded health failure naming the pair id with `Dx_r = NaN`; wrapped mode reads the counts of orbit A from components 3 and 4 of the first half.
- Flag words: bit order of the arrays equals the bit-name lists; `_flag_word` is correct for 11 bits; the tables of phase advance and Birkhoff map the reducer fields to the right columns (window-major rows); E31: `zero` allows NaN in absdig, reldig and dig only, `reldig_undefined` in reldig only (matches `birkhoff_index`), `degenerate` and `undefined window` allow any NaN of the row, infinities never. Note: for phase advance and Birkhoff the "undefined" flags are derived from the NaN itself (`isnan(delta)`, `isnan(reldig) && !zero`), because the reducers publish no separate flag; this is correct for a complete run but makes the "same NaN without its flag fails" rule of D86r vacuous for those two bits.
- Failure handling: rows from the failing grid row on are set to NaN (state, series, det, symp); `t` and winding of failed rows stay 0 as in the old recorder; `complete` false and the frequency `failed` bit become chunk failures through `ind_defects`; a non-finite sample of the E1 buffer is named with plane, window, sample and orbit.
- No stale state: the series buffer, the E1 buffer and the workspace are fresh per orbit; `ctx.bytes`, `ctx.frames`, `ctx.grids` are read-only in the parallel region (a cache miss recomputes without writing). Frame checks run once per (precision, direction, k, spec) in the sequential `prime_frames!`.
- Determinism (I24) on the CPU: per-orbit independent computation, a single-thread FFT in the transform, exact integer pooled sums in orbit order; nothing depends on capacity, thread count or group composition.
- Memory E28: `orbit_bytes` terms (M with s = 4 or 8 and k, R from `reducer_bytes` including 4 bytes per workspace entry, S = 8 c ng with c = 1 + 2 + 2 (wrapped) + 2 + E24 columns, B = 2 W_max sizeof(Complex{T}) = 32 or 64 W_max); `group_capacity` is exact rational arithmetic; `_launch_capacity` refuses a spec for which one orbit does not fit, naming the terms.

Device path (by reading; not run)
- Both kernels write only row `i` of the record array and `fail[i]`, `code[i]`, `hstep[i]` of their own orbit, so no race; the row index `g` and the failing-row convention (`g` for a failure inside the grid loop, `ghi + 1` after it) agree with `_ind_unpack!` (`fail - 1` rows kept, `mmax` of the last good row).
- `L` is a multiple of tau (`_budget_steps`, `_forced_launch`), so `steps / tau` in the window kernel loses no handoff; grid rows fall on handoffs, so `n == grid[g]` always meets.
- Record array rows `nser + 3 + ns` never exceed the `c` used by the capacity formula; the batch groups orbits by map type (`_by_system`), so the reader tuple built from the first item is valid for all.
- The row writers do not build strings or allocate; argument checks live in the block, the plan and the host. The `_NO_WS` default of `_orbit_body` is the pattern already used by the old kernel.

Store, manifest, pilot
- Provenance per member as a group, popped from the root attributes before the attribute comparison, read back and compared; `lyap` optional on read; version stays 2; `direction` deleted when the item has none.
- Atomic write unchanged (tmp file, read-back, `complete` last, rename); the new `pooled` group is written before `after_data`.
- Backend: `spec_sha256` of the record against the spec hash gives the CPU with the note; stretching and frequency are CPU-only with the sixth reason; Double64 and BigFloat resolve as before.
- Pilot: window kinds run at tau x run length; CPU rerun gated only for non-GPU chunks.

Rules
- No em dash or other non-ASCII character in the added code except the division sign in comments and loops (checked on the diff); no study value, default, threshold or detection time in the module (the constants that exist are engineering fixtures in `hot_loop_bytes` and dummy ranges for the frame check and the run check).
