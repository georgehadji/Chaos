The generic tableau of the package performs, for each stage, `position += dt b_i velocity` (drift b_i) then `velocity += dt a_i acceleration(position)` (kick a_i), drift first (`symplectic_perform_step.jl`, generic `SymplecticTableau`). Our table (c, d) is (drift c_i, kick d_i) with the first stage first, so a package tableau is the table (c, d) = (b, a). For the leapfrog family, S1, S2, S11 to S13, the tableau read this way is our table as it stands; for Ruth3 (a = 2/3, -2/3, 1; b = 7/24, 3/4, -1/24), CandyRoz4 and CalvoSanz4 the package solver equals ours only when the roles of drift and kick are exchanged in our table (our S4 and S9 start with a kick, with the Ruth1983 and CalvoSanzSerna1993a reading of stage 01; the package starts with a drift). Both versions are methods of the stated order (package Ruth3 3.02, 3.01, 3.005; CandyRoz4 4.0000; CalvoSanz4 in package form 2.93 to 2.98 on F4 at the first steps, ours 4.0000; the swapped table reproduces the package maps to 1.8e-15). So the O6 comparison fixes the coefficient values but not the stage order for S4, S5 and S9; the order of the stages is the stage 01 reading of the papers (page images), checked by the measured order 3 (S4) and 4 (S5, S9) and by the exact equality of AC3b5 (RKN form against splitting form).
